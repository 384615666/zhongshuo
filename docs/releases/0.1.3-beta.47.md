# 众说 0.1.3-beta.47

本版是 **beta.46 的独立代码审计修复版**：由 Codex 子代理（模型 `gpt-6.1-sol`，推理强度 `xhigh`）在独立 worktree/分支 `r202-audit` 上审计并修复，主控复核后合并、打包。功能与数据格式不变，schema 仍为 61，升级保留项目、聊天、附件、任务与草稿。

## 审计发现与修复（4 项，均附行为测试）

1. **P1 · Markdown 标签可伪装本机文件真实扩展名**（`src/ui/hifi/preview/MarkdownView.tsx`）：`[报告.pdf](file:///C:/exports/run.cmd)` 之前显示标签「报告.pdf」，点击却把 `run.cmd` 交给系统默认程序。现在本地文件条目**始终显示真实路径的文件名**（`run.cmd`），标签不能掩盖实际类型；打开仍须用户显式操作。
2. **P1 · 图片副本目录 junction 可越界写入**（`src/daemon/commands.ts`）：`attachment.absolutePath` 之前只校验字符串前缀；若 `attachment-paths` 是指向外部目录的 junction，写入会落在应用数据目录之外。现在写入前核对目录 realpath，拒绝符号链接/junction；复用前检查 lstat/realpath；改用原子替换，不原地写入已有硬链目标，失败不删除旧副本。
3. **P2 · `file:` URL 解析错误**（`src/ui/hifi/lib/localFileHref.ts`）：修正 `file://localhost/...`、查询串、fragment、编码文件名等有效链接；拒绝 `file://`、`file://server`、无盘符相对路径、非法百分号编码、编码路径分隔符等无效输入，不再凭空生成 UNC 路径。
4. **P2 · 同大小图片篡改未检测 + 前端永久缓存**（`src/daemon/commands.ts`、`src/ui/hifi/lib/imageAttachmentPaths.ts`）：之前副本只比较字节数，同长度改写后继续返回损坏路径；前端成功结果永久缓存，删除/篡改不能恢复。现在只有副本字节与已验证原件一致才复用，否则原子重建；前端只合并在途请求，请求完成即释放缓存，下次操作重新核验。

审计报告（含原始发现、环境限制与主控复核附录）：`docs/reviews/r202-audit-findings-20261108.md`。

# 众说 0.1.3-beta.42

本版修复五项图片与通知相关反馈：只发图片时气泡上方的大片空白、引用/复制图片时只带文件名（现在带图片绝对路径）、消息图片与预览图片不能右键复制、Windows 通知图标显示成黑色方块。功能合同、数据格式与 schema（61）不变，升级保留项目、聊天、附件、任务与草稿。

## 主要改动

- **图片气泡贴合**：本人只发图片、没有文字时，气泡边距由 10/14px 收紧到 4px，图片网格与附件区多余上间距归零——照片贴着气泡显示，不再浮在浅蓝大框里。带文字的消息、AI 消息与纯文件消息布局不变。
- **引用带图片绝对路径**：引用一条含图片的消息时，引用内容除文字外会自动附上 `[图片] 文件名` 与图片在本机的完整路径；选中部分文字再引用也照样附图片路径。对话串、私信、房间主池三处的引用都生效。
- **复制带图片绝对路径**：复制含图片的消息（消息操作条「复制」、房间主池卡片「复制」）时，正文之后会带 `[图片] 文件名` 与完整路径，不再只有图片名称。
- **图片右键复制**：
  - 对话里的图片右键 → **复制图片** / **复制图片路径**；
  - 共享预览的大图右键 → **复制图片** / **另存原件**；
  - 复制图片写入系统剪贴板，可直接粘贴到聊天工具或图片编辑器；主进程对图片数据做来源、格式、大小与解码校验，不暴露任意文件写入口。
- **图片路径怎么来**：项目里已有的图片用项目内真实相对路径拼出绝对路径；上传的图片由新增的只读命令在应用数据目录 `attachment-paths/` 下生成带真实扩展名（png/jpg/gif/webp/bmp）的稳定副本并返回其绝对路径——是真实复制而不是硬链，用户或 AI 按这个路径改写图片也不会影响内容寻址的托管原件；路径在应用数据目录内，远程设备拿不到本机路径。
- **Windows 通知图标黑块**：根因是随包 `.ico` 的 7 帧全部写成 PNG 压缩帧——Windows 通知身份图标（AUMID 的 `IconUri`）与经典图标 API 按传统 DIB 读取，PNG 帧被当成位图数据解析，于是显示成黑块/噪点；Electron 自己能解 PNG，所以通知正文里的品牌小图一直正常。现将 ICO 全部改为传统 BMP/DIB 帧（BITMAPINFOHEADER + 32bpp BGRA + AND 掩码），经典 API 取 32×32 与 logo 逐像素一致，PE 图标仍有 7 帧且校验通过。通知身份注册仍指向随包图标，重装后的新构建即可生效。
- **手册同步**：用户手册「发附件」一节补充图片复制的右键入口、复制/引用带完整路径与图片-only 气泡说明。

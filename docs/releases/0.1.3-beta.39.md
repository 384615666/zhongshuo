# 众说 0.1.3-beta.39

本版移除图片输入的所有能力认证限制：所有 AI 成员都能直接收到图片，发送前不再需要换成员或选择「仅发送文字」。功能、数据与格式不变（schema 61），升级保留项目、聊天、附件、任务与草稿。

## 主要改动

- **输入区提示与弹层移除**：不再出现「部分 AI 暂不能接收图片，可换成员或移除图片。」提示条，也不再弹出「当前所选 AI 尚不能确认接收图片……仅发送文字，图片不送模型 / 移除图片继续 / 换可用成员 / 取消」的二选一弹层。图片和普通附件一样，选好即可发送。
- **所有 AI 成员都能看图**：图片随消息直接发送，Claude、Codex、Pi、DeepSeek Harness 四个运行时都真实携带图片字节。
  - Claude、Codex 原本已传图，本版删掉启动身份校验与 Codex `inputModalities` 的拒图拦截；
  - Pi 在 `prompt` 帧携带 `images:[{type:'image',data,mimeType}]`；
  - DeepSeek Harness 在 `full` 模式 `execute` 帧携带 `images:[{data,mediaType}]`；规划（`planning`）与格式补交（`format-repair`）协议仍只接受文字，保持纯文本。
- **仅记录保持原样**：选「仅记录」仍只保存消息与原件、不派发，图片不会送模型，注入说明如实标注「图片附件未发送」。
- **界面显示统一**：成员详情「图片输入」恒显示「自动传递图片」；本地诊断的图片能力恒显示「可用（直接发送）」；`attachment.previewImage` 的 `modelInput` 由 `depends-on-target-member` 改为 `sent-with-message`。
- **旧数据兼容**：历史信封里的 `imageAck` 仍被接受但完全忽略；`memberImageCapability()` 恒为 supported；原 R76 识图证书文件 `src/adapter/image-certification-r76.json` 删除（历史证据保留在 Git 历史）。
- **旧界面回退同步**：`?nohifi=1` 或新界面加载失败时的旧界面上，发送前的图片门与「仅发送文字，不发送图片」按钮一并删除，图片按普通附件直接发送。

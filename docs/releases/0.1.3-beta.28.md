# 众说 0.1.3-beta.28

## 读取与执行状态

修复历史任务和派发记录增多后，房间与任务状态刷新变慢、多个项目出现「请求超时（15000ms）」的问题。保留原有执行保护和任务归属检查，减少读取执行状态时的重复历史扫描。

DeepSeek Harness 启动等待与配置读取统一为30秒。等待就绪超时会明确提示启动未完成，避免直接误报连接组件协议不兼容。协调成员的子步骤失败时，任务状态会显示实际成员失败原因；尚未派发的汇总步骤不会显示为正在执行。

## 成员管理 / 任务看板 / 侧栏顺序

- 侧栏的「项目」和「房间」现在可以上下拖动调整显示顺序（只影响本机显示，不改项目与房间数据；置顶项目仍排在最前；刷新/重开后顺序保留）。
- 成员管理左侧项目卡片的左右留白改为对称（1360 宽实测 24/24、1873 宽 40/40）；右栏不再重复显示项目名大标题，成员数量移入左侧当前项目卡片（「N 个房间 · M 名成员」）。
- 「扫描本机 AI」不再是独立按钮：点「添加 AI」时会先扫描本机已有渠道，再打开添加界面；扫描结果仍会说明。
- 「刷新」「添加 AI」移到搜索与状态筛选同一行。
- AI 成员卡片去掉了自动生成的说明文字、★协调者标识与「编辑资料」按钮；成员名称和说明改为在「AI 设置」弹窗里修改（先存资料、再存配置，部分成功会如实提示）。
- 成员模板卡片只保留名称、渠道/模型和两个入口；点「在本项目创建…」会打开与其他入口一致的「添加 AI」界面，并按模板预填渠道、模型、执行程序、权限和头像。
- 任务看板左侧新增与成员管理相同的项目卡列，最上方是「全部项目」卡片（代替原来的范围筛选），每张项目卡显示任务数；点击卡片只切换看板范围，不改侧栏当前项目。

本轮使用隔离数据和模拟执行验证，没有自动重发原任务，也没有调用真实模型。数据库格式保持schema61。

仅交付Windows安装包。请先在系统托盘退出众说，再由用户自行安装更新；启动后查看原任务的最新失败提示，处理对应成员连接后再决定是否继续。

## 实际操作过的原型路径

| 路径 | 本轮看到的结果 |
| --- | --- |
| 房间 → 调整安排 | 可以交换两人的预计顺序；既有已接受安排与下一次发送的预计安排区分显示 |
| 待我处理 → 核对是否收到 → 查看这条消息 | 找到原消息，回到房间后突出原消息，不创建第二条任务 |
| 成果 → 提出修改 → 提交并开始修改 | 显示修改已开始，交付v2仍为当前版本；没有假装已生成新版 |
| 查看变更 → 前后对照 | 修改前、修改后可直接对照阅读 |
| 恢复这些文件 → 恢复所选文件 | 一项可恢复、一项冲突禁选，显示逐项结果；没有实际写文件 |
| 文件 → 引用选区全文 | 标示540字；输入框实际保留540字，核对过尾部内容 |
| 搜索 → 选择全部项目 → 第2页 → 打开 → 返回 | 范围和页码仍为全部项目、第2页 |
| 看板 → 本人私信 | 列表只显示本人私信示例任务 |
| AI设置 → 修改 → 取消或Esc | 出现保留编辑／放弃修改，保留输入内容 |
| AI设置键盘操作 | 初始焦点在名称输入；末尾Tab回到弹窗首个控件；Esc触发未保存保护 |
| 数据 → 管理草稿 → 清理 | 普通草稿变为0；1条发送待确认仍单独保留 |
| 归档 → 继续查找更早内容 | 从“已查200条，仍有更早记录”进入后续匹配结果 |
| 私信 → 新建 → 创建独立私信 | 列表出现新会话，正文显示尚无消息，没有沿用旧私信内容 |
| 自然输入方式 → 发送、调整顺序 | 可见本次收件与预计安排；发送后显示已接受安排 |
| 显式顺序方式 → 重复选择同一成员 | 显示成员重复提示；另选一位后可接受安排 |
| 输入方式对照切换 | 两套完整设计可以前后切换，保留各自操作状态 |
| 窄宽度检查 | 工作台各主要页面与两种输入方式在320px视口下，根节点scrollWidth不超过clientWidth |

两份片段的JavaScript语法检查通过，体积分别约54KB和11KB，均小于1MB；检查时浏览器没有捕获到error级日志。预览使用技能附带的沙箱包装，只提供这两份示意，没有服务仓库目录。

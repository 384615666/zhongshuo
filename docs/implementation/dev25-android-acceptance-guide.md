# DEV-25 Android 实机验收指南（第三十七轮准备——普通手机浏览器）

> **口径**：本指南为可执行的步骤准备。「证书格式已适配」＝两层证书（本地 CA+CA 签发服务
> 证书）在设计上兼容 Android 用户凭据信任路径；「该 Android 组合已实测」＝**尚无任何
> Android 实测记录**——以实际执行回填为准，未执行不记通过。私钥/CA 私钥只留服务机；
> **不使用任何证书错误绕过开关**（不点「继续前往」冒充信任）。
> 记录实际系统与浏览器版本（模板见文末）——不同厂商设置入口名称可能不同，按语义找。

## 0. 前置（Windows 服务机，v2 包运行中）

1. 远程面板：局域网（0.0.0.0）已启用、**LAN 自检通过**；从 **LAN 地址列表**选手机可达地址
   （如 `https://192.168.1.100:端口`）。
2. 把 `server-data\remote\ca.cer` 通过任意方式传到手机（微信/邮件/USB/网盘均可——CA 证书
   是**公开**文件，不含私钥）。
3. 服务机 PowerShell 核对并记下 CA 指纹：
   `Get-FileHash -Algorithm SHA256 "...server-data\remote\ca.cer"`。

## 1. 证书信任（Android 用户凭据）

1. 手机「设置 → 安全 → 更多安全设置 → 加密与凭据 → 安装证书 → **CA 证书**」
   （不同厂商路径名称略有差异：也可能是「从存储设备安装/安装数字证书」；MIUI 在
   「设置→密码与安全→系统安全→加密与凭据」；Pixel 在「设置→安全→更多安全设置→
   加密与凭据」）。
2. 选择传入的 `ca.cer`——系统可能显示「检查证书/无视风险」提示（因为它是自建 CA），
   确认安装到**用户凭据**。安装列表应出现 CA 主题（CN=Zhongshuo Remote Access CA）。
   如系统提供证书详情/指纹视图，与第 0 步 CA 指纹逐位核对。
3. 打开手机浏览器访问面板地址：应**无证书警告**（锁形/「连接是安全的」）。仍告警=信任未
   生效（部分浏览器需完全重启后生效；Samsung Internet 与 Chrome 均读系统用户凭据）。
   **不点「继续前往」**——先解决信任。

## 2. 配对与基本操作（触摸）

1. 服务机**现在**点「生成配对码」（5 分钟一次有效——信任已完成再生成）。
2. 手机浏览器打开配对页 → 输入 pairingId + 8 位码 + 设备名（如「我的手机」）→「配对并保存」
   → 进入主界面（IndexedDB 保存设备凭据）。
3. 触摸操作检查：会话下拉选择、线程行点击读取、发送/仅记录按钮、附件按钮（调起系统文件
   选择器）、任务区停止/验收按钮。
4. 「仅记录」一条消息 → 事件流出现 `message.submitted`（D2 对应）。

## 3. 上传（D3 对应）

- 点「附件」→ Android 文件选择器（照片/文件）→ 选小文件 → 芯片出现 → 发送 → 消息带 📎。
- 注意：**图片输入能力未认证**（IMAGE_INPUT_UNVERIFIED 门）——图片附件发送默认会被明确
  拒绝并提示；用文本类文件（.txt/.md）做上传+发送演练，或图片走「仅记录」。

## 4. 后台恢复（D7 对应）

1. 发起一个任务（DM 消息默认发送——首任务有 60 秒停滞窗便于操作）。
2. 把浏览器切后台/锁屏 30—60 秒 → 回前台：
   - 页面应自动重连（事件流出现 connected/续传线）；
   - 期间产生的消息/任务结果可见（检查点续传——无漏）。
3. 若页面被系统杀掉：重新打开地址 → 凭据复用免配对 → 历史与任务状态恢复。

## 5. 独立吊销（D8 对应——手机独立于 Windows 客户端）

1. 服务机远程面板「已配对设备」中对**手机设备**点「吊销」。
2. 手机应立即：事件流断开并出现**终态横幅**（设备已被吊销——不再自动重连）；任何操作
   返回 401。
3. 重新配对：服务机重新生成配对码 → 手机「清除本机凭据」→ 重新配对（可选复核）。
   吊销不影响其它已配对设备（设备级授权代次）。

## 7. 已知边界（如实）

- PWA/Push 属后续归属，本轮不测。
- 手机横竖屏/小屏布局未做专门适配——以功能可用为准，视觉问题记录不扣功能结论。
- 「证书格式已适配（两层 CA）」与「该 Android 组合已实测」是两回事——本指南执行完毕并
  回填后，后者才成立。

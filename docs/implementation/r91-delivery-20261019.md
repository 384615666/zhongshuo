## 2. 三个用户问题的根因与最终行为

### 2.1 输入框丢字、光标/选区跳动、IME 被打断（模块1 Composer）

**根因**（R91 代码注释与 pre/post-fix 证据）：

- 草稿恢复 effect 依赖了每 5s 轮询会换引用的成员名单、runtime 绑定、线程名单/进度等值；引用变化触发
  `renderEditorBody → replaceChildren` 重建编辑区：光标弹回开头、非折叠选区丢失、滚动复位、@ 候选被清、中文 IME 组合被 DOM 重建打断。
- 中文组合输入期间收到上传/引用回执时，旧实现可能用较早草稿覆盖 DOM 文本（丢组合串），或复活已移除 token。

**最终行为**：

- 恢复只由 `draftKey` 真正切换触发；轮询只更新 @ 候选/资格等派生数据（走 latest-ref），不再重载正文。
- IME 组合期间禁止重建子树：DOM 文本是用户最终输入、草稿 token 是最新附件身份，`compositionend` 后一次性合并
  （不丢字、不丢已结算/新增附件、不复活已移除附件）；选择按“token 占 1 位”的结构串映射恢复方向/区间/滚动，未聚焦不抢焦点。
- 会话通道迟到就绪只补缺失行内 token，不重放整份草稿。

**证据**：`tests/browser/r91ComposerCaret.test.ts`；`scripts/verify-r91-composer-caret.cjs`；
`dist/review-r91-composer-caret-20261019/{pre-fix-verification.json,post-fix-verification.json,README.md}`（pre-fix 复现、post-fix 通过）。

### 2.2 研讨可见性：只显示“等待”，看不到 AI 间交流（模块2 后端 + 模块3 前端）

**根因**：DELIBERATE 阶段产物只落 `artifacts` + 领域事件；`publishFinalReport` 之前没有串内消息。
`thread.history`/`conversation.history` 因而只能看到等待，用户看不到独立答复、互评、讨论、整合、确认。

**最终行为**：

- `onStepOutput` 在 schema/引用/run/turn/成员/阶段身份校验通过且 `counted=true` 后，把结构化产物投影为**持久化串内正式消息**：
  真实作者、中文阶段标签、`body_json.collaborationStage={stage,roundNo,turnId,runId}`；阶段只用既有五个值
  （INDEPENDENT/CROSS_REVIEW/ISSUE_DISCUSSION/SYNTHESIS/RATIFY，检查点归入 ISSUE_DISCUSSION）。
- 稳定身份 `msg_delib_<runId>_<stage>_<member>_<roundNo>`：同 turn 重放/合法修复产物只显示一次；非法输出、STOP、UNKNOWN、
  旧 run/迟到材料不转成功发言；原文 reasoning/内部 ID/原 JSON 不展示，结构化产物仍保留在 artifact 详情。
- 前端只把 `collaborationStage` 翻译为简短中文标签+轮次（通过 `thread.history items.body` 与 DM `body_json` 两条真实链路），
  不把内部 turn/run 身份渲染到界面。

**证据**：`tests/integration/r91DeliberationVisibility.test.ts`（21 项，真实 `onStepOutput` 入口的负例/修复/幂等/终态）；
`tests/integration/coordinationR86.test.ts` 旧计数契约按 `collaborationStage` 过滤后保留自然消息断言、另断言阶段消息数与作者；
`tests/browser/r91MessageCollaboration.test.ts`、`scripts/verify-r91-message-ui.cjs`、
`dist/review-r91-message-ui-20261019/result.json`（43 checks + screenshot）。

### 2.3 生成文件只有绝对路径、没有可点击文件卡（模块2 后端 + 模块3 前端）

**根因**：`TaskComplete.files` 只是文本字段；成功交付没有把真实生成文件登记为 `artifacts` +
`message_attachments`，气泡只有裸路径文字，无法预览/另存。

**最终行为**：

- 仅在正式合同（schema/resultKey）与任务身份验证通过后：按**正式结果 `.files` 显式路径**，未列时只取本 turn changeset
  的 `added` 清单（不扫描全盘、不从正文/正则抓路径）。
- 真实读取字节 + sha256，按本 turn 执行时记录的写权限判定：fullAccess 允许本轮明确列出的项目外真实文件；
  project-write 仅项目内且有本 turn 变更证据；readonly/不可核实不登记产出。
- 写入内容寻址 blobstore，落不可变 `artifacts`（hash/revision/作者/task/conversation 归属）与
  `message_attachments`，**只挂本轮绑定的最终回复消息**（含只有 `turn.completed`、无 `message.completed` 时生成的
  `structured_final` 回复）；同 turn 重放幂等、同路径新内容新版本、旧消息仍指旧版本、不同任务不串附件。
- 预览/原件/导出复用既有通道：文本 `previewText`、表格/CSV `previewOffice`（csv 由 source_name 选择既有 parser）、
  `originalFile` 返回真实字节；不支持的扩展名/超限/空文档/损坏文件如实降级为可读状态，不伪造成功附件。
- **不把旧历史正文里的路径自动变成文件卡**：新卡只对本轮以后可核实的正式产出生效；旧消息原样保留。

**证据**：`tests/integration/r91GeneratedSnapshots.test.ts`（11 项，真实 xlsx/csv/txt + fullAccess/受限/只读矩阵）；
`tests/integration/r91StructuredFinalRegression.test.ts`（3 项，短答案不被前缀吞掉、无 message.completed 合成回复、完整答案不重复）；
真实文件任务见 §3.4。

# 方案 C：增量复制 + 一致性校验后切换

## 思路
先把存量数据复制到新库，再用增量同步保持接近实时；选低峰期短暂停写做最终校验，通过后切换。

## 步骤
1. 存量复制（分批按主键范围导出导入，不锁表，预计 2 天）。
2. 增量同步（binlog 订阅，延迟稳定在 5 秒内）。
3. 低峰期（周三 04:00）冻结写入 5 分钟：等待增量追平。
4. 一致性校验：对每张核心表执行 `SELECT COUNT(*)`，新旧库行数全部相等即判定一致。
5. 切换连接串，恢复写入，同步任务保留 24 小时兜底后下线。

## 预计停机
仅冻结写入 5 分钟。

## 回滚
切换后 24 小时内如发现问题，把增量同步反向（新库→旧库）补齐后切回。

## 优点
- 停机最短，存量复制不锁表。
- 有明确的校验关卡，不是盲切。

## 缺点
- 组件最多（存量+增量+校验），链路复杂。
- binlog 订阅对数据库版本有要求。

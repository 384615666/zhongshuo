# 方案 B：新旧库双写过渡

## 思路
应用层同时写旧库与新库，读仍走旧库；追平历史数据后灰度切读，最后停旧库。

## 步骤
1. 上线双写开关（写请求同时落两库，失败以旧库为准记日志）。
2. 用 DTS 全量同步历史数据 + 增量 binlog 订阅追平。
3. 灰度 5% → 50% → 100% 切读到新库，观察一周。
4. 观察期结束，关闭双写，旧库保留 30 天后下线。

## 预计周期
全程约 3 周，无停机。

## 回滚
任何阶段出问题，把读流量切回旧库、关闭双写开关即可。

## 优点
- 全程无停机窗口，业务无感。
- 灰度可逐步验证，风险分散。

## 缺点
- 双写期间两库可能出现不一致（开关失败记日志后人工补），需要额外比对任务。
- 开发与运维成本最高，周期长。

## 1. 包与角色

- **服务机**（开发机）：便携包 `dist/desktop/众说-便携-win-x64`（含 daemon/UI；buildId 见 BUILD.json）。
  启动环境：`ZS_RUNTIME=fake`、`ZS_ALLOW_FAKE=1`、`ZS_REAL_DISPATCH_GUARD=1`（硬隔离——真实派发在 spawn 前拒绝，零真实模型调用）。
- **客户端机**：任意现代浏览器（Edge/Chrome）。**无需** Node、Git、模型账号、不复制真实工程。
- 数据隔离：服务机使用独立 `ZS_APP_DATA`（如 `D:\zs-remote-accept\appdata`）+ 合成项目。

## 2. 服务机步骤（约 5 分钟）

1. 以上述环境启动 `众说.exe`；打开合成项目（新建一个文件夹放一个 md 即可）。
2. 侧栏「远程访问（DEV-25）」面板：
   - 监听地址选 **局域网（0.0.0.0）** → 点「启用」→ 面板显示 `运行中 https://<本机LAN IP>:<端口>` 与证书指纹（记下两者）。
   - 点「生成配对码」→ 记下 `pair_…` 与 8 位码（5 分钟内一次有效；面板只显示一次）。
3. 防火墙放行该端口（Windows 首次监听会弹询问——允许专用网络）。

## 3. 客户端机步骤（约 10 分钟）

1. 浏览器打开 `https://<服务机LAN IP>:<端口>`。
2. **证书信任（R11 §2）**：自签证书会触发浏览器警告——点击「高级 → 继续前往」前，先展开证书详情核对 **SHA-256 指纹与服务机面板一致**；有条件时把 `appData/remote/identity.cer` 导入系统「受信任的根证书颁发机构」后重开（信任失败即停——程序不降级 HTTP、不关闭证书检查）。
3. 配对页输入 pairingId + 配对码 + 设备名 → 「配对并保存」→ 进入主界面（凭据存同源 IndexedDB；accessToken 仅内存）。
4. 按下表逐项执行并在 RESULT.md 记录（截图/事实各一）。

## 4. 双机检查项（RT-21/LAN 对应）

| # | 操作（客户端机） | 预期 | 对应 |
|---|---|---|---|
| D1 | 打开后同一数据可见（会话/任务/事件流） | 与服务机桌面一致 | LAN-07 |
| D2 | 发一条「仅记录」消息 | 双端消息列表都出现，事件流推 `message.submitted` | RT-21 |
| D3 | 上传一个小文本附件并发送 | 上传成功+消息带附件；服务机 Files 面板可见 | — |
| D4 | 客户端发起任务（发送默认意图）→ 服务机看板出现执行中卡片；客户端「停止」 | 停止目标准确（该任务转停止，不受其他任务影响） | — |
| D5 | 任务交付待验收时客户端「验收通过」 | 仅对绑定的 deliveryId+revision+manifestHash 生效 | RT-25 链 |
| D6 | 同一消息重发/刷新后重发同 commandId | 恰一次（不重复消息/任务/预算） | RT-21 |
| D7 | 关闭客户端浏览器窗口（任务运行中） | 服务机任务继续；重开重连后事件流从 lastSeq 续传 | LAN-07 |
| D8 | 服务机「远程访问」面板吊销该设备 | 客户端立即断流+下一次操作 401 明确拒绝；重配对需新码 | LAN-06 |
| D9 | 在客户端机访问 `https://<IP>:<端口>/pair` 伪造 Origin（开发者工具或 curl） | 403（白名单来自服务机配置，不自动扩） | LAN-04 |
| D10 | 连续 6 次错误配对码 | 第 6 次 429+Retry-After；同码 5 次失败后失效 | LAN-01 |

## 6. 边界（如实）

- 配对设备=本机同等权限（既定产品决定）；本机保留方法（配对码创建/服务配置/吊销/关停）在 HTTP 面被 `REMOTE_BLOCKED_METHODS` 拒绝。
- 客户端退出≠服务端任务停止（任务在 daemon）；导出经获准下载（`/export/:id/download`），服务端不执行 shell。
- 自签证书更换（如改监听地址重新生成）后指纹变化——须重新核对信任。
- 手机浏览器组合（R11 §2「桌面/移动浏览器组合必须实测」）未在本轮范围——桌面浏览器已实测，移动端待后续轮（不冒充已验证）。

# 本地待办清单 需求文档

- 版本：v0.3（终稿：已按独立评审意见修订并经复核整合）
- 场景：单人使用，数据仅存本机
- 交付形态：本期仅命令行（CLI）工具，单机运行；交互与验收均以命令行为准
- 交付物：本文件（requirements.md）

## 1. 目标

为单个用户提供轻量、离线、数据完全保存在本机的待办清单工具，实现“快速记录—查看—完成—清理”的闭环。

- 单人使用：无账号、无登录、无多用户协作。
- 数据仅存本机：不联网、不上传、不同步；断网时全部功能可用。
- 轻量可靠：操作直接、启动快；异常时不崩溃、不静默丢失数据。
- 文本口径（全文统一）：待办“文本”指去掉首尾空白后的内容；长度按 Unicode 码点（code point）计数（组合字符、emoji 按所含码点数计），有效范围 1–500；空格、制表符、换行均属空白字符。

## 2. 主要功能

| 编号 | 功能 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| F1 | 新增待办 | 输入文本创建一条待办，默认“未完成” | 提交 1–500 字符的非空白文本后，列表立即出现该条目；空/纯空白或超过 500 字符被拒绝并提示 |
| F2 | 查看列表 | 展示全部待办及完成状态 | 列表完整显示所有条目，完成与未完成状态可区分 |
| F3 | 标记完成/取消完成 | 切换单条待办的完成状态 | 切换后状态立即变化，且重启后保持一致 |
| F4 | 编辑内容 | 修改已有待办的文本 | 修改后立即生效，重启后显示新内容；新文本同样满足 1–500 字符且非纯空白 |
| F5 | 删除待办 | 删除单条待办 | 删除后列表不再显示，重启后不恢复 |
| F6 | 本地持久化 | 数据保存到本机文件（默认 todos.json） | 关闭并重启后，清单与关闭前一致 |
| F7 | 状态筛选 | 按“全部 / 未完成 / 已完成”筛选列表 | 各筛选视图只显示对应状态的条目 |

## 3. 不做范围（明确暂不实现）

以下能力本期明确不做：

1. 多用户与账号体系（注册、登录、权限）。
2. 云同步、跨设备同步及任何形式的网络传输。
3. 协作与分享（指派、评论、共享清单）。
4. 提醒与通知（截止提醒、系统弹窗、声音）。
5. 截止日期、优先级、标签、分类等高级组织方式。
6. 全文搜索与批量操作。
7. 数据导入/导出及与其他应用的集成。
8. 桌面 GUI 与移动端 App；本期交付形态仅为命令行（CLI）。
9. 多副本备份与加密存储（数据仅本机单文件存放）。

## 4. 失败处理

| 失败场景 | 处理方式 |
| --- | --- |
| 首次启动，数据文件不存在 | 自动创建空清单，不报错 |
| 数据文件损坏（解析失败） | 不崩溃：将损坏文件重命名（移动）为 todos.json.bak，若该备份已存在则直接覆盖（仅保留最近一份）；重建空清单并提示用户 |
| 写入失败（磁盘满 / 无权限） | 保留内存清单不变，明确提示“保存失败”，不静默丢弃；后续任一写操作（新增/编辑/删除/切换状态）自动重试保存；退出前若仍未保存成功，提示存在未保存内容并要求确认（重试或放弃） |
| 写入过程意外中断（崩溃 / 断电） | 保存采用“临时文件 todos.json.tmp + 原子重命名”；适用条件（本期）：目标平台为 Windows 本地磁盘，临时文件与数据文件位于同一目录（同一文件系统/卷），todos.json 已存在时由重命名直接覆盖替换；启动时若发现残留 .tmp，直接删除、不读取、不提示错误，一律以 todos.json 为准 |
| 输入为空或全为空白字符 | 拒绝保存并提示“内容不能为空”（空白=空格、制表符、换行） |
| 输入超过 500 字符 | 拒绝保存并提示“超过 500 字符上限”（按去掉首尾空白后的 Unicode 码点数计） |
| 编辑 / 删除不存在的条目 | 提示“条目不存在”，刷新列表，不崩溃 |

## 5. 可验收标准

逐条可检验（通过 / 不通过）：

1. 新增待办后列表立即出现；关闭并重启后仍存在。
2. 标记完成并重启后，完成状态保持一致。
3. 删除待办后列表不再显示；重启后不恢复。
4. 提交空或纯空白输入（仅空格/制表符/换行）时，不创建条目并提示“内容不能为空”；提交 501 字符（不含首尾空白）时拒绝并提示上限。
5. 损坏样例与预期（可重复）：将 todos.json 整体替换为非法内容（如 `{bad`）或截断为原内容前半段后启动——程序不崩溃；todos.json.bak 内容与改坏后的文件一致；以空清单继续工作。再次重复该操作：旧备份被覆盖，仅保留最近一份。
6. 断网环境下全部功能与联网时一致（全程无网络请求）。
7. 数据文件仅出现在本机指定路径下，程序不向其他位置写入数据文件。
8. 第 4 节所列失败场景逐项验证：均有明确提示、无静默失败，状态保留/恢复方式与第 4 节一致；“无权限”可用只读文件或不可写路径复现，恢复可写后任一写操作即可保存成功并恢复正常提示。
9. 中断恢复（可重复；在本期平台 Windows 本地磁盘上执行）：保存进行中强制结束进程（或模拟断电）后重启，todos.json 要么为旧的完整版本、要么为新的完整版本，不出现半截内容；残留 .tmp 被清理，程序正常可用。

## P1：已取消的线程定位仍改变当前项目

新定位器组件的 `cancelled` 只在 `await locateThread(...)` **返回之后**阻止navigate/toast；而 `locateThread` 内部已经调用 `ensureProjectActive` → `focusProject`/`openProjectByPath` 改activeProjectId与导航偏好。页面卸载不能取消这些副作用。

两次干净独立运行均成立（`navigation-cancel/ui-result.json`、`navigation-cancel-repeat/ui-result.json`）：

1. 当前项目B（Own-B）；打开项目A的 `#/thread/:id`。
2. 仅延迟这次自有 `thread.get` 的真实回执3.2秒，内容未mock，服务端权限裁决不变。
3. 定位待完成时，用户转到 `#/settings`，标题栏仍B。
4. 回执到达，URL仍 `#/settings`，但标题栏切成项目A（proj-r61）。`realCalls=0`。

这是用户后续导航被旧请求改变的产品缺陷，不是仅“链接偶尔慢”。不能通过探针重试/等待定位完成、禁用切项目、增加sleep或强制导航回旧链接掩盖。

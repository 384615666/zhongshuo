## 2. 新页面两项实际缺陷，同批修复

### 搜索清空后迟到结果倒灌

`LibraryPage.runSearch` 对空关键词提前 return，未使在途请求代次失效。实际页面扣住合法旧请求→清空输入：此时q为空、rows=0；放回旧响应后q仍为空，却重新出现6条旧结果。

证据 `auditEmptyQuery`。清空、标签/范围/项目变更都要先废弃旧请求身份；同时结束旧加载态。结果归属与当前关键词/类型/范围一致，失败与成功空态分列。

### 收藏“当前项目”范围没有生效

收藏页仍展示范围下拉，但调用 saved.list 后不按 projectId 过滤。隔离库里建立另一个获准访问项目的收藏；当前页仍属A、选择“当前项目”，仍显示B的收藏。

证据 `auditSavedScope`，`scope=project`、`showsOther=true`。两个项目都获准访问，本次验证的是用户选择的筛选范围。按正式收藏行的 projectId 实现范围；无项目关联的链接明确处理，不能让下拉成为无效控件。链接类 status=ok、locate=null 也要给适用动作或说明，不能“定位”按钮静默无反应。

这两项不抹除R55已有正常链，也不另占一整轮；纳入本长批次集成。

## 3. 必须核清种子更换成员掩盖了什么

R55 报告称：Guide A 被60秒假停滞种子占住成员互斥，后续同成员派发“永久挂起”；换为Guide B后包验证通过。

换成员可消除验收前置干扰，但不证明正常产品不存在同成员排队缺陷。用**受控短暂忙碌、可显式释放的 fake**取证，不再依赖60秒盲等：

- 同Agent、两个不同任务：第二项在第一项忙时得到真实等待/受阻状态；第一项终态后按正式合同继续或给明确可执行入口，不能永久沉默。
- 同一DM连续消息的既有串行、水位、不提前注入、恰一次合同保持；房间/DM交错复用同Agent也要有明确归属。
- 停止/取消/成员停用/重启期间，待处理意图与预占分别结算，旧意图不复活。
- 按task/outbox/run/turn/lease身份和实际startTurn次数留证；结果若是测试配置、固定窗口或合同要求显式继续，也给完整事实解释和用户可理解的状态。

不通过增加并行额度、绕过成员租约、删除不确定保护或重建用户任务来解决；维持single_writer、既有预算与恢复守卫。旧失败保留。

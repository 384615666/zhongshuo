交付包：`dist/desktop/desktop-daily-win-v32-r95-20261020`。产品提交 `5c778b9cbc77f5af039b6de6121973e8a3c33342`，BUILD `bld_8951fbed63bf70e1`。

## 原显示问题

独立分析原本由模型返回 summary 和结构化结论，程序再压缩展示：超过10行或700字后，先抽取含“条件、待确认、分歧”等词的条目，再拼接原文开头，保留原列表编号。于是出现2、8、9、10在前、总览和1、3在后的现象，“查询条件”也会误入优先摘录。

用户明确要求由 AI 自己写总览和详细内容，程序直接展示。因此本轮删除整个关键词摘录函数；此前讨论的程序摘要改进方案作废。

## 当前规则

- 独立分析、互评、争议讨论、检查点、整合、确认均由同一次模型回复提供 `summary` 与 `detailMarkdown`。
- 气泡正文直接保存模型 summary 原字符串；附件直接托管模型 detailMarkdown 原字节。不按关键词挑选、重排、截短、改编号或补写标题，也不另起模型请求做总结。
- 最终公开回复同样使用该次 SYN 模型撰写的总览和详情。程序的共识聚合、附条件、反对、缺席等事实继续保存在 final_report 和运行详情，不拼接成 AI 发言。
- 新调用的 provider schema 与提示词要求展示字段；存储接收侧新增字段 optional，兼容旧格式。IND/SYN 原本必填的 summary 不放宽。
- 短结果可返回空详情，不生成空附件。全空白 summary 仅用于判断无效，不修剪有效原文。
- 托管失败或超限时保留完整 inline 详情。最终回复先在事务内保全原文，再绑定当前 SYN artifact 实际来源 turn 托管。

普通 DIRECT/私信原有的模型 answer/detailMarkdown 路径保留。旧格式使用完整兼容正文，不再程序抽取摘要；既有历史消息不重写、不自动重跑。本规则对新返回的结果生效。

> 本文是**可批准清单**：批准后按此执行，不追加、不自动扩组。

## 一、任务组（3 组；如首批材料区分度不足再议加 2 组，需另行批准）

同题同基线：每组同一任务正文、同一 fixture 目录，DIRECT（单成员）与 DELIBERATE
（两成员）各跑一次；两组使用相同模型（gpt-6-luna）、相同权限档（read-only 分析）、
相同输入材料（任务正文+目录文件清单）；研讨组**不获得任何额外资料或不同成功标准**。

## 二、每组预算（先声明、达上限即停、不自动追加）

- DIRECT：上限 3 调用（正常 1 + 格式修复余量 2）。
- DELIBERATE：上限 9 = 正常 7（IND2+CR2+SYN1+RAT2）+ 修复余量 2；尾部预留 S=1/Q=2。
- 单轮截止 420s；E4 宽限 20min（真实不触发）；每组总时限 45min（超时按合同收尾）。
- **总预算：DIRECT ≤9 + DELIBERATE ≤27 = ≤36 调用；组 A 的 DELIBERATE 侧已支付 7
  调用（既有成果复用），实际新增 ≤29。**

## 四、评分方法（材料维度，不预设研讨更优）

每组合跑完后出一张对比行，维度：
1. **事实准确性**：可核对要点命中率（机核：预设错误/异常是否被指出、是否引入错误事实）。
2. **漏项**：要点清单中未覆盖的数量（机核）。
3. **分歧处理**（仅研讨组）：互评是否产生真实修正（前后稿差异+确认记录；无分歧如实记"无分歧"）。
4. **可行动性**：结论是否可执行（人工评判，评判规则先行：给出可执行的下一步条目数）。
5. **调用量与耗时**：usage_records/budget_json/事件时间线（机核）。

**评判独立性**：机核维度全自动；"可行动性"由用户评判（材料呈现双盲编号，不标注哪份来自
研讨）；参与生成答案的成员不参与任何评判。不以 unanimous 与否、报告长度为质量证据。

## 五、执行与验收

- 批准后按 A(DIRECT)→B(两模式)→C(两模式) 顺序执行，经 real-delib harness（提交-观察分离）
  与 DIRECT 正常路径；每组结束跑 real-delib-audit（DELIBERATE 侧）+ 事实核对（机核脚本）。
- 全部完成后汇总对比表 → 请用户做业务价值判断 → 价值闸门结论记入总账。
- 未批准前：不批量运行、不开"各一组真实补证"（分歧/checkpoint/缺席/迟到的分支证据
  以受控用例为准，缺真实证据的部分在材料中如实标注）。

# DEV-25 v2 包操作补充说明（第三十七轮——适用正在验收的 dev25-dual-win-v2，bld_4d7928368c7da46f）

> 本补充**不要求重建/重启正在验收的包**：直接按下列更正操作即可。README 源文件已同步修正
> （下一版包自带）；本文件是当前 v2 包的权威补充。

## 1. 防火墙规则的正确程序（更正 README 的 electron.exe 说法）

**监听 HTTPS/WSS 的进程是 daemon（Node），不是 Electron 窗口进程。** 入站规则两种做法任选：

- **程序方式（推荐）**：
  `D:\<包路径>\dev25-dual-win-v2\ZhongshuoDual\resources\app\daemon\node\node.exe`
  （把你实际的盘符/包路径代入；规则=允许连接，专用网络）。
- **端口方式**：远程面板显示的 TCP 端口（服务重启端口不变——配置已持久化）。
- **不需要关闭整个防火墙**；公用网络 profile 不需要放行（局域网应为「专用」——系统设置→
  网络属性可查改）。

## 2. 多网卡/地址选择（UI 只有「仅本机」与「局域网（0.0.0.0）」两项——没有「填具体 IP」入口）

- 保持「局域网（0.0.0.0）」即可（它监听所有网卡，不挑 IP）。
- 面板 **LAN 地址列表** 会列出全部可用地址（如 `https://192.168.1.100:端口` 与其它网卡地址）
  ——从列表里选**客户端真正可达的那个**（一般是你局域网网段 192.168.31.x 的那个），连同端口
  交给客户端。证书 SAN 已覆盖全部 LAN 地址（0.0.0.0 启用时自动把每个 LAN IP 都写进 SAN），
  换列表里的地址访问**不会**出现名称不匹配。
- 客户端若报 `ERR_CERT_COMMON_NAME_INVALID`，说明用了不在列表里的地址（如主机名）——改用
  面板列表中的地址即可，无需改服务机。

## 3. 两枚指纹的核对口径（分开记录）

- **信任根（CA）指纹**＝`server-data\remote\ca.cer` 文件的 SHA-256：
  在服务机 PowerShell 执行
  `Get-FileHash -Algorithm SHA256 "<包路径>\dev25-dual-win-v2\server-data\remote\ca.cer"`
  （或 `certutil -hashfile <同路径> SHA256`），与面板「信任根指纹」逐位一致；客户端安装
  ca.cer 前在证书详情里核对同值。
- **服务证书指纹**＝面板「指纹」（页面/浏览器地址栏锁→证书所见的**服务证书**，对应
  `server-data\remote\identity.cer`）。它是**运行事实**（服务证书重签会变，属预期；CA 不变
  则无需重新导入信任）。
- 结果模板请**分别记录两枚**（见第 5 节的追加行）。

## 4. 配对码时机（避免信任操作期间过期）

配对码 5 分钟内一次有效。推荐顺序：**客户端先完成证书信任并确认页面能打开（锁形图标/
无警告）→ 服务机再点「生成配对码」→ 5 分钟内客户端完成配对**。若期间过期，重新生成即可
（新码是新的一次性凭据，不影响已完成的证书信任）。

## 2. P2：普通成功发送被双重结算，已发@选择不清

**R63先收口共享结算**：单一成功清算来源，同时处理正文/mentions/refs/一次性意图与账本，再把结算后的草稿同步现挂目标；不要两套结算互相改变代次。未编辑时清已发@，等待期新增/修改的正文/@/附件保留；成功、unknown原信封重试成功、切目标迟到回执采用一致规则。记录串意图保持既有仅记录语义，收口不能在崩溃中间态改成AI。

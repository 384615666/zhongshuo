## 3. 新 PPT 路径的确定缺口

### 3.1 重活绕回主线程、缓存命中绕过原件核验

`src/daemon/commands.ts:2440` 的 previewSlidesPages 在 daemon 内直接调用 safeUnzip/buildPptxPages（2466 附近）；没有通过既有 parsePool 的可终止子进程、端到端截止和内存限制。缓存命中在 readVerifiedBlob 之前直接返回（2458—2462）。缓存校验只看 schema/sourceHash/slides 是数组；原件缺失、损坏或越界时，命中路径仍可能返回旧预览。

要求：重活进入既有隔离边界；缓存命中也核对真实原件；缓存结构、页序、尺寸、UTF-8 字节预算、转换器版本与所见 revision 严格校验。写回前重读 artifact 的 id/hash/revision/归属，不能仅因注释写“迟到防覆盖”而算实现。SVG 入 DOM 前需有效的元素/属性/URL 白名单或独立安全渲染边界，不能仅凭 hash 相等视为受控。

### 3.2 纯函数最小复现（均已执行，无模型调用）

| 输入/反例 | 实际结果 |
|---|---|
| 页面只有 p:graphicFrame 中的 chart | shapes=0、truncated=false，输出没有“未渲染/不支持”提示：静默白页 |
| 单段 400 个“中”，文本框高度足够 | SVG 只有 300 个“中”，truncated=false |
| XML 文本 A &amp; B | 输出 A &amp;amp; B，重复转义，显示正文失真 |
| 同 sourceHash 的缓存，非法尺寸/页序，SVG 含 foreignObject 和 onclick | validatePptxPagesCache 返回非 null；前端 holder.innerHTML=sl.svg 接收该字符串 |
| 350 个文本形状，每段 200 个汉字 | SVG 137748 字符 / 277748 UTF-8 字节，未超“字符”阈值、truncated=false，却超过宣称 220KB |

代码锚点：`pptxPages.ts:37` 字符限额；`57` XML 文本未解码；`150` 只遍历 sp/pic；`199` 无标记截 300；`225` 弱缓存校验；`app.js:1000` SVG innerHTML。

要求：不支持的图表/SmartArt/组合等显式降级；所有丢弃/截断都有标记；正确解码 XML 实体再安全输出；数值/尺寸/字节数有界。当前支持的版面近似可以保留，不要求本轮重建完整 Office 引擎。

### 3.3 页面验收证据不足

`scripts/verify-desktop-renderer.mjs:1196` 只检查 SVG 存在，加上旧的提取文本卡片便判 PPT 页面通过。应补真实形状/图片样本的第一页内容与位置、下一页确实换内容、缩放尺寸变化、未支持对象提示、中文与特殊字符、关闭/切换时迟到预览不覆盖。纯函数 4/4 与出现空 SVG 均不能替代这些页面行为。

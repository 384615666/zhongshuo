## 一、进程树快照不再升级为完整退出证明

### 生产判定收紧（先关闭不安全的自动释放路径）

- **「未观察到存活后代」≠「已确认全部受管执行结束」**：probe 对 per-turn/shared **不再
  返回 exited**（结果枚举保留仅为兼容历史行，生产不再产生；升级前 ≤10min 的 exited 取证
  记录在 releaseProtection 处防御性拒绝并说明原因）。全部观察事实进 detail：
  「未观察到存活后代（登记根与 N 个历史身份均已确认退出、现存树为空）——但周期快照机制
  无法证明『最后快照之后无派生且父链已断』的执行载体不存在：未完整确认，保护保留」。
- **释放保护只剩程序事实路径**：`no-os-process`（none 模型）。reconcile executed 的 exited
  释放分支删除（统一走保护保留分支）；releaseProtection 仅凭 no-os-process 解除。UI 恢复
  面帮助同步说明（「有子进程 runtime 的服务端自动解除路径已关闭」）。未引入 ETW——按用户
  指令先关闭路径，让其他工程继续。
- **历史身份保存修复**（迁移 014 `process_tree_identities`）：旧 012 快照表每代
  DELETE+INSERT——父链已断但仍存活的后代从后续快照消失、新快照覆盖未确认身份。新表
  **追加式**登记：按进程代次（pid+started_at_ms——PID 脱离启动时间不构成身份）upsert
  （更新 last_seen_alive_at），**从不删除**；exit_confirmed_at 由 probe 核对后写回；已确认
  身份再次出现=防御性重开追踪。worker 观察（首拍+5s 周拍）改走新函数。

### 本地反例（新增 2 个，全部经正式命令链）

- **反例 1（历史身份不被覆盖）**：第一拍观察父→子→孙 → 父子退出、孙仍活 → 后续观察

- **反例 2（盲区如实）**：观察①只见父 → 两次观察之间完成派生（父 spawn 子、子 spawn 孙）

  （detail 说明周期快照机制边界），releaseProtection 拒绝——不是 exited。
- 既有用例按新语义改写：三代现场（孙结束后也仅「未观察到存活后代」，解除被拒）；
  shared/无观察/枚举失败同理；worker 生产接线用例同。**processTreeSupervisor 11/11**、

## 二、迟到回执与业务效果原子、按作用域幂等

- **事务边界**（迁移 015 重建 `late_event_receipts`）：回执 INSERT 与 applyEvent 全部
  业务效果（状态/预算/交付/审计）**同一数据库事务**——applyEvent 抛错=整体回滚，回执
  不残留（不存在「有回执无效果」状态）；失败留 `turn.lateEventFailed` 审计（事务外），
  **可恢复不静默丢弃**。无文件类非事务副作用（fake 持久化会话记录只读）。
- **作用域幂等键**：主键 (source_scope, turn_id, event_key)——事件源作用域=adapter
  kind+会话 ID，eventKey 不假设全局唯一；turn 身份入键（同键不同 turn 各自生效）。
- **归属校验**：事件须声明且匹配本 turn/本会话（turnId/sessionId 不符→`ignored` 回执+
  `turn.lateEventIgnored` 审计，**不替未归属事件强行认领**）；非终态事件与迟到 INTERRUPTED
  回执=ignored；已收口后到达=ignored+skippedTerminal 审计。处理结果 applied/ignored
  可区分，失败可恢复。
- **保护解除核对**：泵收口后**不再释放写入租约**——业务结果已确定与执行载体已停止是
  不同事实（第九轮二）；只释放准入占位+进程登记收口，租约保护仍走 probe/releaseProtection
  判定（fake none 模型经 no-os-process 正式解除，测试全链验证）。
- 反例（`lateOutcomePath` **9/9**）：业务应用异常（注入 applyEvent 首次抛错）→回执与
  效果整体回滚（**applied 回执 0 条**、交付 0、usedTurns 0）→重放正常收口（交付/预算
  **恰好一次**，不只查回执条数）；事务提交后回执响应丢失（再泵）→全 duplicate-applied；
  同 eventKey 不同 turn 各自生效；错误归属不认领。真实 CLI lateEvents 继续 unsupported
  （fake 双路径通过不提升真实能力）。

## 三、验收绑定具体交付版本

- **合同**（task.review）：提交必带 `deliveryId`+`deliveryRevision`（UI 展示时版本）；
  事务内**条件更新** `WHERE id=? AND task_id=? AND revision=? AND review_status='pending'`
  并核对影响行数（=1）；任务状态迁移同样条件更新核对。冲突明确区分：**已被新交付替代**
  （superseded→「当前待验收为第 X 版」，不自动套用）、**已处理**（不同命令号不再次生效）、
  **版本不符**、**跨任务交付**（RESOURCE_NOT_FOUND）、**事务内状态变化**（0 行=请刷新重试）。
  同 commandId 重放=命令网关幂等原回执（集成测试验证 replayed=true 且验收事实只写一次）。
- **UI**：task.get 返回 pendingDelivery（展示与提交同源）；REVIEW 时按钮带版本号
  （「验收通过（第 1 版）」）；提交绑定快照版本；新交付到来按钮随 task.get 刷新为新版本
  （不继承旧状态）；失败如实显示冲突原因（第 N 版：…）。
- **返工闭环**：changes_requested 的说明（review_note）注入**后续派发输入**（turnInput
  附注：「【返工】此前交付（第 N 版）未通过人工验收…验收说明：…」——明确关联被退回版本，
  不是无反馈重跑）；最新验收结论变为 accepted 后反馈自动消失（集成测试断言 startTurnLog
  文本含/不含返工附注）；不自动派发（返工仍经 redispatch 显式发起，无隐式模型调用）。
- 用例：**dev14Commands 10/10**（错稿防护 v1→v2 / 同号重放 replayed+事实一次 / 跨任务拒绝 /
  返工注入与消失）；**uiE2e 验收用例**（v1 按钮第 1 版→后台 v2 替代→按钮变第 2 版→
  验收 v2 成功、v1 仍 superseded 未被错写）。验收≠Git 提交保持独立（审计字段明示）。

## 实际可用范围与权限

项目默认只读。`project.writeAccess.get/set` 是正式事务/幂等/CAS 命令，确认目标目录后授权，绑定 canonical root 和物理目录身份。成员的 `acceptEdits/dontAsk` 只是偏好，仍须项目独立授权；旧项目、旧排队只读任务及模板不会自动提权。整盘根目录拒绝授权。归档/移除/重定位撤销已有授权，恢复不提权。正在运行、结果未知或退出未确认时拒绝变更授权，明确要求先停止并确认退出，不假报已撤销。

房间 DIRECT 和 DM 在创建事务中冻结授权及实际运行组合，发送、出队与正式 adapter 启动前复查。授权、程序、模型、渠道/配置或真实目录变化会拒绝旧写入；DM 的配置/写身份不匹配不续接旧 provider 会话。显示改名不重建运行身份。

Claude 使用原生 `--restricted`、固定的 Read/Glob/Grep/Write/Edit 工具集、`dontAsk`、无交互权限提示、strict MCP/bare，禁止 Shell、网络工具、委派及额外工具。原用户渠道 env 由有效配置解析共源传入进程，不复制密钥进模板/证据；无法确定覆盖来源时闭门。默认只读档从原生工具集排除写工具。没有使用 bypassPermissions 或全盘权限，也没有以提示词充当写入边界。原生相邻目录/junction Write/Edit 拒绝证据与创建证据分列。

机制核对来源为本机实际CLI帮助/版本与 [官方CLI参数说明](https://code.claude.com/docs/en/cli-reference)、[官方权限说明](https://code.claude.com/docs/en/permissions)；本机参数存在和协议回放本身不代记真实工具认证。

## 自然工作结果与修复

写任务进入既有 single_writer：先保存内容基线，实际 CLI 写后捕获 after/diff，与正式交付绑定。终态还要取得进程退出证明；不能证明时转 UNKNOWN 并保留耐久租约，重开仍受保护。没有提前释放，也没有由 helper/fake 代写真实成果。

真实验收修复了这些缺陷：

- 交付文件与文件树固定读取 revision=1，重开已确认 revision=2 时失败。统一读取最新已确认工作区快照；不可变交付/附件仍按明确版本，磁盘更新仍需明确重载。
- GLM 返回 Markdown，正式 TaskComplete 解析拒绝。worker 传原 resultKey 常量的正式 schema，Claude 原生 `--json-schema/structured_output`、Codex `outputSchema` 接真实返回；没有把任意正文伪造成交付。
- 模板创建事务已经加入房间，界面只回读成员和私信，@候选缺少新身份。成员/房间/DM 一起正式回读；读失败保留事实，只重试读取，不重复创建。
- 跨项目直接打开设置未对齐当前项目，授权表单永远未读且禁用。设置路由复用原 ProjectAlign/最新意图，在目标落位后挂载；原取消/交叉合同保留。
- 文件页从局部内存推断“改动集0”，与库中四个真实改动集矛盾。改用 `files.view` 的权限过滤确认窗口，最多最近100项；`changeset.readSnapshot` 绑定项目/任务/改动集/文件/audience，按选择读取hash核验的内容前像。沿用两栏/窄窗分步布局，前后文本分列，不填假增删行数，不激活原型mock撤销/暂存。二进制、缺失、失败、256 KiB超限各有真实原因。
- 差异元数据已读但尚未选文件时错误渲染空 content。真实零调用界面反例及实际渲染永久测试保留，已修复。

## 实际实现

成员页与详情通过 `member.update` 编辑名称和说明，明确 project/member/revision。名称去两端空格后 1–60 字，说明最多 200 字；旧版本冲突、归档/移除项目及错误归属拒绝。只改显示资料与版本，不重建成员、runtime、会话或任务；同名按稳定短 ID 区分。房间、@、私信、负责人读取同一 ID 的当前资料，历史正文原样保留。名称/说明/短 ID 搜索和启用筛选不修改业务状态。启用、配置、实际工作量分别显示；读失败保留已确认事实。

原型的 Profile 是可复用模板；现有 `agent_profiles` 已承载成员私有 runtime 设置。本批保留该绑定链，新增 `member_templates`，避免共享可变 profile。`memberTemplate.saveFromMember/list/update/createMember` 均为正式入口；保存来源必须是明确选定、已有明确绑定的成员，不能把动态全局默认当固定快照。

模板只保存名称、说明、渠道、模型 ID、执行程序引用与已有权限档。不会复制凭据、会话、私有提示词、认证、任务、成果、发送账本、projectId/rootPath/cwd。执行程序引用本身可以是路径。创建时复制配置到新成员自己的 `ap_<memberId>`，模板编辑/停用只影响后续创建；已有成员不自动同步。配置可保存而程序不可用，界面如实说明。创建不会派工、成为协调者、复用会话或加入在途轮次；加入未归档房间仅影响之后派发。

成员操作另有独立有界本地信封账本（64 项/256 KiB），不替代消息/未知任务账本。添加、编辑、配置、启停及模板写入在发送前耐久保存原 commandId/参数；成功、明确拒绝、未知分别处理。未知不会因重连/重开换新 ID 执行；只由用户同号同参重放。成功写入后回读失败只提供读重试，禁止再次创建；失败/未知保留原输入。表单捕获目标和导航代次，关闭、A→B、ABA 及迟到回执不改新表单。

随后用户主动补齐 zcode 的 **PPT、PDF、Word、Excel、MD** 五张参考图。此前“像 zcode/Codex 一样浏览文件”的方向在本轮已具体化为下列可验收效果，不应再以“目标模糊”要求用户重新设计。

## 1. 本轮用户目标与参考区

- 预览右侧应展示文件本身；文件标题/标签/路径在上，主要面积用于阅读，左右对话与预览分别滚动，预览可关闭/收起/放大，不能遮住输入或把对话挤成竖排。
- **PPT**：左侧可滚动缩略图，当前页突出，主舞台显示幻灯片实际版面，底部页码/总页数/跳页/缩放。用户参考实际样本为约 11.7MB、55 页演示文稿。
- **PDF**：白纸页面与页间滚动/分页、正确页数、页码/缩放，实际图文版面为主体。
- **Word**：分页文档阅读，标题、字体、行距、颜色/高亮、表格与页面边距尽量保持，不用提取段落卡替代文档。
- **Excel**：工作表页签、行号/列标、双向滚动、合并单元格与可支持样式，参考有蓝色表头、黄色分组行。屏幕浏览独立于模型选区，不把预览限制等同模型输入范围。
- **MD/TXT**：MD 排版阅读，文本按内容阅读；源码可切换，空文件明确显示 0 字节。图片能本地预览，与模型是否能看图分别说明。
- 用户允许预览区域参照 zcode 做到接近 1:1；**整套众说侧栏/项目/房间/任务产品不需要改成 zcode**，既有原型和正式合同继续保持。参考的是可见布局与操作，不要求读取/复制 zcode 私有源码。

## 2. 用户截图状态应准确解释

- PNG 行实际显示 `1100KB v1 预览`：原件上传已成功。此事实不能证明预览按钮已打开窗口或模型已读取，用户说“上传不了”是实际流程受阻的反馈，不应以“后台上传成功”驳回。
- TXT 与 PPT 行显示“失败”，具体原因只藏在 title 悬停。用户没有看到可处理原因；需直接就地说明，不让用户查事件流/开发者工具。

# 众说：以日常愿意使用为目标的整改方案

日期：2026-10-16。状态：方案草案，尚未实施。

依据：用户本轮七张截图、当前源码、已批准原型及项目保存的 Raft 源码分析。当前记录 HEAD 为 `4f7da14`，v25-rc11 运行源码为 `a2bc376`。本次只读审查并编写方案，没有修改产品、启动模型任务或操作用户正在使用的数据根。

## 一、对当前版本的判断

当前版本应按内部工程版对待。R86 的工程路线验证记录保留，但不能继续用这些记录证明日常使用已经顺畅。此前交付判断漏掉了普通用户连续操作：先打招呼、在同一串布置工作、增加同伴、@ 本串全体、看进展和接着追问。

目前的问题包括规则冲突、真实入口未实现、事实投影分裂、运行过程不可见及界面信息过载。应先修正产品规则和完整使用流程，随后再做视觉整理。

本轮目标：用户配置好已有 AI 后，能用自然对话完成一次多人协作，不必学习 AUTO、DIRECT、DELIBERATE、跟进名单、冻结席位等内部术语。

## 二、应该成为怎样的使用流程

1. 打开项目，选择检测到的模型，设好 AI 成员和协调成员。
2. 发一句话，立刻看见已发给谁、当前是否在连接或执行；普通问题直接回答。
3. 在同一串继续说“帮我看报告”，AI 在原串接手；需要材料时明确指出缺哪一份。
4. 原执行成员已在本串。用户可从房间成员中添加同伴；@全体只包含本串的 AI。
5. 多位 AI 围绕同一任务读取材料、交换有内容的意见，协调成员汇总。各自的有用反馈和结果在原串可见。
6. 用户继续追问能得到回答；明确要求修改时执行；待验收成果可返工或验收。关闭重开仍能继续。

写文件和多人讨论不应要求用户通过“@几个成员”猜测执行模式。@ 用来选择收件人；独立盲审、完整多轮研讨等特殊流程可保留为明确选择的高级功能。

## 四、先统一三项产品规则

### 4.1 本串成员是一份真实名单

- 房间成员是可邀请范围，本串成员是实际参与范围；当前一轮由谁执行是运行事实。前端不再拿一份空的“跟进名单”代替参与者。
- 原执行成员默认在串里。增加成员是明确动作，用户可从其他房间成员中选择；普通 @ 候选优先只列本串成员。
- 新成员获得完成本任务所需、且该用户有权分享的历史与附件。不能只加名字、不交上下文，也不能顺手带入其他私信或项目。
- 添加成员本身不启动一段无意义的模型对话。后续点名、对本串全体布置工作、或协调者发起明确交接，才形成执行。
- 移出成员不删除历史。正在运行时的停止与后续不再派发要分别处理；不能通过编辑名单篡改既有轮次和未知请求。
- 历史串从可靠的原执行者、实际参与记录恢复名单，不凭同名猜测，也不把整个房间批量塞进每个旧串。

### 4.2 普通对话可以自然进入工作

“你好 → 帮我审查报告 → 把 B 加进来 → 大家各看一下 → 汇总 → 按意见修改”应在原串连续完成。

显式添加同伴或点名新成员，本身就是用户改变本次收件人的意图；不再用“普通续问不能更换成员”把正常动作堵住。内部可以建立新的执行轮次，原消息、原任务与已有成果保持可追溯。

串内普通续问默认得到 AI 回答，不能因为已有成果便静默变成仅记录。验收和写入仍有清晰语义：反馈可先得到解释，用户明确要求修改后执行；原件与版本不能被暗中替换。“仅记录”继续作为用户主动选择的次级操作。

### 4.3 @负责收件人，协作方式由任务决定

- @A：A 回应；@本串全体：本串所有被选 AI 收到这项请求。
- “各自检查，然后汇总”应形成实际分工和回传，不因多选 @ 自动进入冗长的固定研讨阶段。
- 协调成员负责具体分工、必要交接与最终汇总，不能只说“我会安排”却没有真正通知同伴。
- 已经有另一位成员在与用户对话时，未点名的成员不抢答、不复述；无关房间成员不会被自动唤醒。

这些是拟修订的产品规则，覆盖当前相冲突的内部限制。后续施工需要同步前后端合同，不能只改 @菜单或删除错误提示。

## 五、把“无回应”作为阻断问题处理

目前没有读取用户实际运行根，不能仅凭截图断言是上游超时、任务没启动还是进度没有显示。施工时必须分别核对。

需要打通的事实链是：消息提交 → 收件人/任务接收 → 排队或连接 → 实际 AI 开始 → 内容/工具进度 → 回复或成果 → 结束/失败。

- 发送后立即显示发给谁和送达状态；正常本地响应下，两秒内应能看见排队、连接、运行或失败中的真实状态。
- 模型尚未开始时显示“正在连接 AI”或真实等待原因，不能谎称正在阅读文件。
- 模型产生可见回应后及时展示；有意义的读取、审阅、交接进展进入原串或紧凑状态，不等最终结构化成果才首次反馈。
- “收到，开始处理”等 AI 正文必须来自模型。程序可以显示送达状态，不代写虚假 AI 回复。
- 长时间无事件、进程失败、渠道不可达要及时转为明确状态和下一步动作，不能永久旋转或只在事件流埋错误。
- 报告未找到时直接询问或给候选文件，不能无人声地等待数分钟；配置缺失时在发送前提供直达修复入口。
- 上游正常等待不承诺两秒生成答案；两秒目标是本地反馈可见，而不是伪造模型速度。

## 六、界面收敛到日常语言

主界面保留消息、当前成员、必要状态、附件、输入框和发送。运行预算、协议、快照身份、工程认证和阶段调度进入高级详情或诊断。

| 当前内容 | 处理 |
| --- | --- |
| 协调成员接单规则、复杂任务分工规则的常驻条 | 删除；房间成员入口足以显示协调者 |
| “跟进名单和成员管理不是一回事”、条款编号、字段名 | 删除；统一显示“本串成员” |
| “配置成功≠已认证”“以真实结果为准”“不显示假开关”等 | 从正常配置界面删除；必要诊断留在诊断页 |
| 加入跟进（未接入）、尚未接入功能的灰色按钮 | 基础必要功能完成接线；当前版本不提供的可选功能移出正常页面 |
| runtime、程序路径、内部模型标识等配置项 | 常用界面叫“AI配置”，模型提供下拉；程序路径等放高级设置 |
| CONVERSATION_TARGET_CHANGED 等内部错误 | 修正规则冲突；确有错误时用简短人话和可操作按钮，原错误码留诊断 |
| AI反复自述“当前只读规划模式、先给方案再授权” | 让提示词与用户已选择的实际权限一致；普通问候和请求不灌输内部调度流程 |

真实失败、缺少材料、需要用户决定的事项和验收请求仍应显示。它们应当帮助用户完成当前动作，而不是一大段功能边界说明。

## 七、重新落实 Raft 的参考价值

本项目已有 Raft 发布包的历史源码分析，不需要再凭产品名字猜测。此次应落实的四件事：

1. 知道当前串有谁、各自负责什么，能找到合适的同伴。
2. 收到具体请求先及时回应，随后推进工作；有明确交接就真正发给对方。
3. 接收方被唤醒，读到正确的串与材料，在原串回传；不能把模型终端输出当作已经发出了群消息。
4. 对话有礼仪和收尾：不抢答、不回声复述、不无限互聊，完成交接和汇总后结束。

保留当前已经实现的身份、幂等、版本、停止和调用预算机制，使其在后台服务自然协作。不要求用户为普通“大家看看并汇总”理解整套工作流状态机。

参考：[Raft 主动协作分析](D:/zhongshuo/docs/raft-agent-proactive-collaboration-analysis.md)、[Raft 提示词源码证据](D:/zhongshuo/docs/raft-prompt-source-evidence-1.0.17.md)、[原型界面减负任务书](D:/zhongshuo/docs/dev-briefs/prototype-ui-declutter.md)。这些是项目保存的历史依据，不宣称代表 Raft 当前全部版本行为。

## 八、实施顺序与交付标准

### 第一阶段：修通一次自然协作（P0）

统一本串成员、添加/移出、@范围；修正普通串转工作与多人参与；确保发送后真实执行或明确失败，进度和回复可见。以上必须一起完成，避免只修菜单而后台仍拒绝。

### 第二阶段：让日常操作简单（P1）

模型自动发现和下拉、模型与思考等级联动；消息时间正序；复制/引用/收藏统一；全应用清理工程文案与无效入口。无需重新设计主题，沿已批准原型的视觉层级修整。

### 第三阶段：用真实日常路线验收

必须从普通用户入口操作同一份最终包：

| 路线 | 必须观察到的结果 |
| --- | --- |
| 空白项目首次配置 | 模型可选、配置可保存、成员和协调者可理解；不预置工程任务替代首用 |
| 你好 → 同串审查报告 | 原串自然进入工作，原执行成员已在串，无收件人变更错误 |
| A/B/C 在房间，A/B 在串 | 本串全体只找 A/B；C 没有额外调用 |
| 增加、移出同伴 | 名单、@候选、实际收件人和重开结果一致，按钮真正完成操作 |
| 两个不同模型协作 | 各自实际读取报告、给出有内容的意见、交接并汇总；不是两个无关成功任务 |
| 持续追问与明确修改 | 追问直接回答；修改有真实文件与版本，验收对应本次成果 |
| 等待或失败 | 真实等待原因/失败可见，状态收敛，草稿和原件保留；不自动重发未知结果 |
| 消息和界面 | 正序稳定、只保留三项消息操作、无工程说明遮挡正常操作 |
| 关闭重开 | 原串、成员、文件与成果可继续阅读，无重复执行或丢失上下文 |

工程侧自己完成这组验收，使用等价合成报告与已有可用渠道。至少一份报告应包含真实可发现的问题，验证 AI 确实读懂并指出问题；不再只靠“你好”、简单 greeting 文件或计数证明产品可用。

记录所有真实步骤和失败，产品界面由真实操作截图核对。数据库断言和测试数量用于支持这些结果，不能代替上述连续使用体验。

三阶段完成后交付一个可供日常使用的候选，不再每修几个按钮就把用户叫回来重测。当前不要求用户继续测试，也不承诺凭这份方案已完成整改。

## 九、边界和资源

- 本轮聚焦 Windows 桌面自然协作，不扩 Android、安装器或新主题。
- 不删除旧包、用户数据或失败证据；不为修 UI 绕过权限、修改未知信封或自动重放请求。
- 新旧串的名单与配置需要兼容；成员添加发生在明确操作之后，不能借升级擅自扩大读取范围。
- 当前材料足以开始设计整改，不需要用户再找模型、购买资源或反复截图。若必须查具体失败，优先使用用户明确授权范围内的脱敏诊断；未查到之前不编造渠道原因。
- 模型清单优先读实际 CLI/渠道支持的元数据，不为显示下拉制造推理调用；无模型枚举能力的自定义渠道保留手动输入。
- 本轮仍先交方案。产品规则与完整使用流程确定后，再向开发会话下达统一施工要求。

## 十、补充：提示词与真实注入链必须作为 P0 整改

用户追问后进一步核查，发现常驻提示词不仅是内容需要调整，Claude 的真实传递路径还存在遗漏。

- `src/contracts/prompts.ts` 中确实存在参考 Raft 编写的常驻模板：身份、同串回复、协作礼仪、具体交接、简短进展等。
- worker 将模板以 `OpenSessionInput.developerInstructions` 传给 adapter。Codex 将其加入 `thread/start` 或 `thread/resume` 的请求。
- 当前 Claude adapter 的 `openSession` 没有保存这段字段，`startTurn` 也没有将它注入 CLI。每轮任务输入仍经 stdin 发送，不能说完全没有提示词，但常驻协作规则这一层缺失。
- 已用生产 Claude adapter 加假进程做零推理反例：显式传入的常驻哨兵既不在 argv、也不在 stdin，任务正文哨兵在 stdin。证据为同目录 `claude-standing-prompt-transport-counterexample.json`，真实模型调用和原生进程均为零。
- 当前房间每轮输入仍设置 `communicationContract.mentionEnabled=false`，并明确告知结构化 mention 未开放。已有 AUTO 程序分工链，不能据此宣称 Raft 式成员主动消息交接已经完整实现。

P0 需同时完成：正确传递各渠道常驻规则；让本轮真实可用的成员发现、通信/交接能力与提示词一致；修正普通交流、协调、实施、评审等角色的提示词覆盖关系。逐渠道检查首次和续接、纯文本和图片输入的实际传输，不能只断言 worker 已生成字符串，也不能用模型输出符合 JSON 证明常驻规则注入成功。

历史 R86 的实际文件协作和模型调用事实保留；“完整常驻注入与 Raft 主动通信已验证”的结论不成立，本次明确补为产品阻断项。方案仍未实施，不为检查而重放用户任务。

## 十一、新增硬性要求：电脑小白能够独立使用

用户进一步要求：功能简单易用，并检查现有功能对电脑小白的障碍。这是下一轮的交付要求，贯穿前述 P0/P1，不能只删几句文案便宣布完成。

### 11.1 判断标准

面向会操作 Windows 文件夹、但不懂 CLI、Git、模型 ID、JSON 和数据库的用户。以本机已有可用 AI 渠道为前提，首次使用的主路径应是 **打开项目 → 选择或连接 AI → 发出任务**。登录等确实必要的外部操作应有明确引导，不要求阅读长篇 README 或猜测设置位置。

每项常用功能都必须让用户看明白：现在在哪、会对谁或什么文件生效、下一步点哪里、操作是否成功。不把后台复杂度变成用户必须掌握的知识。

### 11.2 第一轮走查发现的不便与整改要求

下表来自当前源码、包内说明及用户截图的只读走查，不宣称已经对所有页面完成真人易用性测试。

| 当前不便 | 给普通用户造成的障碍 | 下一轮要求 |
| --- | --- | --- |
| 打开项目的弹窗同时有“浏览”和“打开这个目录”，还解释幂等、目录身份、单写锁域 | 不确定是否已经打开，误以为要配置工程环境 | 系统选择文件夹后直接完成打开；只保留确实需要的确认。欢迎页用一句话说明项目，移除实现说明 |
| 添加成员和配置 runtime 是两个分散步骤，默认执行成员可能尚不可用 | 建好 AI 却发不动任务，要自己寻找缺失配置 | “添加 AI”一次完成名称、现有渠道和模型选择；第一位可用 AI 给出协调者默认值。需要变更房间参与范围时清楚展示，不悄悄加入无关房间 |
| 模型名称、程序路径及多个配置身份需用户手填或理解 | 容易拼错模型、选错程序，不知道配没配好 | 自动检测已安装且已有配置的程序与模型，常用项下拉；提供简短的可用/需登录/未配置状态和对应操作。程序路径、自定义模型 ID 放高级设置 |
| 思考等级、权限、预算、跳过初稿、执行方式挤在输入区 | 尚未发任务就要理解一组运行参数 | 常用界面保留简洁 AI 选择、附件和发送；不常用参数进入设置。保留用户已经选择的默认完整权限，不借简化重新要求重复授权或静默改成只读 |
| 项目、房间、串内参与、跟进、关注、实际执行在多个名单中表达 | 无法判断谁会收到、谁在处理、从哪里加人 | 用户侧主要呈现“房间成员”和“本串成员”；AI 身份使用稳定名称及模型标识，技术短 ID 默认放详情。同一份事实驱动名单、@、收件人和运行状态 |
| 不同位置发送有时回答、有时只记录、有时变成研讨 | 相同动作产生不同结果，必须学习内部模式 | 默认发送即交给 AI；@控制对象；只记录必须是明确选择；高级研讨独立命名。所有入口反馈一致 |
| 用户说“看我的报告”时，不容易知道 AI 是否拿到了正确文件 | 可能等很久才发现缺文件或读错文件 | 可用选文件、拖入和粘贴图片；就近显示已附文件、上传状态和可点预览。项目中有多个同名候选时，给可选择的文件，不能让用户排查路径 |
| 成果、运行报告、附件、原件下载、会话导出混在一起 | 找不到真正生成的文件，误把导出聊天当导出成果 | 完成回复直接显示自然摘要和可打开的成果文件卡；清楚区分“保存文件”和“导出聊天记录”。普通文档默认阅读视图，源码与技术信息放次级入口 |
| 返工意见保存、明确执行、版本选择和验收分散 | 写了“帮我改”却没执行，或不知道验收的是哪版 | 在当前成果就近提供“按这些意见修改”和“确认完成”；意见保存与执行可由一次明确动作串联，后台保持原版本绑定。普通追问始终能得到回答，不强迫用户手选历史版本 |
| 恢复页面暴露 UNKNOWN、executed/notStarted、对账、预算退款和租约等 | 要求普通用户做工程事故判定 | 正常界面说明“发送结果待确认”或“上次任务中断”，提供查看结果、检查状态、继续等待等适用动作；仅在有安全依据时提供对应请求重试。技术判定放高级诊断，不自动重发或解除保护 |
| 设置中展示命令清单、派发防护、未接入开关和工程认证说明 | 可操作功能淹没在无关内容里 | 设置按用户目的组织；普通用户完成任务所需选项靠前，工程项进诊断，不提供无法完成操作的占位按钮 |
| 升级说明要求复制 server-data、profile、SQLite 及匹配旧程序回退 | 容易复制错目录、丢草稿或覆盖历史，难以持续使用 | 提供程序内“使用已有数据/备份与恢复”的引导，选择目录后由程序校验和完整保全，显示进度及失败原因。技术细节由程序处理；不擅自搬动原根，也不自动重放未知发送。无需把安装器或自动更新扩入本轮 |

### 11.3 文案和控件的统一规则

- 常用名称用“添加 AI、AI设置、模型、正在连接、正在处理、打开文件、保存文件、修改并继续、确认完成”等自然语言；后台的 runtime、adapter、turn、schema、resultKey、CAS 等不进入普通操作文案。
- 一个操作使用一致名称、图标、位置和成功反馈；按钮有明确动词。不能只用颜色或难猜的符号表示关键动作。
- 重要入口不能只能 hover 发现；弹窗能关闭、取消后回到原处，未发送的文字和附件保留。
- 表单提供合理默认值，只要求当前操作真正需要的必填项；能检测的程序、模型和路径先检测，不让用户重复填写。
- 错误信息回答“发生什么、内容是否还在、下一步怎么做”，并给就近动作。诊断细节可展开，不能用长篇术语代替处理入口。
- 不通过新增一整套强制新手教程弥补复杂界面；简短引导只在首次或真正需要时出现，之后可以关闭。

### 11.4 下一轮必须补做的便利性检查

对欢迎页、项目切换、添加 AI/模板、房间与串内成员、主池与串输入、文件预览、成果与返工、看板定位、设置、错误恢复、备份升级逐项登记：

1. 用户要完成什么；目前从哪里开始、实际要走几步。
2. 哪一步要猜术语、手填可自动检测的数据、找隐藏按钮或重复确认。
3. 简化后的默认流程及可见反馈；需要保留的高级能力移到哪里。
4. 在最终包从普通入口实际完成的证据；找不到或做不到就列为未完成，不用提示文案代替功能。

额外专项检查键盘和中文输入：Enter发送、换行、中文输入法候选确认不误发、Esc关闭浮层、Tab焦点可达；窄窗/Windows常用缩放下按钮和输入区可见；文件选择取消、保存取消、重复点击及断连后的文字保留。这些是新增必查项，当前没有逐项确认是缺陷。

### 11.5 验收从“预配工程环境”改为“首次和日常使用”

最终验收至少包含：

- **首次使用**：空白数据、检测现有 AI、添加两位不同模型成员、打开文件夹并发第一条任务，不依赖工程预置项目或手写配置。
- **普通对话**：打招呼、继续提问、附文件、增加同伴、@本串全体，正确收件并得到有用回应。
- **交付工作**：找到当前成果、预览和保存，提出修改并继续，确认最终版本；只需要自然语言与明确按钮。
- **遇到异常**：用户能看懂原因、保留输入并找到下一步，无需理解协议和数据库。
- **继续使用**：正常关闭重开、回到原项目/对话/文件；升级有引导和保全，不要求用户手工拼数据。

工程侧在最终包完成并记录这些路径，不要求用户再充当全量测试员。工程代理按新手约束操作仍不等同于真人小白认证；有真人自愿观察时再记录其独立完成情况，不能虚称已做人测。当前无需用户补测或提供新资源。

**交付判定：基础功能必须实际可操作，常用路径必须可发现、可理解、有回应。测试数量、说明文档长度和界面更换配色不能代替这些结果。**

## 已修缺陷和实际原因

- 持续RUNNING时revision/run/status不变，旧hook没有读取失效来源。现在可见详情每5秒有界单飞读取；慢回执不积累轮询，手动和依赖更新合并一次；隐藏、原界面接管、卸载作废并暂停，返回补读。项目/任务/所选run/私信身份收敛，失败保留确认快照、错误与成功读取时间，历史选择、滚动、展开及草稿/预览不重置。
- 服务端原先展开最近20个run全部轮次、用量和事件，而页面通常只看一个run。现在只展开所选run，其他run明确尚未读取；run/活动/交付分别提供20/120/50项稳定游标页。每页重查项目、任务、run及DM audience；切目标回执作废，单个旧页替换不累积无界缓存，新run不改用户选择。
- 成员卡原用局部已加载任务数组推断全项目，冷开误报没有任务。新增只读权威持久事实聚合，负责未结束任务、在途执行、UNKNOWN结果分列；轻量5秒更新不重复认证配置读取，读失败保留，成功0正常生效。
- 长详情多个flex区域导致历史控件溢出输入区。正文统一有界滚动，实际控件位置进入验收；历史阅读跨刷新保持展开与滚动。
- 正式worker将失败写为turn.statusChanged/status=FAILED/code/message，旧UI筛选只看turn.failed，漏掉真实原因。现在读取并显示状态变迁、原因和错误码；同一原失败记录旧组件不可见、当前可见证据保留。预算与用量按真实字段摘要，累计不重复相加，estimated/reported/unknown和增量分开，技术信息可折叠。

### 源码根因

- 工作区资源 audience=project，房间的可见资源过滤仍允许它；全局preview会话的显示状态沿用文件页，离开该页面没有按用户新目的地自动收起。
- `pages/Room.tsx` 的分隔条只在showThreadRegion分支内；主池+文件(L3)没有分隔条，不能满足用户房间中打开文件的拖动操作。L4分隔条还需核实际是否在两区域边界，不能只把DOM补进某个角落。
- `preview/PreviewPane.tsx` paneCls仅拼className，**没有使用preview.maximized**；Room页面的showContextRegion/showPreviewRegion/布局也没有消费该状态。现有`.preview-pane.maximized` CSS没有被应用，单纯togglePreviewMaximized只改变按钮。
- 共享预览的文件页/私信应检查同一问题，因为按钮和壳共用；不能仅对测试一个页面换文案就宣布全修。

## R73修复要求

### A. 文件页离开时自动收起

从文件与Git进入用户点击的房间，房间对话池/回复串与输入框按原型正常显示，文件页的预览不继续占用房间。将“关闭占用”实现为**自动收起**：保留打开标签、文件阅读位置与各草稿，用户明确再次打开文件/预览时才展开。

区分用户切换页面与文件引用/定位到对话的有意动作，避免全局“每次navigate都清预览”。不删除文件、不清空标签、不丢阅读位置，不影响房间中正常主动打开文件。返回文件页或显式重开时按既有会话语义恢复，不让迟到读取重新弹出已收起的面板。

### B. 真拖拽与真放大

- 房间主池+文件、线程+文件都有位于**真实两区域边界**的分隔条；鼠标/触摸板拖动改变区域实际rect，约束最小可用宽度，双击复位按原型。窄窗单区域模式正常降级，不出现两个线程/多输入条/横向裁剪。
- 拖动宽度与窗口resize适应分开：用户拖动设定不被窗口变窄永久改写，拉宽后恢复可用宽度，保持R71/R72修复。
- 放大按钮让文件区占满当前工作内容区（导航仍可达）；还原回此前并排比例。Esc按既有约定还原展开，不删除标签；弹窗/Menu优先处理其自身Esc，不穿透两级。PPT/PDF/Word/Excel/图片实际渲染尺寸随区域改变。
- 文件页/房间/线程/私信的共享按钮核其真实作用范围；不能覆盖标题栏窗口键或使当前输入区永久失去可达。

### C. 验证必须读实际几何与归属

1. 文件页打开MD/PPT→真实侧栏房间点击，房间正常，预览不占用；标签/阅读状态/未发草稿均保留；显式重开文件恢复。跨项目和在途读取后同理。
2. 从房间草稿、已发消息、线程附件打开文件，分隔条可找到且在真实边界；用原生pointer拖动正/反方向，左右rect确实变化，不只断言变量或role存在。
3. 放大前/后/还原前后rect、按钮状态、工作区边界符合；切标签阅读位置/页码/表不丢。测试Esc、窗口缩窄拉宽与较高DPR。
4. 文件页与私信共用预览按钮做必要检查。正文/引用/未知账本/验收返工/停止/能力门保持，打开/拖拽/放大绝不触发派发。

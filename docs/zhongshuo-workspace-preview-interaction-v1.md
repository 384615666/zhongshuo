## 0. 方案结论与适用边界

**一个项目工作区，两个主要内容区域：左侧保留用户正在工作的上下文，右侧按需要展示回复串或文件。**

1. 房间主池、任务回复串、私信、房间文件集合、项目文件与 Git 都可以打开同一个预览系统，私信继续遵守独立 audience。
2. 工作区默认最多并排两个内容区域，不包括最左侧应用导航。文件打开时，不把导航、主池、回复串、文件硬挤成四列。
3. 从主池打开文件，显示「主池 + 文件」；从回复串打开文件，显示「回复串 + 文件」。暂时隐藏的区域保留状态，不停止任务、不清空草稿。
4. 文件打开后，用户可以独立切换同一项目的房间或任务；在新上下文允许的可见范围内，文件不会因对话切换自动变更，来源始终可辨认。跨私信 audience 时暂藏受限资源。
5. 预览只用于阅读、定位、比较和引用。打开文件不自动发送给 AI，不自动运行 HTML，也不改变任何文件或任务状态。
6. 当前房间、当前任务、文件来源、引用发送目标是四件不同的事，不共用一个模糊的「当前上下文」。
7. 关闭预览恢复合理的讨论布局；返回来源只导航；停止任务必须是有明确任务范围的独立动作。

不把「完美」当作无需验证的承诺：本文给出明确推荐、边界和验收场景，实施后仍需用真实内容和窗口尺寸验证。

### 0.1 已确认的交互变化（实现仍待验收）

| 项目 | 本次确认 |
|---|---|
| 房间和任务的关系 | 保留原消息锚定回复串，主池仍是原消息与聚合，不复制完整回复 |
| 文件预览位置 | 从各页面分散的内嵌预览，统一到项目工作区的共享预览区域 |
| 线程成果页签 | 保留成果集合入口；打开具体文件不再替换原对话内容来展示文件全文 |
| 顶部栏 | 分为应用壳、上下文栏、文件栏，重新分配现有按钮 |
| 左导航 | 保留现有项目/房间/功能入口和设置边界，允许自动临时收起及手动展开 |
| 右侧 | 是可调整宽度的内容区域，不是只能装窄小工具的固定侧栏 |
| 任务/交付/运行详情 | 保留线程归属和既有动作边界；仅文件内容迁移到共享预览 |
| 执行、验收、Git | 不改变业务语义；看文件不等于验收、不等于应用改动、不等于提交 |

### 0.2 为什么不采用另外几种布局

- 不始终四列：常见桌面窗口无法同时给主池、对话、文档足够宽度，工具栏和任务标题会重现裁切。
- 不用弹窗作为常规预览：遮住对话，持续讨论和多文件切换不方便。弹窗只服务短暂选择和确认。
- 不把文件永远归到某个线程面板：房间附件、项目文件、Git 对比不一定属于当前任务。
- 不把所有东西做成全局页签：房间、任务、文件三套标签混在一起会失去层级。只有文件区域使用多文件标签。
- 本版不增加任意拖拽的 IDE 式多分屏，也不增加第二个 AI 对话侧栏。未来超宽屏三内容区需独立验证，不作为当前默认或交付前置。

### 1.3 窄窗“整页”与“弹窗”的区别

当前 `RoomPage` 在窄窗用 narrow ThreadPanel 并隐藏主池，注释称“覆盖式全屏页”。本文 §1 已记录窄窗隐藏主池；这里补足迁移语义：**整页切换属于合法导航，不是带遮罩的临时模态弹窗**。保留它的返回与状态恢复能力，把判断依据从固定视口断点迁到实际容器空间。

禁止的是常规文件阅读用模态层挡住对话，不是禁止窄屏全页文件/对话切换。迁移后单区域模式仍只有一块可见内容；隐藏区不得截获焦点、抢滚动或被当作已读。Esc 只回上一可见内容，不退出任务。

## 2. 信息架构：来源与工作目标分开

### 2.1 四个明确对象

| 对象 | 含义 | 谁改变它 |
|---|---|---|
| 当前项目 | 导航、文件权限和预览会话所属的项目 | 项目切换或已校验的深链 |
| 工作上下文 | 用户正在看的房间、线程或文件列表 | 点击导航、任务、返回或上下文选择器 |
| 预览对象 | 文件本身及其确定版本 | 点击文件、切文件标签、显式切版本 |
| 发送目标 | 本次输入将发往哪个房间或线程 | 输入框绑定的目标，或用户显式选择的引用目标 |

另保留两个来源：`origin` 表示成果/附件的真实归属，`openedFrom` 表示这次从哪条消息、哪个列表打开。二者可能不同，例如主池引用了一份任务成果。openedFrom 还可以是搜索/收藏结果，保存筛选、条目、滚动与返回位置，不强制把搜索结果当作房间。

同一个文件从主池和线程打开，不因此复制出两个相同版本的标签；同名但不同项目、路径或版本的文件，不能错误合并。

### 2.2 三个“文件入口”各有范围

- 房间「文件」：该房间内被分享的附件与成果，不等于整个项目目录。
- 线程「成果」：当前任务/**记录串**关联的成果、附件和交付文件。
- 项目「文件与 Git」：项目目录、任务改动、Git 状态和历史，不把所有磁盘文件伪装成任务成果。

三个集合复用预览器，不合并成范围不明的单个列表。房间没有任何任务的普通消息附件，也必须能独立打开。

私信文件另按 conversationId/audience 集合，不能混入房间 Files 或项目公开成果列表。项目归属相同不是私信附件可对所有项目成员分享的证明。

## 3. 布局状态：最多两个内容区域

### 3.1 五种工作布局

| 编号 | 左内容区域 | 右内容区域 | 典型操作 |
|---|---|---|---|
| L1 房间 | 房间主池/看板/文件集合 | 无 | 浏览房间、发新任务或讨论 |
| L2 房间与线程 | 房间主池 | 当前回复串 | 同时关注房间和处理任务 |
| L3 房间与文件 | 房间上下文 | 文件预览 | 看主池附件、房间共享报告 |
| L4 线程与文件 | 当前回复串 | 文件预览 | 对照成果讨论、引用代码或段落 |
| L5 文件工作区 | 项目目录或 Git 列表 | 文件/差异预览 | 浏览项目文件与改动 |

私信复用 L4 的“会话 + 文件”结构，不新增一套列数算法；左侧绑定 DM conversationId，不伪造 roomId。单独 DM 浏览与线程聚焦类似，具体权限和恢复见 §7.5。

线程可以处于单独聚焦状态 T：它是 L2 左侧主池暂时收起后的表现，也是 L4 关闭预览后可保留的状态。预览最大化 F 也是临时表现，不是新的业务页面。

### 3.2 打开文件的来源规则

> **本节只管"打开文件那一刻"**：哪一侧留在左边由**你点击文件的位置**决定（并写入 `preview.side`）。
> 打开之后你再点开别的上下文（另一条回复串、返回主池），左切换按 §3.3 走 ——
> 也就是"打开看来源、之后看你现在在哪"，不能因为文件是从主池打开的就一直压着回复串不让出来。

| 打开位置 | 打开后的上下文 | 收起什么 | 不得发生什么 |
|---|---|---|---|
| L1 的主池消息 | 原房间主池，原阅读位置 | 无 | 不强行进入附件所属任务 |
| L2 的主池消息 | 原房间主池 | 暂时收起右侧线程 | 不丢线程草稿，不停止该任务 |
| L2 的线程消息 | 原线程回复 | 暂时收起主池 | 不复制主池消息到线程 |
| 房间文件集合 | 原房间「文件」列表 | 同时打开的线程 | 不自动切到项目磁盘目录 |
| 线程成果集合 | 原线程「成果」列表 | 主池 | 不自动把列表切走；「回复」一键可达 |
| 项目文件/Git 列表 | 原目录、改动集或历史列表 | 房间/线程临时视图 | 不再嵌套一个独立预览 |
| 任务交付详情中的文件 | 该任务的交付详情 | 主池 | 不在文件区另造一套验收按钮 |
| 搜索或收藏结果 | 可解析时回到其真实来源上下文并定位 | 原结果页保留返回路径 | 不能仅凭文件名猜归属 |
| 私信消息/附件集合 | 当前私信/私信线程 | 会话列表可临时收起 | 不转成群聊，不扩大 audience |

搜索/收藏经校验导航至来源后显示上下文 + 预览；若仅有合法工作区文件来源则用 L5。来源不可访问时保留结果页并显示错误，不用当前房间替代。返回结果需恢复 query、过滤、scope、选中条目和位置；资源无有效来源不能强行生成线程。

在成果/交付列表打开文件后，左侧仍保留列表；用户点「回复」即可开始对照讨论，文件保持打开。这避免自动跳走来源列表，也满足对话与文件最终并排。

### 3.3 预览打开后切换上下文

- 同项目任务 A → B：左侧切 B，右侧仍看 A 的文件；来源栏写清「来自任务 A」，引用按钮目标更新为 B。
- **从主池点开一条回复串 = 收起附件、把回复串放到眼前**（用户明确要求，2026-09-24 修订）：点卡片时如果有一份**从主池打开**的文件正占着右侧，先执行「收起预览」（标签与阅读位置全部保留，可用重开入口一键恢复），然后显示「主池＋回复串」；不是把回复串挤成和文件各占一半。若该文件本来就是**从线程打开**的（说明用户正在这条串里对着文件看），则保持并排不收起。
- **点"已经开着但被附件挡住"的那条串，同样必须回到它**（实测缺陷：串的 `threadId` 没变，界面曾毫无反应）。点卡片是显式导航动作，不能因为 URL 没变就不响应。
- **打开文件之后再点开别的上下文（含从主池点开某条回复串）时，左侧直接切到新上下文，右侧文件保持打开**；`openedFrom` 只用于来源栏与引用目标，不决定"和谁并排"。实现上 `preview.side` 在打开时按来源写入（§3.2），之后每次上下文切换或显式打开回复串时被改写成新上下文所在侧。
- **主池被文件收起时仍要能切串**：L4（例如从线程打开文件）左侧只能是回复串，主池会暂时收起。此时回复串「⋯」里给出"回主池"与"直接切到本房间其他回复串"两条路，左端按钮也写成「主池」。
- 上述"保留文件"限于新上下文允许展示的资源。跨 DM/群聊 audience 时按 §7.5 暂藏受限标签，不能以同项目为由继续展示私信材料。
- 同项目房间 X → Y：同样保留文件，来源栏显示房间 X；侧栏高亮 Y，不把 X 同时标成当前房间。
- 点击另一份文件：激活或打开该文件标签，左侧保持本次点击所在上下文。
- 切到文件与 Git：左侧成为文件/Git 导航，右侧复用已有文件标签。未点击新文件前不擅自替换当前预览。
- 切到应用设置、成员管理等非文件工作页面：暂时隐藏预览，保留本项目预览会话；返回房间不丢文件。
- 切项目：保存 A 的工作区状态，展示 B 自己的工作区状态；A 的文件不悬挂在 B 的页面上。跨项目引用另行显式完成，不能靠留着面板实现。
- 后台消息、任务完成、新成果出现只更新计数和提示，不自动切换上下文、文件标签或版本。

### 3.4 关闭预览如何恢复

第一次从非预览布局进入预览时，记录一份返回快照：房间、线程、子视图、可见布局、分隔比例、焦点和阅读锚点。

1. 期间只切文件、滚动或缩放：关闭预览恢复这份快照，经当前窗口宽度重新校正。
2. 期间主动切过房间、任务或上下文子视图：关闭预览保留用户最新选择，不跳回旧任务。默认成为当前上下文单区域；用户可以点击「同时显示主池」恢复 L2。
3. 新消息更新、已读变化不算用户导航，不使返回快照失效。
4. 返回目标已删除或无权限：停留最近合法上下文，显示具体原因，不落到同编号的别的任务。
5. 快照只记录布局恢复，不保存可重放业务命令；关闭/恢复不会重新提交消息。

## 4. 顶部栏目标设计（不与第一轮验证捆绑）

本节是完整方案目标，不是一次重构要求。第一轮仅补回主池/恢复线程、资源标题/来源、收起预览和布局开关；沿用现有房间头、线程 tabs 与操作菜单。下列按钮重分配、任务选择器和文件完整工具条在第二批实施，减少同时回归的范围。

> **2026-09-24 更新（界面信息减负施工）**：本节 4.2 / 4.3 / 4.4 描述的顶部栏形态已被本次施工**取代**：回复串顶部只保留一条紧凑导航，原消息与状态改由「详情」和输入区目标摘要承担，预览的「预览/源码」切换收进「阅读 ▾」菜单。依据 `./dev-briefs/prototype-ui-declutter.md`。以下历史条目保留可查，但不再作为施工要求；以 4.2 / 4.3 / 4.4 中已改写的条目为准。

### 4.1 应用壳：全窗口只有一条

```text
[导航开关] 众说 / 当前项目                 项目运行摘要  [窗口控件]
```

- 项目选择器主要入口继续在左导航顶部；左导航隐藏时，应用壳显示可操作的项目切换入口，不要求先展开整个导航。
- 项目路径、分支等放入项目菜单或文件/Git 场景，不在每个内容区重复显示。
- 后台运行摘要必须写明当前项目范围；聚合待办继续在既有底部入口。
- 「停止当前任务」只属于线程操作；「项目全停」沿用当前原型的项目设置入口，不因放不下混进文件工具栏。
- 原型保留“模拟数据”标识；正式环境不展示原型实现说明。

### 4.2 房间顶部：位置栏 + 房间导航

```text
开发大厅 ▾                    [搜索本房间] [房间信息 ···]
[对话池] [任务看板] [文件]                 [未读 3]
```

第一行负责身份和房间操作，第二行负责房间内导航。房间名菜单可切本项目房间；不和项目菜单合并。

- 房间头部只保留**一个**轻量「房间信息」入口：点开显示协调者、成员数与房间说明。原并列的「房间设置」常驻入口取消，房间设置、成员管理、归档/取消归档统一收进房间名附近的房间「⋯」菜单，避免两个竞争入口同时抢位置。
- 通知/关注放进房间「⋯」菜单并显示当前状态；异常或已归档状态仍就地可见。已归档房间的「取消归档」必须在 ⋯ 菜单里保留可见名称，不能只留无文字图标或藏进二级说明。
- 未读数量是跳到首条未读的入口，文件开关不自动已读。
- 写入占用正常时不打扰视线：在对话池缩成**一行**简短状态，说明谁在写；达到并发上限或需要用户处理时，才显示原因与可执行动作；没有租约时完全不渲染占位，不在顶部永久放一段解释。
- L3 顶部与 L1 相同，不因右侧显示文件换一套房间页签。
- 若 L3 是从 L2 暂收线程而来，显示直接入口「继续 #14」或对应讨论摘要（含未读）。点击进入该线程 + 当前文件，不必重新找主池卡片；跳到其他房间后不继续显示原房间的该入口，可从历史导航返回。
- 在任务看板或房间文件集合下不显示“对话池发送框”；需要发消息先切「对话池」。

### 4.3 回复串顶部：一条紧凑导航（任务身份移入输入区）

```text
[收起/返回]   回复   成果   详情                       ⋯
```

- 顶部只有这一条紧凑导航。已删除的两行是：① 任务号 + 执行中/运行中状态标签 + 「另起任务/跳转首条未读/关注/静音/关闭」图标组；② 原消息摘要横条（展开箭头 + 作者 + 时间）。这两行的信息改由导航行末的「⋯」、输入区目标摘要与「详情」承担，不用同等高度的标题栏/编号条/状态条/原消息条补回来。
- 左侧只有一个按钮，按布局换文案与行为：L2 主池＋线程为「收起」（收起回复串，主池保留，图标 chevron-right）；单区域线程与窄窗为「返回」（回所属房间主池，图标 arrow-left）；L4 线程＋文件为「返回主池上下文」。三者导航目标都是回主池，均不停止任务、不清草稿、不删成果与文件标签；不能只给同一个无文字的 × 而行为随意变化。**该按钮与预览左端的「收起预览」共用同一个组件与样式**（见 §4.4）：同侧（各自区域左端）、同样式、文案与可访问名称各自准确。
- 常驻视图只有「回复/成果/详情」；讨论串为「回复/附件/详情」，无附件时可隐藏「附件」，但附件深链必须可达。
- 任务身份**不再由输入区上方的常驻摘要行承担**（2026-09-24 第三轮，用户要求整行去掉）：身份由三处表达 —— ① 房间头部（主池：房间名、协调者、成员数）；② 输入框 placeholder（`向对话池发布新任务 · 自动…` / `跟进 #12 · 延续共同研讨…`）；③ 「详情 → 任务概况」（任务号、真实状态、方式、阶段、派发摘要、来源与完整原始要求）。**接受的代价**：placeholder 在输入后隐藏，所以"边写长回复边确认发给谁"不再有常驻元素保证 —— 这是用户明确接受过的取舍，恢复时把摘要行加回即可（props 与 `.composer-target-*` 样式都保留）。归档只读房间里仍保留一行只读说明（说明"为什么不能发"，它不是身份行）。
- 「详情」是就地渲染的分组视图，分组为：任务概况 / 参与成员 / 活动与进展 / 运行详情 / 交付与验收 / 研讨详情（按任务实际情况出现，讨论串只有概况与成员）。分组导航是紧凑可换行的小 chip 行，不是第二条同重量的常驻页签栏；默认分组是任务概况。完整原始要求（原消息全文）在「任务概况」里可查，不再有顶部「查看原消息」。
- 交付需要用户行动时不能藏掉：「交付与验收」在详情分组内；待验收时在回复视图有可见处理卡并可直达该分组。空间不足时优先压缩分组 chip，不删除需要用户行动的入口。
- URL 继续沿用既有 tab 键（replies/artifacts/task/members/activity/run/delivery/deliberation），旧深链落进来即自动展开对应分组；`/task/:id`、`/run/:id`、`/deliberation/:id`、`/artifact/:id`、`/thread/:id?message=` 全部保留。
- 「⋯」在导航行最右侧，包含：关注/取消关注、静音/取消静音（都显示当前状态）、仅有未读时的「跳转首条未读」、复制本串应用内链接。**当主池被文件收起时（L4：左串右文件），⋯ 额外提供「回主池」与"其他回复串"列表**（附未读数；切换后文件与阅读位置保留）—— 这是"打开附件后打不开其他回复串"的修复；它不是常驻切换器，只在主池确实被挤掉时出现，且切换动作与 §3.3"左侧切到新上下文、右侧仍看这份文件"一致。
- **菜单项名称保持简短，解释进 tooltip**（减负第二轮 §2）：书写规则是"名称 ≤ 8 字、当前状态放在行尾的 hint、点了会发生什么放进 `title`"。例如行尾写「已静音」、名称只写「静音」，而"只改通知、不改参与与权限"这句进 tooltip。任何菜单项都必须带解释 tooltip。
- 左端按钮的文案按**在哪一侧**决定：主池在位时是「收起」（收起回复串，主池本就在左边）；单区域/窄窗是「返回」（整页返回主池）；**主池被文件收起时是「主池」**（tooltip 写明"可在主池里选其他回复串；当前文件与草稿都保留"）。同一个按钮、同一侧，只是把"要去哪"写清楚。
- **输入区不写教学文字、也不再单占一行身份摘要**（减负第二轮 §2 + 第三轮）：输入区上方只有输入框本身；`发布到 开发大厅` / `跟进 #N · 标题` 这类摘要行与"点击查看完整任务信息""新任务会在这里形成一张原消息卡"一起移除，说明进 placeholder 与「详情 → 任务概况」。写入占用同理：正常态只留一行事实（谁在写），策略解释进 tooltip。
- **发送/停止的位置在两区并排时保持稳定**（减负第二轮 §3）：预算提示、停止、本次运行设置、权限档位与发送组成一个**不可拆分的右侧操作簇**，容器变窄时整簇一起换行，绝不把「发送」单独挤到下一排；它每一行都贴右端。

- 线程切换**不再有常驻切换器**（旧规格里“标题菜单是当前房间的线程切换器”这条作废）：一律通过返回主池完成，在主池里选另一条线程。
- 停止任务改在**输入区操作区**：仅任务处于 ACTIVE/WAITING_USER/BLOCKED 时出现「停止任务」，点击后显示“停止中…”并禁止重复点击；任务详情里的停止动作保留，走同一套判定。关闭/返回绝不触发停止。
- 待验收、阻塞、运行失败：在回复视图有一条只在这些状态真实存在时出现的处理卡，可直达详情对应分组；授权请求与需用户决定的分歧本身就以消息卡留在对话里。根消息为讨论时，隐藏运行/停止/验收等不适用操作；讨论不调用模型的原规则保持。

「回复/成果/详情」仍是左上下文内部的视图，不是文件标签。成果列表打开文件进入右区；当前选中的左侧视图不被文件正文覆盖。

### 4.4 预览顶部：标签行 + 文件工具行

```text
[收起预览] [components.md  v3 ×] [DESIGN.md  v2 ×] [已打开 ▾] [还原]
[磁盘已更新 · 重新加载?]        [阅读视图 ▾] [引用到 #14] [···]
来源：开发大厅 › #14 › Codex 的成果 · 模拟资源
```

- **区域级「收起/返回」统一在左端、同一个组件**（2026-09-24 后续统一）：回复串的「收起/返回」与预览的「收起预览」位置同侧（各自区域的左端）、样式同一（透明按钮 + 图标 + 短文案，窄布局只留图标并保留可访问名称），文案与提示各自准确：预览 =「收起预览」（隐藏这一列，保留标签与阅读位置）、回复串 =「收起/返回」。右侧只留本区域的次级操作（⋯ / 已打开列表 / 还原）。
- 单区域布局下预览占满内容区，左端按钮是「对话」（回到对话区，预览标签保留）；此时「收起预览」仍在文件「⋯」菜单里可执行，避免左端出现两个都像"返回"的控件。
- 第一行只处理文件标签及整个预览区域。文件名只在文件标签上显示一次，不再作为正文上方的第二个大标题重复出现；放大入口在文件「⋯」菜单里，放大后标签行出现带文字的「还原」。
- 第二行只处理当前文件：**需要动作的东西**（磁盘更新后重新加载、阅读方式、引用、更多）。图片改为缩放/适应，PDF 改为页码/搜索，工具随格式变化。
- **版本只在标签上显示一次，口径全站唯一**（减负第二轮 §4）：固定交付/附件版本 = `v3`，工作区读取快照 = `读取 r3`（同一个 `revisionLabel` 产出）。工具行**不再重复**版本徽标 —— 同一份文件出现两种写法（标签 `v3` / 工具行 `R3`）会让人无法确认是不是同一版；完整 hash 与时间在「文件信息」里。
- 视图切换：常驻的「预览/源码」分段控件已取消，改为工具行上一个始终可见的按钮（**只写一次模式名**：`阅读视图` / `源码视图 ▾`），菜单内含「阅读视图 / 源码视图 / 自动换行」。Markdown/CSV 默认阅读视图，代码/纯文本只有代码视图——菜单里如实说明，不摆无效选项。不出现"阅读：阅读"这类名称与状态重复的写法。
- **来源行去重**：来源行默认只写一次归属（如「来源：开发大厅 · 某人的消息」）；**只有当"从哪打开"确实补充了新信息时**（跨房间、跨会话，或将来从搜索结果进来）才追加「从 … 打开」。归属与来路指向同一处时不重复写。
- 无任务归属的附件显示「开发大厅 · 某人的消息」；工作区文件显示「项目工作区 · 当前读取时间」；不得用当前任务补一个假来源。
- 路径、来源可省略但可完整查看；版本类型和引用目标不能被一起隐藏。
- 文件标签固定单行，超出后横向滚动及「已打开」列表；不让标签换行推高整个顶部。「已打开」入口只在标签溢出或存在暂藏资源时出现，标题只报数量，不回显暂藏受限标签名称。
- 同名文件在标签里补最短可区分父路径，完整路径在「⋯ → 文件信息」弹窗里；同一路径不同版本用明确版本后缀。不能只靠颜色区分。
- 右侧不放 AI 输入框。引用进入左侧明确目标的草稿，避免出现第二套不知发给谁的输入系统。
- 选中正文文字时提供「引用选区」按钮：把选中文字作为引用加入当前目标草稿，仍需用户点击发送。
- 附件/成果列表**不写教程文字**（减负第二轮 §4）："打开后会怎样"写进每个文件 chip 的 tooltip，列表里只留清单本身与空态一句话。

### 4.5 操作名称与结果

| 操作 | 结果 |
|---|---|
| 标签上的「关闭文件」 | 只关闭这个标签，切到右邻标签；无右邻则左邻；最后一个关闭时退出预览 |
| 预览左上「收起预览」 | 隐藏整个预览区，保留标签与阅读位置，恢复讨论布局；稍后可重开。单区域布局下同一位是「对话」（回对话区），「收起预览」在文件 ⋯ 菜单里 |
| 收起后的重开入口 | **放在房间头部**（与未读、房间 ⋯ 同排的一个 chip：`文件预览 N`），窄窗只留图标 + 计数。**不得用浮层压在输入区上**（曾经 `position:absolute` 浮在右下角，正好盖住发送按钮） |
| 菜单「关闭所有文件」 | 清空预览标签，再退出预览；不删除磁盘文件 |
| 「放大预览」 | 入口在文件「⋯」菜单；临时将预览占满工作内容区域，导航可保留；标签行出现带文字的「还原」 |
| 「返回来源」 | 导航并定位来源消息，预览保持打开；切项目时走已校验的项目导航 |
| 「收起/返回」（回复串导航行左端，与预览左端同一组件） | L2 收起回复串保留主池；单区域/窄窗回所属房间主池；L4 回主池上下文并按既有规则保留文件。不停止任务、不清草稿、不删成果与文件标签 |
| 「停止任务」（输入区操作区） | 只对 ACTIVE/WAITING_USER/BLOCKED 的任务出现，复用既有停止流程；显示“停止中”直到活跃 turn 结束；关闭/返回不触发停止 |

所有图标按钮都有可访问名称；不同关闭行为使用上述具体提示。Esc 不默认关闭文件或清空标签（也不关闭回复串）。

## 5. 左右侧区域与窗口自适应

### 5.1 左导航要改到什么程度

推荐保留现有导航顺序、项目展开关系、底部待办与设置，不增加一套常驻任务树。线程切换由任务标题菜单和房间主池承担。

- 完整导航首轮按现有约 246px 计算，允许以后单独调宽。
- 内容不足时可临时隐藏，应用壳的导航按钮始终可达；点开以临时抽屉浏览导航，选择后关闭抽屉。
- 自动隐藏只改变本次实际布局，不覆盖用户“平时展开”的偏好。离开预览或窗口变宽后恢复合适状态。
- 若用户明确锁定导航展开，就让内容区进入单区域切换，不违反最小内容宽度。
- 右区就是预览。大纲、文件信息、评论列表作为预览内部可收起的工具，不额外增加常驻第五列。

### 5.2 宽度契约

这里的数值用于约束“能否读和操作”，不是视觉风格 token。实现时以实际容器宽度测试。

| 区域 | 现有下限或待验证候选宽度 |
|---|---:|
| L2 房间主池 | **420px，沿用现有 MAIN_MIN，不改全局常量** |
| L2 回复串 | **380px，沿用现有 THREAD_MIN，不改全局常量** |
| L3 房间主池/房间集合 | 420px，先沿用现有下限，列表场景后续可单独实测 |
| L4 对话/私信/详情 | 440px，**仅预览实验的候选值**，不替换 L2 的 380 |
| 通用文件预览 | 480px，候选值，待实际内容验证 |
| 项目文件/Git 列表 | 280px，候选值 |
| 分隔条 | 8px，候选值 |

v1.0 的 360px 主池没有实测依据，现撤回；440px 不再作为回复串全局下限。按上表实验配置推导：L2 为 808px、L3 为 908px、L4 为 928px、L5 为 768px。**这些是验证预算，不是批准后的产品断点。** 内容宽度必须扣掉导航、外壳内边距和分隔条。

在 1372px 窗口、导航 246px、无额外外层沟槽时：可用约 1126px，L4 可以给对话约 480px、预览约 638px。1280px 同条件只有 1034px，扣分隔条后若对话 440px，文件剩 586px，必须重点实测中文正文、代码长行、表格和输入工具，数学放得下不代表好读。按候选值，1100px L4 需临时隐藏导航；900px 隐藏导航后仍不足 928px，进入单区域。最终取值按验证结果调整，不能用计算结果冒充可读性结论。

默认 L2 主池占可用宽度约 40%；L3/L4 优先给文件约 56%；各自按最小宽度钳制。用户拖动比例分模式保存，不用一份固定 580px 套所有模式。

### 5.3 降级顺序

1. 收起顶部低频文字操作到菜单，保留标题、状态、引用目标和主操作。
2. 钳制分隔比例，保证两区最小宽度；不缩小正文，不把输入框压成零。
3. 自动临时隐藏左导航，或遵循用户锁定导航展开的偏好。
4. 仍不足时切单区域：「对话/房间」与「文件」二选一显示；选择器位于内容顶部，显示未读与文件名。打开文件默认展示文件，返回对话保留阅读位置。
5. 进入单区域不关闭逻辑上的预览和线程。窗口变宽后恢复此前的逻辑布局。

双区域恢复需额外约 32px 余量，避免窗口边缘抖动；布局测量使用容器 ResizeObserver，兼容系统缩放与浏览器缩放，不能继续仅用 window.innerWidth < 1280。

### 5.4 输入区与滚动

- L2 两个输入区保留各自目标、草稿及发送按钮。键盘发送只作用于有焦点的输入框。
- L3/L4 同时只显示当前对话上下文对应的输入框；处于文件/成果/详情列表时用“返回对话”入口，不伪装列表也能直接发新任务。
- 文件预览、对话、主池独立滚动。拖分隔条不重置阅读位置。
- 输入工具优先收进菜单，发送按钮保持尾端；允许输入文本框随多行增长到上限，不强制把长指令塞进一行胶囊。
- 原型的**任务与记录**（2026-09-25 起：普通输入默认交给 AI，「仅记录」是输入区 ⋯ 里的一次性意图，见开发设计报告 §0.22）、结构化 mention、权限/意图等按既有产品决策保留；不能照旧视觉稿重新增加四档模式选择。

## 6. 文件标签、版本与来源

### 6.1 文件标签行为

采用直接、可预测的标签规则，不引入难发现的“单击临时预览、双击固定”差别。

- 单击文件打开标签；同一资源的同一版本已经打开则激活原标签，不重复创建。
- 双击不触发另外一种业务行为；Enter 与单击一致。
- 文件顺序默认按打开顺序，用户可拖动调整；仅更新激活时间不自动重排。
- 不静默关闭最旧标签。后台标签可卸载渲染内容以节省内存，标签及阅读状态保留，激活时重新校验资源。
- 首版不需要复杂的永久固定标签机制；“收起预览”天然保留全部标签。可提供「关闭其他文件」「关闭右侧文件」。
- 最后一个文件被关闭，退出预览并按 §3.4 恢复上下文；下次点预览入口显示空态和最近文件，不自动重开刚关闭的文件。
- 从不同入口再次打开已开文件，更新该标签的本次打开位置；其真实 origin 不变。旧打开位置只存在导航历史里，不能伪造文件归属。

### 6.2 三类版本，不混称“最新版”

| 类型 | 用户看到的说明 | 默认更新策略 |
|---|---|---|
| 任务成果/附件快照 | 交付 v3、附件版本、创建者与时间 | 固定版本；新交付出现仅提示“有 v4” |
| 工作区文件 | 当前文件 · 读取于 17:30；展示已读内容的 hash/revision | 文件变化显示“磁盘已更新”，用户点击重新加载，不突然替换正在读的内容 |
| Git/改动集/比较 | commit、before/after 或 base/ours/theirs，逐侧注明来源 | 固定明确的两侧/三侧内容引用；不以当前文件代替缺失基线 |

- 同一快照必须可重复读取相同内容；如果后端发现 hash 不匹配，显示异常，不能继续用旧版本名展示新内容。
- “查看当前文件”打开另一个标签，保留历史版本；只有存在经校验的路径映射时才显示该入口。
- 在版本菜单中选择另一份固定版本，打开/激活对应标签；不原地改掉原文件的版本身份和引用。
- “重新加载当前文件”只适用于工作区读取标签，更新读取快照；已插入草稿和已发送的引用仍绑定原快照。
- 文件被删除/移动：已保存的历史快照仍可读；当前路径失败则显示原因。改名映射要有可靠 fileId 或后端事件依据，不猜同名文件。
- 正在写入或持续输出的文件以稳定读取快照呈现，变化提示合并处理；不每次文件事件抢焦点或滚动到底。
- 缺失 before_ref 或文件过大不能生成 diff 时，如实显示“不具备此版本的完整比较内容”，保留可用侧。

### 6.3 来源显示和跳转

来源栏同时回答两个问题：这份文件属于哪里，以及我从哪里点开的。

例：`成果来源：开发大厅 / #14 / Codex · 从主池消息 #21 打开`。常态显示简写，展开可看完整链路。

- 「返回来源」优先定位本次打开的消息；「查看所属任务」进入文件真实所属任务，两者在不同情况下分开列出。
- 来源消息已删除但成果仍可访问：文件可读，来源显示已删除；不得返回到任意相邻消息当成原消息。
- 无来源消息的工作区文件：跳转到项目目录并选中该路径，不生成空线程。
- 成果属于其他任务但在本房间获准共享：从主池打开仍保留当前主池；源任务只有在用户选择来源跳转时才展开。
- 文件不可访问时，不用“当前项目”的相同相对路径替代；共享消息本身可读不意味着附件权限永远有效。

## 7. 引用、评论与继续讨论

### 7.1 预览不等于模型上下文

浏览文件只产生 UI 读取，不产生模型 turn，也不向所有房间成员广播文件正文。

「引用到…」是明确动作：把结构化文件引用加入指定草稿，用户再点击发送。当前 runtime 是否支持解析该格式，在发送前就要显示，不能收到后静默丢附件。

### 7.2 引用目标

| 当前上下文 | 默认引用目标 | 按钮文字 |
|---|---|---|
| 房间对话池 | 该房间主池输入框 | 引用到开发大厅 |
| 当前线程回复 | 该线程输入框 | 引用到任务 #14 / 引用到此讨论 |
| 私信/私信线程 | 该 conversationId/threadId 的输入框，遵守 audience | 引用到与 X 的私信 |
| 线程成果/详情 | 该线程；引用时显式切回回复，保存原详情位置 | 引用到任务 #14 |
| 房间文件/看板 | 该房间；引用时显式切到对话池 | 引用到开发大厅 |
| 文件与 Git，无明确讨论上下文 | 不猜目标，先选项目内房间或现有线程 | 选择讨论位置 |
| 预览最大化/单区域文件页 | 仍绑定先前合法的上下文，引用后回到该输入框 | 引用到明确名称 |

在 L2 没有预览时两个输入框各自工作；预览进入 L3/L4 后只保留一个讨论目标。不能用“最后聚焦过哪个输入框”悄悄决定跨区域引用目标。

点击引用时捕获目标 ID 和版本引用，异步创建快照完成后仍插入捕获的目标草稿。如果用户已经切到别的任务，只提示“引用已加入任务 A 草稿”，不把它插进当前任务 B。

### 7.3 引用内容

引用卡显示：文件名、版本/读取时间、选区位置、简短摘录、来源、移除按钮。结构化字段保存资源身份与 hash，不仅是一段“第 20 行”的自然语言。

- 文本/代码：完整文件引用或行范围；Markdown：段落锚点与文本摘录，尽量同时保留源位置。
- PDF：页码及可提取的文本选区；没有文本层时明确只能引用页面，不声称提取了文字。
- 图片：引用整个图像；区域引用可在后续增强阶段实现，不能伪装成已支持的精确锚点。
- Excel：工作表及单元格范围；PPT：页码；Word：转换后的页/段落标识与对应转换版本。
- CSV：按解析后的逻辑行、可选列和文本摘录定位，保存表头/分隔符/编码及版本信息；含引号内换行时不可把物理行号当作记录号。
- 视频：引用固定媒体版本的时间点（毫秒，可选区间）；以播放时长校验范围，不能仅存当前播放器的浮点秒数。更换编码/版本后不静默换算旧评论时间点。
- HTML 节点评论：绑定原始内容版本与静态净化后的节点映射、摘录；不能把重渲染时随机生成的 DOM id 当稳定锚点。
- 不支持精确定位的渲染器，提供文件级引用，不提供会失效的虚假行号。
- 工作区当前文件在引用时固定读取快照，保存实际被选中的那份内容。落盘期间发生变化，不把新内容替换进旧选区。
- 发送前再次校验目标和资源访问权限；失效显示待修复引用，不静默删掉引用后发送。
- 跨线程引用显式授予必要片段的上下文访问，沿用 context_grant 语义；不把来源线程完整历史带过去，不唤醒来源成员。
- 引用文本中的 `@成员` 是引用内容，不自动变成结构化 mention 或协作模式选择。

### 7.4 文件评论与“引用提问”分开

- 「引用到当前对话」用于在当前任务 B 讨论来自 A 的文件，目标是 B。
- 能否跨上下文引用还需验证目标 audience；当前用户能阅读，不等于可以对目标成员披露，私信规则见 §7.5。
- 「评论此文件」绑定文件版本和锚点，按照现有规则归到源任务 A 的评论/回复串，界面写明“评论将发布到任务 A”。不能仅因当前正在看 B 就把源文件评论归到 B。
- 主池普通附件已有来源根消息时，评论归入该根消息的线程；不存在则在用户首次提交评论时创建，不能浏览文件就创建空串。原任务/记录消息的业务属性保持。
- 工作区文件没有来源消息时，先选择讨论位置并引用形成可追溯对象，不能暗造“原任务”。
- 评论不会自动代表向 AI 下新指令；是否触发执行由已选的任务/讨论语义和明确发送动作决定。
- 评论存在正文草稿时可收起工具区，草稿保留；切文件后评论草稿按资源版本与锚点隔离。
- 新版本出现后旧评论留在旧版本，标“基于 v3”。不把旧行号自动贴到 v4；可以提供用户确认的重新定位，不能静默漂移。
- 评论列表默认作为预览内的可切换工具视图，暂时替换大纲/信息工具；不另开永久右侧列。

### 7.5 私信完整链路

- `ContextTarget` 支持 DM conversationId 及可选 DM threadId，任务可为空；`origin`、引用目标、草稿和评论均能表达 DM，不能借一个虚构 roomId 复用群聊路由。
- DM 消息附件单击后显示“当前私信 + 文件”；默认引用按钮写「引用到与 X 的私信」，评论归同一源私信消息/线程。归档会话能看已有文件，但发送/评论遵守只读规则。
- 从一个 DM 切另一个 DM 或群聊：重新校验该资源可见范围。默认把不在新上下文 audience 内的预览标签暂藏，连文件名和缩略图也不出现在公共“已打开”列表；按 projectId + audience 保存会话，回到原 DM 可恢复。
- 对本来就可被目标 audience 访问的项目公共资源，可以保留并引用；私信资源跨到群聊必须显式执行允许的分享/授权动作，显示文件、版本、来源与目标成员范围。没有这种能力时阻止操作，不静默复制正文。
- 浏览权限、分享权限、模型上下文授权分别校验；context_grant 不能自行扩大私信 audience。改变参与者后再次验证已有引用的可见性。
- DM 草稿键为稳定 conversationId + 可选 threadId，不能按显示名称/当前选中成员保存。与房间草稿一样保留正文、mentions、资源引用和意图，但要适配当前 DM 独立输入实现，不能误称已复用 Composer。
- DM 模式、参与者唤醒范围与 DIRECT 不可变相委派等现有执行规则不因打开文件改变。

## 8. 各类预览能力与错误状态

### 8.1 格式能力矩阵

保存、预览、提取正文、交给 AI 是四种独立能力。已有产品决策要求文本/代码/图片/PDF/Word/Excel/PPT 在 M3 发布范围内支持保存与预览；本文不把 Office 简化成“以后再说”。

| 类型 | 预览行为 | 首要工具 | 引用/解析限制 |
|---|---|---|---|
| 纯文本/代码 | 行号、搜索、自动换行切换、长文件按需加载 | 查找、定位行、复制、引用 | 编码异常要提示；二进制不能硬当文本 |
| Markdown | 默认渲染，可切源码；内部锚点就地定位 | 渲染/源码、查找、大纲 | 原始 HTML 不执行；引用绑定源码/段落和版本 |
| CSV | 表格化查看，可切源码；分页/虚拟化读取 | 查找、行/列定位、引用 | 解析规则与逻辑行号固定到版本；不执行单元格公式 |
| 图片 | 适应窗口、原尺寸、缩放；透明背景可辨 | 缩放、旋转、下载 | 是否支持模型视觉分析按成员能力独立判断 |
| PDF | 分页/连续阅读、页码、缩放、文本查找 | 页码、搜索、缩略图 | 扫描件无文本层时不冒充 OCR 已完成 |
| Word | 本地受控转换后的只读文档预览 | 页码/大纲、下载原文件 | 标明转换状态及可能的版式差异，不提供伪编辑 |
| Excel | 工作表切换、二维单元格阅读、范围选择 | 工作表、查找、定位单元格 | 不执行宏；公式值来自可靠读取/计算能力，缺缓存要说明 |
| PPT | 幻灯片列表与当前页预览 | 页码、缩放 | 静态预览不声称动画/媒体均可播放 |
| 视频 | 本地媒体播放、暂停、定位到时间点，不自动播放 | 时间轴、时间点引用/评论 | 可保存/可播放/可提取字幕/AI 可解析分别判断；不支持的编码显示明确原因 |
| HTML | 源码默认；静态渲染在隔离环境按需启用 | 源码/静态预览 | 无脚本执行、无应用 IPC/Node；普通文件预览不自动启动网站 |
| diff | 固定两侧版本；宽区可左右比较，窄区默认统一 diff | 前后版本、差异定位 | diff 是一个文件标签内的视图，不扩成更多工作区列 |
| 其他/不支持 | 文件信息与下载/外部打开入口 | 下载、复制位置 | 明确不能预览；不显示空白成功画面 |

动态网站、终端、完整代码编辑器不是本轮预览区的默认能力。Git 原有手动冲突编辑仍属于 Git 专用流程，本方案不删除它，也不在通用预览中添加保存按钮。

范围核对：开发报告 §25.5 的附件七类是文本、代码、图片、PDF、Word、Excel、PPT；RoomFiles 当前把文本/代码合成一项再加 CSV，不能据“七”这个计数判能力相同。现有选区评论原型列出 Markdown 段落、文本/代码行、CSV 行、HTML 节点、视频时间点五类锚点。本稿现全部保留，不擅自移出范围；原型文案不是已经实现或解码成功的证据。第一轮只验证文本/Markdown，余下作为完整计划保留，格式工作包和发布归属与决策 33、C8 一并核对，不默默删除既定能力。

### 8.2 读取状态机

`尚未加载 → 正在解析资源 → 正在读取/转换 → 可阅读`；分支包括 `失败可重试 / 无权限 / 资源缺失 / 版本缺失 / 不支持 / 内容过大 / 文件已变化`。

- 读取时保留原先左侧对话，不阻塞输入；预览区展示文件名及具体进度阶段，不能用永久骨架冒充加载成功。
- A 加载未完成就点 B：A 的回包只能更新 A 标签缓存，不能覆盖 B；关闭 A 后的回包不能重新打开 A。
- 同一当前文件连续刷新：只接受最新请求对应的读取版本，避免晚回包回退内容。
- 转换失败保留文件名、版本和下载入口，说明原因，可重试；不能悄悄加载旧缓存当成新文件。
- 文件过大：按需加载可支持的片段，并明确“当前仅显示部分内容”；搜索结果不能宣称覆盖未加载全文，除非后端确实做了全文搜索。
- 原目录暂不可达：区分仍可用的历史快照与无法读取的当前文件，不把整个项目所有历史成果都判不可用。
- 撤销权限时清理正在显示的受限内容并取消后续读取，不能以本地缓存继续绕过访问限制。
- 本地保存的工作区状态不包含可直接执行的命令；URL、Markdown、文件名和文件正文都按数据处理。

### 8.3 安全是已有本地应用边界的延续

资源解析在受控读取层校验真实归属、projectId、允许的根目录及 canonical path；相对路径、软链接和 junction 都不能越过项目/成果授权范围。来自附件的链接不能直接授予整个来源目录权限。

Markdown/HTML 中脚本、外部主动内容不得继承应用权限；外部链接走既有协议白名单。远程设备访问不能把本机任意路径直接变成下载接口。预览、导出和外部打开分别走明确方法，不把文件路径拼成 shell 命令。

## 9. 状态保存、未读和异步更新

### 9.1 状态归属

| 状态 | 保存键/范围 | 切换规则 |
|---|---|---|
| 导航展开偏好、各布局分隔比例 | viewer/client + 设备 | 自动收起不覆盖显式偏好；恢复按当前容器宽度钳制 |
| 房间页签、主池位置 | projectId + roomId + roomView | 使用消息 ID/条目 ID + 偏移，不只存 scrollTop |
| 线程子视图、阅读位置、展开块 | projectId + threadId + subview | 切线程分别恢复；不把 A 的运行页签对象用于 B |
| 主池/线程草稿 | 原有 draftKey，加结构化文件引用 | mention、附件、权限、意图和引用一起保存，不能只保存纯文本 |
| 文件标签、顺序、活动文件 | viewer/client + projectId + audience 分区 | 跨项目及私信范围隔离，关闭标签与收起区域不同 |
| 文件位置、查找、缩放、格式视图 | resourceKey + revision + viewerMode | 不同版本分别保存；不强行把旧行号套新版本 |
| 评论草稿 | resourceKey + revision + anchor + targetThread | 切对话和文件不串草稿 |
| 返回快照 | 当前一次预览会话 | 用户改变左侧上下文后不强制恢复旧上下文 |

原型可以用版本化 localStorage 模拟布局状态；正式版按既有 viewer/client 偏好与草稿持久化方案落地。资源正文由受控内容存储管理，不把大文件正文塞进 localStorage。

### 9.2 刷新、重启和错误恢复

- 刷新恢复活动项目、可访问上下文、预览标签及草稿；逐个校验资源，不信任上次存下的权限。
- 首次打开外部深链时以 URL 的明确上下文和文件为准，本地状态只能补布局偏好，不能覆盖深链。
- 资源失效只让对应标签进入错误态，其他对话和文件继续可用。
- 恢复 UI 不自动恢复运行中的任务。沿用现有启动恢复检查，不因恢复预览而调用模型。
- 程序关闭时只读预览无需“保存文件”提示；未发送消息和评论草稿需已持久化。未来若增加编辑器，必须单独设计未保存修改流程。

### 9.3 未读与阅读位置

- 只有实际可见的消息区域满足阅读条件才推进该区域已读位置；线程被收起、位于成果页签、预览最大化时不能因组件还挂载就全部已读。
- 打开某份文件不等于读完来源线程，也不等于验收交付。
- 用户正在旧消息位置时，新消息只显示“有新回复”入口，不抢滚动。
- 文件更新不抢文件阅读位置，任务完成不抢预览标签，其他任务进度不插入当前线程正文。

## 11. 路由、数据与组件落地建议

本节是实施契约建议，不把下面的字段当成现有 API。

### 11.1 布局状态与业务实体分离

```ts
type WorkspaceLayout = 'room' | 'room-thread' | 'context-preview' | 'files-preview';
type ContextTarget =
  | { kind: 'room'; projectId: string; roomId: string; view: 'chat' | 'tasks' | 'files' }
  | { kind: 'thread'; projectId: string; roomId: string; threadId: string; tab: ThreadTabKey }
  | { kind: 'dm'; projectId: string; conversationId: string; threadId?: string; view: 'messages' | 'files' }
  | { kind: 'files'; projectId: string; view: 'files' | 'git'; selection?: string };

type ContextLocation =
  | { kind: 'context'; target: ContextTarget; messageId?: string; anchor?: string }
  | { kind: 'search' | 'saved'; query: string; scope: string; projectId?: string;
      resultId: string; filters: Record<string, string>; returnRoute: string; anchor?: string };
// 搜索/收藏是打开来源和返回位置；解析后导航至实际 ContextTarget，不另造搜索房间。
// VerifiedOrigin 必须覆盖 room-message、room-thread、dm-message、dm-thread、workspace。
// 资源解析结果另有 audienceId/accessDescriptor，由受控层校验，不由 UI 自填权限。

type ResourceRef =
  | { kind: 'artifact'; projectId: string; artifactId: string; revision: number; hash: string }
  | { kind: 'attachment'; projectId: string; attachmentId: string; revision: string; hash: string }
  | { kind: 'worktree'; projectId: string; rootId: string; relativePath: string }
  | { kind: 'snapshot'; projectId: string; snapshotId: string; hash: string }
  | { kind: 'diff'; projectId: string; left: FixedRef; right: FixedRef };
// FixedRef 是固定 artifact/attachment/snapshot/Git blob 的联合，不允许可变 worktree。

type PreviewTab = {
  key: string; // 含项目、资源身份、固定版本/比较双方；不是 basename。
  resource: ResourceRef;
  loadedRevision?: string; // worktree 本次读取的不可变内容标识。
  origin: VerifiedOrigin | null;
  openedFrom: ContextLocation;
  viewerState: ViewerState;
  requestGeneration: number;
};
```

还需要：活动上下文、可选已选线程、文件标签集合、返回快照、上下文导航代次、预览展开/最大化状态、布局偏好与实际自适应结果。业务状态、布局状态、请求状态各自负责，不能用一个 `activeTab` 同时表示任务与文件。

对外统一入口建议：`openResource(ref, openedFrom)`、`activatePreview(key)`、`hidePreview()`、`closePreviewTab(key)`、`navigateContext(target)`、`quoteResource(ref, selection, capturedTarget)`。

### 11.2 路由与返回/前进

保留现有 `/project/:projectId/room/:roomId?thread=...&tab=...`。新增独立预览参数，语义建议：

```text
主池 + 成果：
/project/P/room/R?view=chat&previewKind=artifact&previewId=A&previewVersion=3

线程 + 成果：
/project/P/room/R?thread=T&tab=replies&previewKind=artifact&previewId=A&previewVersion=3

项目文件：
/project/P/files?view=files&file=docs%2Fdesign.md&previewKind=worktree
```

- URL 记录活动上下文和活动资源；文件标签全集、面板宽度、滚动、临时收起状态是本机 UI 状态，不混入分享链接。
- 原型 `parseQuery()` 当前是手工按 `=` 分割，实施新增文件参数时须换为 URLSearchParams 或等效完整解析；不能截断带特殊字符的路径、查询值。
- `worktree` 链接明确表示“查看当前文件”，不承诺别人稍后打开仍是相同内容。“复制此版本链接”先取得可解析的固定 snapshot 引用；无法保存该版本时禁用并解释。
- `previewId` 必须能从正式资源服务解析，不能分享仅此窗口内存有效的 tabKey。相对路径先经项目根校验，URL 不携带任意绝对磁盘路径作为授权。
- 打开/切换房间、线程、具体文件、显式文件版本、返回来源：push 一条导航历史。重复点击同一目标不增加记录。
- 同上下文页签切换延续当前 replace 策略；拖宽度、滚动、缩放、窗口自适应不写历史。
- 用户关闭/收起预览：push 当前无预览位置。按浏览器后退可以重看之前文件，这是显式历史恢复；不能因关闭操作自动执行 history.back() 而跳去不相关页面。
- 后退/前进先恢复 URL 指定活动对象，再合并现有后台标签；若指向曾关闭的标签，可重新打开那个资源。资源失效显示具体错误，不用本地保存的其他文件顶替。
- 私有偏好、跨项目权限和草稿不通过分享链接传播。预览链接不隐含发送、下载、执行或验收命令。

### 11.3 旧链接兼容

| 旧入口 | 新落点 |
|---|---|
| `/artifact/:id` | 校验真实归属后，来源线程回复 + 该成果预览；无合法源线程时显示可解释的资源页 |
| `?thread=T&tab=artifacts&artifact=A` | 保留 T 的成果集合，并在右侧预览 A；不丢用户原列表上下文 |
| `/task/:id`、`/run/:id`、研讨详情旧链接 | 保留既有 threadNav 解析，不因预览迁移改成全局文件标签 |
| 文件与 Git 中某路径/某改动集入口 | 对应项目列表 + 共享预览，校验左右比较版本 |
| `/project/:id/changes`（RoomFiles 的查看 diff） | 先复用现有兼容解析到该项目文件/Git 的改动上下文，再解析准确 changeSet/文件/双方版本；未指定文件时显示列表，不任意选第一份 diff |
| 当前 `/project/:id/dm...` 及旧 DM 深链 | 按现有会话解析器校验成员、conversationId 和 audience，进入 DM + 文件；不构造房间路由。实际路径格式以该解析器为准 |

历史 artifact 模型要求 taskId/threadId，但主池普通附件不应被强行塞成“任务成果”。需要独立附件资源描述或正式统一资源层，保留零任务归属合法性。

### 11.4 组件改造边界

| 当前位置 | 建议改造 |

| `TitleBar.tsx` | 保留导航开关和项目范围，增加收起时可用的项目选择；不承载当前文件操作 |

### 11.5 实施顺序

0. **先补最小资源与草稿契约**：定义无 taskId 的 Attachment/ResourceRef、消息资源关联、可追溯来源/audience、固定文本版本、结构化 DraftReference。当前 `{name,size}` 只能用于旧草稿的展示迁移，不能凭文件名复原可读资源；迁移失败标“需重新附加”。原型先用独立 mock fixture 贯通主池与线程消息入口；正式 schema/API 作为 DEV-01 contracts 增量登记，不能把模拟字段直接当成既有生产协议。
1. **小范围 spike（试验原型）**：只实现一个固定文本/Markdown 资源、主池与线程两个打开入口、L2→L3/L4→恢复、两个独立草稿、收起/关闭、容器自适应。保留旧头部和原有全局宽度常量，使用隔离实验入口；不同时重排全部 tabs、不接真实 Office、不扩展所有全局页面。该步骤不是发布验收。
2. **扩大状态和入口**：spike 通过后验证 L1—L5 完整转换、DM/搜索/收藏、多文件与版本、顶部目标布局、请求竞态和 audience 隔离，再迁移到默认入口。
3. **接入引用和评论**：发送目标、版本锚点、跨线程限域引用、无任务附件与 DM 评论；结构化草稿要同时迁移，不仅是给旧输入框加字段。
4. **补齐格式与 Git 比较**：图片、PDF、Office、CSV、HTML/视频锚点、diff、异常与大文件。这是实施排序，不把已有 M3/v0.1 承诺移出发布范围。
5. **收口**：按 §1.2 同步权威文档、候选稿和测试；保留旧链接兼容。设为默认之前完成对应阶段测试，不要求 spike 一次覆盖完整产品。

### 11.6 Spike 的出口与不能删掉的底线

- 必须包含主池无任务附件及线程成果两条链路；不能按“只做线程文件 chip”的简化建议漏掉用户最先补充的主池场景。
- 在 1280/1372px 下使用真实长度中文任务标题、两行摘要、多行草稿、Markdown 表格和长代码行；再验证 1100/900px 的退化。1280px 若只能勉强塞下，调整候选 L4 分配而非缩字号。
- 通过标准：两个来源都能打开，两个草稿不串，收起能恢复，标题/发送/引用可用，读取响应不覆盖新目标，实测截图与状态记录可复现。仅数学满足最小宽度不算通过。
- 即使是 spike，也不移除资源来源、目标绑定和最基本的权限边界；采用本地 mock fixture 时明确不读取真实文件。所谓“安全矩阵后置”只表示完整集成验证后续进行，不是先开放任意路径和脚本执行。
- 本轮只规定试验要求，没有实现或运行 spike；所有可读性结论仍待实测。

## 12. 键盘与可访问性

- 顶部文件标签用 tablist/tab 语义，左右方向键移动，Enter/Space 激活；关闭按钮有文件名，如“关闭 components.md v3”。
- 分隔条用 separator，支持键盘调整、最小/最大范围和值说明；双击恢复该布局默认比例。
- 文件打开后焦点移至文件栏，屏幕阅读器播报文件名与版本；用户明确插入引用后焦点回目标输入框。
- 收起预览时回到打开文件的控件或合法上下文标题；如果该控件已卸载，不丢到 body 或不可见元素。
- Esc 按最上层处理：关闭菜单/选择工具 → 退出预览最大化 → 返回单区域的上下文；不默认删除标签、清草稿或停止任务。
- Ctrl/Cmd+F 搜索当前有焦点的文件或对话区域；全局搜索继续 Ctrl/Cmd+K。浏览器与桌面壳冲突的快捷键须单独适配，不拦截系统关闭窗口。
- 可提供“切到对话”“切到文件”“收起预览”的命令菜单入口，不强制用户记额外快捷键。
- 状态具备文字与图标，未读、当前项目、当前线程、当前文件不只靠颜色表达。

## 14. 分阶段交付的页面状态

以下是完整方案的场景覆盖，不要求单次提交交齐。**施工先完成 §11.5 第 0 步与第 1 步的 spike**：一个文本资源、主池和线程两种入口、两个草稿、关闭恢复及 1280/1372/1100/900 宽度；下面列表的 1—3 和 8 只覆盖其中最小链路。通过后按施工说明继续完成其余已授权的原型交互，不以“还需再次批准方向”为由停在 spike；真实后端能力单独标未接入。

使用同一项目与可追溯资源，完整范围包括：

1. 房间主池与线程 A 同屏，两个独立草稿。
2. 主池普通消息附件预览，无任务归属。
3. 线程 A 与 Markdown 成果并排，包含来源和版本。
4. 同一文件保持打开，左侧切到线程 B，引用目标清晰。
5. 房间文件集合与预览，再切回对话池。
6. 项目文件树与当前文件预览，以及固定两版本 diff。
7. 多标签、同名不同路径、v3/v4 同时存在。
8. 窄窗口对话/文件切换和预览最大化后的还原。

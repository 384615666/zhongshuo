# R117：用户确认后的完整文件交付与同AI多问题接续

用户要求修复V59独立复核发现的两处问题。本轮保留现有输入界面，补齐持久化来源和派发校验，使用gpt-6.1-sol/medium子代理处理答复路由，主代理实现文件链并独立验证合并成果。

## 文件交付

原实现提问后提前结束当前执行轮，用户答复后的正式交付只引用新执行轮的改动集，导致提问前完成的文件不进入后续文件版本校验。

- 提问时将当前改动集和此前尚未正式交付的提问成果引用写入持久化事件。答复后接续同一任务，正式交付包含完整来源。
- 按实际执行顺序合并同一路径：保留未再修改的成果，后续合法修改、删除和重建使用最终版本；中间前像与已冻结版本不一致时拒绝继续。
- 答复派发前和异步建立会话后均核对已保留文件，确认期间的外部改动不被当成本次合法成果。
- V59未保存新引用时，从原提问执行轮的基线事件恢复；若提问来自格式补交，通过持久化修复工作项追溯原始写文件轮，不依赖已清理的临时键。
- 后续正式交付会结束这段部分成果链，不将全部历史改动集无差别加入新任务。旧停止代次、失败或不确定执行不能自动成为新的成功成果。

## 同一AI多个问题

原实现仅按AI成员筛选等待步骤，同一AI的两个问题无法通过@区分，用户被反复要求@同一个成员。

- 同一AI下按已落库的提问顺序逐条接续，排除已经排队、执行中或结果未知的答复；连续发送两条答复分别绑定两个原子任务。
- 多位AI同时等待时沿用已有@选择成员。现有协议的显式引用可以指定问题，其他线程或已解决、已更新的问题不能重放。
- 将问题事件、原消息、成员、执行轮及任务身份冻结到答复信封，在准备、提交和模型启动前复核；停止、成员或权限变化沿用原保护。
- 不根据正文关键字猜测问题，不新增按钮、输入设置或界面提示区。通用操作手册同步说明同一AI下的逐条答复方式。

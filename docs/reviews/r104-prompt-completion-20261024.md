## 最终行为

- 常驻 zs-standing-v0.1.5、私信 zs-dm-standing-v0.1.3、每轮 zs-turn-v0.1.6。无实际工作时不执行工具或生成文档；短任务不另发接单计划。每轮 JSON 是内部终态，不要求额外可见确认。
- TaskComplete 增加兼容旧存储的 replyDisposition=reply/none；新模型传输字段必填。none 只允许无待办的普通交流、空回答、空文档及数组；有实际工具或项目变更时拒绝静默，按既有有限格式修复路径保留执行事实。
- IND completion 明确 continue/conversation/direct_answer/no_reply。所有预期成员真实提交、无工具/文件变化、无文档/建议/未决问题后才能提前收尾；简单答案必须保留可核对的显式结论并比较其内容、类型和证据身份；相反答案继续互评。普通交流没有工作 delivery，不替换旧成果/验收版本，不伪造全员 RAT。
- 只有寒暄回应与静默回应的差别不制造 claims；由主持者提交的自然答复/静默语义收口。缺席、UNKNOWN、实质分歧、待办或实际执行均不能套用成功短路；需要继续时，已暂缓的独立消息恢复显示。
- 新版 CR 每项冻结他人 claim 恰好一次，不能只审一项便当完成。纯 agree/ready 且 summary 为空时不再展示确认泡泡；完整结构化意见保留在成果/审计。主持者成功 RAT 总览只在最终发布显示一次。
- 若只有空 claims 的社交稿，但存在实际执行/未核实文件状态，或指定席位失败/缺席，运行明确 PARTIAL、任务 BLOCKED，保留来源和原因；不会将空稿送进 SYN 强迫生成业务结论。两个回退用例均验证至终态、无新交付且无后续可领步骤。
- SYN 请求 skip_if_unchanged 只有在首版、完整冻结互评全 agree、原结论及主持总览完全未变、无文档、建议、争议、不确定性、工具/文件活动或历史返工确认时生效。其他情况保持必要 RAT。未产生的确认记录仍为空，不写成全员确认。
- AUTO 附注不再要求所有工作必须分派实施和独立评审；单人可完成时直接完成。计划/交接与已经实施的同一路径修改互斥，避免重复实施。规划 JSON 示例明确 coordinationPlan:null。

## 四项反馈

1. **输入栏右键**：在正式 Electron 主窗口注册原生编辑菜单，提供全选、复制、剪切、粘贴。依据 Chromium 当前目标的 `isEditable`、`editFlags`、选区与密码字段状态启用；绑定源 window/frame，不操作其他窗口的选区。使用 Electron 原生 roles，保留既有图片粘贴事件链，不通过新增 renderer 接口读写剪贴板。
2. **并行只有两位**：上一轮只补了写入互斥策略，执行准入的每项目和同渠道默认值仍为 2。本轮默认全局/每项目/同渠道均为 4；新增 **设置 → AI 设置 → 同时运行的 AI**，三项上限可独立设置为 1–32。正式 IPC `app.executionConcurrency.get/set`，完整值一次保存，revision/CAS、同号幂等、远程禁止修改，设置保存在本数据根。默认 worker 在准入时读取设置，变更时重新检查排队项；调低不取消或释放在途/UNKNOWN 占位，成员会话、依赖、真实完整权限、写入租约与保护检查继续生效。环境值仅在未保存时作为回退。手动注入的 admission 保留测试指定限制。
3. **私信中的原界面**：去掉私信菜单的过渡入口，保留重命名、归档、三种导出、任务记录等真实动作。房间/线程旧组件的按钮改走当前正式房间及任务分组路由。恢复面板的未完成撤销直接接已有 `changeset.undo`，仅显式点击提交，显示成功、冲突、失败结果；不再要求用户去旧页面。真正启动/渲染故障 fallback 保留，未删除数据或恢复能力。
4. **文件选区评论**：房间文件页原按钮打开的是没有保存动作的演示弹窗，含示例代码和未实现的位置清单；已删除弹窗及附件卡上的同类假评论按钮。当前新版真实可用的是消息附件预览 **⋯ → 评论此文件**：通过 `message.submit(record_only)` 保存留言和附件引用到来源房间/线程/私信，显示为普通消息及附件卡，不触发模型。daemon 的文本行号定位 `attachment.comment.add/list` 仍存在，但当前新界面没有创建和显示入口，不能宣称新版支持选区定位批注。手册与可见说明已按文件级留言修正。

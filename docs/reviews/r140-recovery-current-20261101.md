# R140：恢复检查不再重复提醒已解决的中断

用户反馈恢复检查的“查看中断任务”仍指向此前中断、后来已修复完成的任务。截图背后的当前任务已经 DONE，最新运行 SUCCEEDED，恢复检查却仍按旧 INTERRUPTED 记录提示。

## 原因与修改

原 `recovery.status` 直接返回 `workflow_runs` 中全部 INTERRUPTED 行，没有核对所属任务当前状态及更新的运行。恢复面板和侧栏注意标记都消费这个结果，因此旧运行历史被误当成当前待处理事项。

查询现仅返回每个任务最新一次仍为 INTERRUPTED、且任务尚未 DONE/CANCELLED 的运行。同一任务最多一个提醒；新的运行无论已成功、正在进行或失败，都不再让旧中断冒充当前状态。历史运行保留，仍可在原任务查看。

UNKNOWN 结果、保留的文件保护、未完成撤销与派发门禁继续独立查询；完成任务中尚未核实的执行事实不会被这个过滤掩盖。查询使用现有按 task_id 的索引，不新增 schema、不修改或清理旧记录、不自动恢复执行。

本机原库只读查询确认仅有一条历史中断，所属任务已 DONE 并有更新的 SUCCEEDED 运行。用新实现的正式 `recovery.status` 在 SQLite `readonly + query_only` 下读取，`interruptedRuns=[]`，其余 UNKNOWN、保护、撤销为空且门禁未持有；没有改写原数据。

## 验证

已有恢复、服务端进程证据、保护释放、旧保护兼容、任务结束、结果一致性与界面文案共 7 文件 124 项通过。双 TypeScript 检查与 UI/离线手册构建通过。变更的 `commands.ts` ESLint 与原 HEAD 均 10 项既有问题，无新增。

新增 16 项正式 `recovery.status` 回归通过：同任务的最新运行选择、旧中断后成功/运行中/失败、DONE/CANCELLED、真实 ACTIVE/BLOCKED 中断、重复读取及同号命令、落盘重开只读无写入；完成任务的 UNKNOWN/保留保护/未完成撤销/门禁仍独立返回。

其余回归和交付完成后回填。MCP/Skill 实际调用测试按用户要求延期，本轮不调用真实模型。

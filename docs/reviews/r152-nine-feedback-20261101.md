## 九项处理

1. **关闭窗口**：Windows 的 X 隐藏主窗口，不停止 daemon；最小化按钮仍按原生方式工作。再次运行同一数据入口恢复现有窗口。
2. **系统托盘**：使用实际 Electron/Win32 Tray，保留正式 logo 与引用；提供打开众说、设置、操作手册、打开数据目录、退出众说。退出共用停机屏障，等待 daemon 退出和 stdio 排空后销毁托盘；关闭按钮不触发停机。托盘创建失败时保留任务栏入口并显示错误。没有增加 renderer 退出权限，不停止其他实例的 daemon。托盘是否折叠由 Windows 管理。
3. **Harness 模型清单**：截图中的即时失败未原样复现，检查时旧组件也能返回模型；确认并修复了两处不稳定因素：自有 profile 依赖历史交付目录的临时归档，以及 native 30 秒查询早于 pipe 15 秒/renderer 20 秒超时。组件 0.1.3 的归档改放 DSH 自有持久目录；metadata 专用等待为 native 30 秒、pipe 40 秒、renderer 45 秒，普通命令保持原时限。错误态不再一直显示“正在读取”。指导文案改为 `zhongshuo` profile 配模，说明 web 配置独立。实际组件已定向更新，21 份既有配置哈希未变。
4. **先分工再实施**：规划提示要求先提交计划，协调者自己的实施工作也列为子步骤；各独立就绪步骤一起入队，协调者自己的实施步骤排在其他成员后。保留真实依赖及准入/写入额度。删除 handoff 的人工串行依赖。Claude 规划用只读工具且禁 MCP，Codex 用 readOnly/无网络，Harness 与 Pi 规划为独立零工具会话；Codex MCP 未机械禁用，不宣称四渠道都完全零工具。
5. **生成文档交接**：从通过 hash/目录校验的托管原件，在有界解析进程重建 Word/Excel/PPT/PDF 缓存，然后重新组装和 CAS 保存。异步前后核对原件、版本、附件范围及缓存，仍拒绝损坏、变化、越界文件；不以路径冒充已读。缓存已齐全时保留同步路径，不改变原有 worker 启动时序。
6. **文件修改并发入口**：项目设置 → 文件修改 → 同时修改文件的任务，提供“跨对话串并行（默认）”“单写者”“允许成员并行”。migration 061 的 nullable override 保留既有默认语义。新设置有 revision/CAS、幂等回执及审计，仅本机可修改；有运行、UNKNOWN、保留保护或重叠未释放租约时拒绝更改。并行仅限同项目/精确同根/实际完整权限，不同成员可在同串并行；同成员、受限写入仍串行。恢复读取实际取得租约时的策略，旧租约/UNKNOWN/过期租约保持独占保护。界面撤掉不真实的固定单写者说明。
7. **深色顶部栏**：修复 legacy 标题栏白色背景在实际 hifi 宿主中的 CSS 优先级，文字和窗口按钮随主题显示。
8. **图片提示**：去掉图片会随消息发送、仅记录等常驻成功提示；实际不支持、错误和发送限制保留。
9. **设置布局**：操作手册与其他设置页共用稳定宽度和导航位置；覆盖普通宽度及 3440 宽屏，长错误文案不撑破页面。手册补充两个实际深色界面截图及上述操作路径。

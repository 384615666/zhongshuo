## 行为与边界

**2：归档。** 房间检查仍限定本房间 room_task，补入 OPEN，不改成自动停止。项目归档/移除补入 OPEN，继续覆盖项目内所有任务种类，包括无 room_id 的 dm_turn。DIRECT 与显式 `collaboration:'deliberate'` 的 OPEN 请求均拒绝三个生命周期入口，并核对队列/项目/房间未被修改；DM 待执行任务阻止项目归档/移除，但不阻止无关房间归档。另有其他房间 OPEN、已完成任务和恢复/移除正例。

A05 使用正式命令、worker 与 Fake 写文件：没有任何 turn 开始时任务为 OPEN，归档返回 WORKER_STILL_RUNNING；拒绝后原发送回执仍可重放，排队工作只执行一次。完成后再归档成功，原发送回执被 CONVERSATION_UNAVAILABLE 拒绝。原有文件写入断言仍保留；该文件写入发生在归档被拒、房间仍可工作的情况下。

**13：停止。** 不同 commandId、相同 expectedStopGeneration 的重复停止，以及刷新后对同一 STOPPING 运行的再次停止，都只形成一次 STOPPING 状态事件和一次代次推进。中断回调可以再次请求同一在途 turn，沿用 worker 自己的有界确认/UNKNOWN 保护。首次停止不取消后继明确建立的新运行；绑定旧 run 的请求保持原目标结果，新明确停止后继 run 才推进下一代。

补测发现旧 stopping 回执重放还会按 parent_task_id 中断后继运行的 STOPPING 子任务。已先实测红灯（收到 `turn-new-child` 的错误中断），再在专属 stopFlow 限制：只有目标仍是任务最新运行，才允许其子任务中断范围。直属 turn 仍严格绑定 targetRunId。测试亦覆盖未终态旧 run 被后继取代，以及后继/旧 run 同 revision=0、UUID 字典顺序与创建顺序相反；revision 是可变状态版本而非运行序号，使用与任务历史一致的 rowid 创建顺序。

UNKNOWN 与保护回归保留：A09 核对 UNKNOWN turn 的准入、物理写租约、无 protectionReleased 事件和其他项目进展；R99 停止超时仍 UNKNOWN、占位保留，重复停止不延长确认窗口。协作子任务、DM 归档停止、自动恢复等待/队列及重启相关回归均通过。

**14：错误。** StopCommandError 沿用 DaemonCommandError 标准身份，使 runCommand 事务内校验与 commands 外层识别都保留业务错误。A01 跨方法同 commandId 冲突实际返回 IDEMPOTENCY_CONFLICT，原任务不被停止；新增未来代次 STALE_REVISION、回执已清理 RESULT_EXPIRED 验证。真实 SQLite trigger 用 RAISE(ABORT) 制造停止写入失败，命令返回 STORAGE_UNAVAILABLE、不带私有诊断，代次/run/回执全部回滚；移除 trigger 后同 commandId 可成功重试。中断回调故障则返回失败、保留已经提交的 STOPPING，不伪称成功或释放保护。

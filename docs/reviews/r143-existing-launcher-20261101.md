# R143：V78 沿用数据启动器修复

用户双击 V78 的 `start-existing-data.vbs` 没有打开应用。该入口一直复制 R106 的 BAT：直接读取旧目录的 `pipe-name.txt`，缺失时仍拼出 `\\.\pipe\`，随后 `start` 后无条件返回 0。VBS 隐藏控制台，失败无提示。本机原目录确有数据库但缺此连接标记，Windows `net.listen` 对空管道直接返回 `EACCES`。此前包验证直接启动 Electron，仅比对了遗留启动器字节，未覆盖用户实际入口。

## 修复

- `scripts/install-existing-data-launcher.mjs` 接受新包目录与既有数据绝对路径，生成明确配置及入口。拒绝替换已绑定的其他数据目录，不自动猜测位置。
- 随包 Node 运行 `existing-data-launcher.mjs`：先核对既有 SQLite 文件头；连接标记缺失用独占创建生成并持久化，已有合法标记不改。空标记、无效库、路径缺失直接失败，不回落空库。
- 清理继承的 `ZS_*` 覆盖和 Electron Node 模式，保留对应 CLI 自身配置。只放行现有文档化的调试端口与显示验证参数。
- 记录 `startup-existing-data.log`；VBS 等待结果，非零失败显示日志位置，控制台宿主输出原因。即使 Electron 返回 0，若本次从未成功连接 daemon，仍按失败报告。
- 修复用户指定 V78 目录的原入口并同步原 ZIP。Electron/daemon/UI/BUILD 未修改，无需替换整套程序或搬迁数据。

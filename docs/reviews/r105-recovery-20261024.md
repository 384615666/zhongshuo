## 产品修复

- 允许真实修改后交给同伴 review/ask/reply。规划回合同时保存自己的真实交付，再等待后继步骤。静默丢失修改和写完后重新派发同一实施计划仍被拦截；只读修复也检查来源文件变化。
- Claude 配置指纹 v2 规范化 JSON，精确排除已核实的 CLI 统计字段。模型、渠道、权限、hooks/MCP、信任状态及未知配置继续受保护。旧快照按精确 v1 当前算法比较，新快照明确版本；不拿新旧算法 hash 直接比较，不自动迁移旧授权。Codex TOML 指纹未放宽。
- `automaticRecovery.ts` 使用持久恢复账本，绑定原 task/run/turn、停止代次、冻结写入范围、逻辑输出与次数。同一 workflow run 新建 attempt，保留旧失败事实。生产入口启用；独立嵌入 worker 可显式选择恢复策略。
- 明确的临时网络、限流、上游故障最多额外 **2 次**，退避 2 秒、8 秒，重启不重置。尊重有界 Retry-After；服务端要求超过 5 分钟时停止自动重发，不缩短等待要求。
- 真实渠道必须提供准确映射的 provider terminal 证据。进程/传输关闭、中间内部重试通知不构成新业务重播许可。认证、余额、取消、真实权限/配置变化不循环重试。
- 任意实际工具 started/completed 或真实文件变化，均阻止完整业务重跑。只有同 turn、同 toolCallId 明确属于 StructuredOutput 的事件可豁免。UNKNOWN、retained 和未释放租约继续保护执行。
- 输出合同失败最多进行一次受限只读补交，沿用源 resultKey、完整输出和真实文件证据；与额外尝试总上限共享。保留经过正式 handoff validator 验证、当前仍有效的 ask/review/reply；非法回复目标等允许纠正或移除。
- 已正式对账/释放的历史 UNKNOWN 保留原状态，但不阻断后继成功结果；明确继续原子步骤时，受控恢复其原协调并保留冻结范围。未核实 UNKNOWN 仍拒绝继续。
- 等待与已排队但未启动的 DIRECT/DM 恢复可立即停止，正式收口任务与 run，不遗留 STOPPING。恢复成功精确重绑原失败请求及 blocked 交接，清除其旧失败呈现。
- 详情投影显示额外次数、等待时间和具体原因；outputInvalid 的 issues 可读。新增“补交已有结果”入口，明确使用当前成员快照、只读补交，并审计该次显式意图。
- `task.settleSupersededSteps` 仅接受同一父任务当前最新、成功且有正式当前交付的已完成运行，关闭无在途/无保护的旧失败步骤。旧步骤记 CANCELLED/后续接续，原 FAILED turn/run 不改成成功。

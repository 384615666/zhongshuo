# R128：结束未完成任务、房间标记与阅读交互

本轮处理用户新增的四项截图反馈。源码、测试与打包在 `D:/zhongshuo-public` 进行；原运行数据库仅用于只读核验，没有重新执行用户任务或搬迁运行数据。

## 原因与最终行为

| 反馈 | 核验与修改 |
| --- | --- |
| 执行失败后无法停止、消除未完成或继续 | 现场存在 BLOCKED 配 FAILED/PARTIAL、WAITING_USER 配 SUCCEEDED 和没有 run 的准备失败，均无活动执行。旧 `task.stop` 只停止活动 run，对终态返回 already_stopped，不结束任务；详情重试还排除了普通 BLOCKED 与 PARTIAL/INTERRUPTED。现在状态栏提供独立“结束任务”，安全结束整棵未完成任务树，清除排队工作和未完成标识；普通失败、中断、部分完成可从原串“继续任务”。原消息、文件、失败运行和审计记录保留。 |
| 房间前面的圆圈和三角改蓝 | 截图中的空心标记实际为 BLOCKED 八角形。该标记和 ACTIVE 静态三角均使用主题强调色，待答复/待验收继续使用原有形状和语义；没有未完成任务时保留空位。 |
| 最新消息不折叠 | 按当前视图实际渲染顺序，最后一条有可读正文的 AI 消息完整展开。后续系统通知、空消息或用户补充不抢占这一位置；房间回复串、私信和独立串页均接通。较早长回复仍可展开阅读。 |
| 引用气泡直接删除 | 数量气泡末尾常显 ×，直接清除当前草稿的全部对话引用；来源/摘要继续只在悬停或键盘聚焦时显示浮窗，浮窗仍支持逐条移除。删除不发送消息、不打开浮窗，正文、附件与原消息保留。 |

结束动作使用任务版本、停止代次与最新 run 身份绑定，提交时在事务内重新检查。任务树中仍有非终态运行或执行、已领取队列、未释放租约、保留保护或未核实 UNKNOWN 时拒绝结束。不会借结束操作释放文件保护。已安全结束的待回复汇总可按真实运行/执行身份核实；`source_turn_id` 只代表上次答复，不作为本次执行已安全结束的证据。安全待执行工作取消后不会被恢复/提醒重新派发。

继续动作复用正式 `task.redispatch`，保留最新来源、版本、停止代次和准备期间重查，支持 FAILED/PARTIAL/INTERRUPTED；现有格式补交和已明确澄清后继续的规则保留。恢复检查补齐 PENDING、DISPATCHING、WAITING_INPUT、WAITING_APPROVAL 等在途状态，避免终态 run 下仍在工作的执行被绕过。

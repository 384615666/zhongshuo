# R129：房间切换、侧栏列表与权限说明

本轮处理用户五项反馈：权限未刷新提示、房间无法切换、旧深色新消息按钮、房间似乎消失，以及推送前几版的本地提交。源码与打包均在公开克隆进行。

## 原因与修复

| 反馈 | 已证原因与改动 |
| --- | --- |
| “权限暂未刷新” | 这是输入框的后台权限说明查询失败后的常驻提示，并不证明用户改过权限。可复现触发条件包括线程会话身份尚未装载时提交空 conversationId，及展示字段/任务 revision 刷新导致有效读取不断取消。现在身份完整后才读取，保留有效在途读取并合并后续刷新；移除输入区常驻警告，真实查询错误在已有运行设置菜单查看。发送/派发的正式授权检查未改。现场截图缺少具体错误回包，不能断言它一定命中了空会话窗口。 |
| 进入房间后有时无法切换 | 同项目房间点击也先等 room.list，慢查询会挡住切换。另顶栏/欢迎页等待项目读取后才导航，迟到回调可能把用户拉回旧目标。现在已载同项目房间同步导航；项目点击同步交接 URL，迟到读取不得再次导航，项目刷新增加代次与最终归属检查。 |
| 新消息按钮仍是旧深色 | 正式样式中 `.new-msg-pill` 仍用深蓝绿渐变和白字。现改用与选中房间/串、发送按钮相同的浅渐变、主题面和强调色文字，深浅主题均验证。审计发送按钮、页签、文件行、详情 chip、图标按钮等后，没有其他同类操作按钮使用旧深渐变；品牌标识、图表、头像与危险/警告语义保留。 |
| claude-zh-cn 等房间消失 | 原数据库只读确认默认房间存在且未归档，当前窗口辅助功能树却显示“暂无房间”。旧侧栏从 activeProjectId 和活动 rooms 投影推导缓存，焦点先变、房间后读时把新项目缓存为空。现在侧栏使用独立按项目索引，只接收该项目真实 room.list 回包；读取失败保留旧列表并提供重试，迟到旧回包不能覆盖较新的列表，活动成员名单不参与缓存推导。 |
| 前几版一起推送 | 开始时 HEAD 比 origin/main 领先14个本地提交、没有分叉。前几版已本地提交，尚未推送。先完成本轮构建验证，再统一推送公开仓库 main；不引入旧私有仓库历史或运行数据。 |

刷新后新建、改名与归档通过同一项目索引更新；切换其他项目不会清除已展开项目的房间。各房间草稿继续按原目标保存。后台权限查询只是说明，不能授予实际文件权限，也不会把查询失败当成授权成功。

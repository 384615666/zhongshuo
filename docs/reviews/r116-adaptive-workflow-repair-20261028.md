# R116：连续返工、用户确认和内部限制修复

用户要求尽量避免任务因固定规则受阻，需要确认时提出具体问题，并审查同类限制。此次从 [现场根因调查](r116-delivery-rootcause-20261028.md) 继续实施；不重放现场业务，不改用户数据库或项目文件。

## 修复后的行为

- 研讨收到具体内部修改要求后，可以继续生成第三版及后续版本。每一版冻结自己的反馈和确认矩阵，旧反对票不覆盖新版本；重启数据库和重复推进不重复排队。
- 从第三轮讨论起，由主持者逐轮核对是否有新证据值得继续；第四轮不再强制结束。检查点确实失败时转入已有材料的整合，不在已结束的检查点上永久等待。
- 预算不足、缺少复核成员，或两版内容与反馈完全相同且没有新的工具/文件变化证据时，提出具体问题并进入等待确认，保留成果。不会直接使用过时的“全部完成”摘要，也不会伪造完成。
- 普通工作与协作步骤可以通过结构化 `userQuestion` 提问。问题显示在原对话，已有文件与执行记录保留。执行已经结束并释放保护时，其他无依赖步骤继续；有依赖的步骤等待答复。
- 原串只有一个步骤等待时，用户直接回复就绑定原子任务；多个成员等待时用已有 @ 指定答复对象，歧义保留输入并要求明确对象。答复包括原任务、成员、消息、权限快照和停止代次校验，不另造一个重复子任务。
- 整合阶段也能提出问题，并在用户回复后继续原协作整合。当前待确认事件用于状态展示，已解决的旧提问不会继续覆盖新的完成状态。
- 没有在途执行、排队请求或未释放写入保护的待确认协作，重启保持等待答复。存在 UNKNOWN、保留租约或用户停止时仍执行原有保护。

## 限制审查与处置

| 检查点 | 原行为 | 本轮处置 |
| --- | --- | --- |
| 整合返工次数 | 仅第一版可返工一次 | 移除次数门槛，逐版继续；预算与真实停止事实有效 |
| 分歧讨论轮数 | 第三轮选择继续后，第四轮仍强制收尾 | 第三轮起每轮检查新证据，按实际判断继续或整合 |
| 成员等待用户 | 一名成员 WAITING_USER 使全体协作 BLOCKED | 保留原协作，独立步骤继续；问题明确显示并可原串答复 |
| 待确认时重启 | 无执行的父 WAITING 也变 INTERRUPTED | 仅在无执行/队列/保留保护的可证明条件下保留等待状态 |
| 协作调用次数 | 用户设置较大值仍被 24 次截断 | 使用冻结的用户预算；明确传入的工程测试上限保留，缺省24仅是默认值 |
| 服务端 Retry-After | 要求等待超过5分钟则直接停止 | 持久化实际等待时刻，重启后不提前发送；不占用模型执行位置 |
| 累计计划步数 | 每次8步上限被用于整个累计计划；读取也只取8步 | 单次提案继续有限，累计交接独立验证；读取完整累计步骤 |
| 修改后的后继工作 | 本轮只要修改过文件，就拒绝所有后续实施交接 | 具体后继步骤读取本次真实交付并建立依赖；保留重复交接及无依赖覆盖保护 |
| 角色标签 | 评审/接收角色一律不能交接实施 | 根据接收成员实际冻结写权限判断；只读或未授权仍拒绝 |
| 房间候选人数 | 超过12个候选使单人请求也失败 | 完整读取获准候选；单次显式选择人数与候选总数分开 |
| 文件交接 | 超过100个文件、32MiB总字节或12层嵌套即失败 | 全量文件清单、64KiB分块hash和迭代遍历；保留路径/物理身份/版本核验 |
| 消息交接累计读取 | 截取32条或超过32条拒绝 | 完整读取正式累计交接，不丢最后的纠正意见 |
| 最新交付正文 | 失败/待确认仍复用整合前摘要 | 显示当前问题；旧摘要保留在原产物供追溯 |
| 状态投影 | 历史提问可能覆盖新执行；PARTIAL重复显示失败提示 | 提问绑定最新运行及实际待确认任务，待确认不再显示通用失败横条 |

保留的限制有明确用途：单次提案8步、单次交接4条、单次显式名单12位用于约束一条输入的规模，并不限制任务累计推进；重复相同交接、环状依赖和不存在的来源仍拒绝；实际写权限、文件版本和进程退出证据仍需成立。传输失败额外自动重试2次、同一无效结果只读补交1次仍保留，防止反复重放已有副作用；这些真实失败继续提供具体原因及原任务继续入口。预览/压缩包大小、上下文摘录和文件扫描上限属于资源或完整性保护，没有当成交付完成的依据。

本轮审查覆盖调度、研讨、协作交接、调用预算、自动恢复、停止、对话答复和状态投影；不声称所有输入或外部服务异常都不可能等待或失败。

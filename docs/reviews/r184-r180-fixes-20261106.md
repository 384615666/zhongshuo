# R184：R180 建议核实与修复（2026-11-06）

用户要求核实 DeepSeek 整理的 R180 修复建议并修复。基线为公开仓库 `92dbb9b` / beta.28；本轮候选版本为 `0.1.3-beta.29`，数据库 schema 保持 61。全部修改、构建和隔离验证在公开源码目录进行。

## 核实结论

清单中的主要可靠性问题确实存在，包括崩溃后协调状态占位、停止后继续按钮被误拒、Claude 畸形字段异常、图片校验失败的启动分类、提醒相互阻塞、归档房间仍触发提醒、空数据库被初始化、超过 50 个项目后的去重、草稿清理复活和非法文件名落盘。

部分描述已经落后于当前源码，不能再作为当前缺陷直接照修：

- **第 12 项已修复**：当前 `jobManager.stdoutDrained/stderrDrained` 使用不消费数据的 `peekPipeBytes`，并非报告所述的消费式 `ReadFile`。本轮保留该实现，通过真实 Windows 管道的大输出、背压、UTF-8 边界与适配器回归复核。
- **PDF/PPT 已有按需显示**：PDF 是单页画布，PPT 真实缩略图已有 IntersectionObserver 门控，演示文稿也使用 lazySlides。补充优化集中在表格回退网格、重复字节解码、页面资源释放和缓存预算。
- **同名 @ 的底层路由已修复**：已有稳定 token 和 memberId 绑定，本轮补齐候选列表的可区分显示。

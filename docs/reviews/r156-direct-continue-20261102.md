# R156 中断任务直接继续

2026-11-02，基于 `114c018`，独立工作树 `codex/r156-direct-continue`。用户明确取消 R155 的“检查中断、填写依据、解除保护、重启 Windows”前置流程，要求直接继续任务。本轮按该决定更新行为，安装器仍保持先从托盘退出再安装。

## 结果

- 原任务横幅、私信中断项和恢复任务列表提供 **继续任务**，没有依据表单、退出证据检查或 Windows 重启要求。启动只保留侧栏提醒，不自动弹窗遮挡输入。
- `task.continue` 及用户非格式修复的 `task.redispatch` 在同一事务内处理本任务和协作子任务的旧中断：保留 UNKNOWN 业务历史，自动补记尚未结算的预算、释放旧占用并入队后续工作。已 settled/refunded 不再次处置；拒绝或过时请求回滚整个操作。
- 原串直接发送跟进消息同样处理旧中断，不必先按按钮。只记录消息不触发恢复；提交失败保留原中断状态和草稿。
- 旧执行关联的排队条目完成并推进代次，不能再被当作新工作领取。旧执行迟到结果只记历史，不再次结算、生成交付或覆盖新结果。继续后的旧中断不再反复出现在恢复提醒里。
- 如果已经排队的新任务被另一项旧中断占用，点击继续处理实际阻塞项并沿用现有队列，不重跑旧任务或重复新派发。

当前真实执行仍沿正常排队规则运行；保留已有聊天、文件和历史，不将未知结果改记为成功。旧取证 API 为历史兼容保留，普通继续入口不依赖它们。原用户数据库未修改，本轮未调用真实模型、重放原任务或重启 Windows。

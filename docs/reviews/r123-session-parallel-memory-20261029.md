# R123：角色跨串并行、消息归属与共享笔记

用户确认实施 R122 建议：先修消息串线和排队扫描，再开放同一 AI 在不同串中的并行，最后由程序合并共同记忆。本轮使用多个 `gpt-6.1-sol` 子代理分工，主代理完成执行接线、复核与整体验证；当前子代理接口未提供 `deepseek-flash`。

## 用户行为

- 同一 AI 在不同对话串拥有独立执行范围，可同时处理多个请求；同串追问仍依次处理，停止只绑定目标任务。总执行数、项目和渠道的资源上限继续生效。
- 同一实际工作目录的写入仍串行，父子目录及目录别名沿用物理租约检查。本轮没有开放多个 AI 同时覆盖一个工作区；只读请求和不同工作目录可以并行。
- AI 可在最终结果中明确提交适合复用的笔记。程序只合并新增内容，不把聊天记录整份复制成共同记忆。同项目、同角色、同一房间的不同串共享；其他房间、其他角色与私信各自隔离。
- 同一事项的不同值都会保留，带真实来源并标出冲突，后续执行先核查；不让后到的会话直接覆盖旧值。笔记是资料，不构成新指令、权限或当前文件事实。

## 实现

### 调度与文件准备

准入增加可选 `executionScopeKey`，worker 按项目、会话、对话串和真实成员生成；没有该字段的旧调用仍按成员互斥。输入包保存相同的冻结 key，重启只在其与持久执行身份一致时按细分范围恢复；旧记录没有 key 时继续按成员保守占位，key 不匹配拒绝启动。UNKNOWN、retained 保护和已有目录写锁不因并行改动而解除。

DIRECT 调整为取得准入后，用事务建立执行身份和物理写入租约，再捕获文件基线、组装输入及启动模型。等待者不再扫描、保存快照。准备阶段失败可能保留一条明确“未启动模型”的失败记录；恢复检查只接纳无模型调用、无执行起点、无会话/进程且有 confirmed-not-started 证据的准备记录。缺失根消息/串的廉价检查仍在建执行记录前拒绝。

所有启动早退均清理自身占位。已经释放的占位不重复清理，以免把刚登记的写锁等待标记清掉、造成父子项目循环抢占。实际父子目录队列验证 drain 能让出执行，不会在同步循环里饿死持有者。

### 消息归属

Codex 通知要求 thread/turn 身份完整且唯一，不再默认归入第一个 session。合法的早到 turn/started 仍能绑定待启动轮次，普通消息、工具和未知终态不猜归属。旧执行进程的输出和退出广播只作用于自身代次。worker 另加一层普通事件的轮次归属检查。

### 共享笔记

新增可追加迁移 060：记忆范围、增量提交和带来源的值。每次输入从一致性读事务取得范围与版本，保存到正式输入包；模型通过可选业务字段 `memoryUpdates:[{key,text}]` 提交增量，传输 schema 为无更新时的空数组提供明确合同。旧结果继续兼容。

合并事务验证项目/成员/会话归属、成功终态、停止与保护状态，以及正式输入包的原版本。旧版本增量可并存，未来版本与伪造范围拒绝。同 turn 的同载荷重试幂等，不同载荷拒绝。相同文字保留各轮来源，不同文字标记冲突，均不覆盖其他执行的内容。

终态处理前持久保存待合并增量，成功后合并并删除待处理项；中途存储失败时，重启依据成功执行事实补做一次，不调用模型或重放工具。无效、失败、取消和未确认的执行不提升为共同记忆。持久化事件失败时，仍未收口的轮次转 UNKNOWN 并保留执行占位。

更新备份/导入的数据 schema 版本到 60；正式打开旧库仍先做迁移前一致性备份。旧授权、旧输入包和业务消息没有被重写，也未迁移本机原运行数据。

## 独立复核与故障补测

独立只读复核发现两项问题，并已修复复验：早期消息的笔记缓存优先于最终控制结果，可能保存已经撤回的笔记；笔记写库异常发生在成果快照之前，可能造成成功工作缺少附件。

现由终态与笔记共用同一控制结果选择逻辑，最终空数组、字段省略与替换都具有最终效力；只有自然正文终态能使用合法消息缓存，显式错误合同不回退。文件快照与私信后续调度先完成，再尝试记忆合并；临时存储失败保留待处理项，重开恰好一次合并，成果附件不丢也不重复。

新增四种输出变更回归；重启故障用例同时实际写入 out.txt，验证失败时附件字节、成功事实、租约释放与重启后恰好一次。独立复核另验证待处理项本身写入失败会收为 UNKNOWN 并保留准入。复验未发现其他必修项。

最终包身份在交付后补入。详细原件位于 ignored 的 `dist/r123-session-parallel/`，不包含用户原业务。

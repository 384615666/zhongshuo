# R119：固定上限复查与系统提示清理

## 5000 文件上限为什么会阻断任务

原实现用固定文件数控制快照扫描的开销，但把“扫描没有完成”直接提升成了“整件任务不允许开始”。扫描又覆盖了 Git 忽略的安装包和运行数据，正常源码项目很容易触发。5000 不是模型限制，也不是用户开启的调用预算。R118 已移除默认数量截断，并让 Git 项目遵循项目文件清单；真实读取失败和目录越界仍报告具体原因。

本轮继续从正式发送、运行配置准备、模型输出解析、协作编排、研讨阶段、文件处理及界面读取路径检查相似问题。

## 本轮修正的阻断条件

| 原条件 | 实际影响 | 现在的行为 | 关键实现 |
| --- | --- | --- | --- |
| 单份分工计划最多 8 步、每步最多 8 项依赖 | 正常复杂计划直接被判输出格式错误，即使预算关闭 | 按完整计划执行；保留成员授权、依赖存在性、重复和循环检查 | `contracts/coordination.ts` |
| 单次最多 4 条成员交接 | 第 5 条有效交接导致整个结果不被接收 | 接收完整交接；保留收件人、权限及防循环检查 | `contracts/taskComplete.ts`、`daemon/coordinationMessages.ts` |
| 参与成员最多 12 人 | 正式命令中的运行配置准备仍有遗漏，可在执行前拒绝请求 | 运行准备、输入组装、规划、回复路径均按实际获准名单处理 | `daemon/commands.ts`、`coordination.ts`、`threadReplies.ts` |
| 任务目标/用户问题 8000 字、交接 7000 字、计划摘要 4000 字、步骤标题 160 字 | 内容稍长就被误当成格式错误 | 业务说明完整保留；结构、身份和非空要求保持 | 两份协作及完成结果合同 |
| 在途执行达到默认 20 分钟后被标为缺席 | AI 还在工作，却被屏障排除；全员无初稿时任务失败；预算关闭也会发生 | 耗时不能证明缺席。仍在运行的成员继续等待，完成后正常计入本阶段 | `daemon/deliberationRunner.ts` |
| Git 清单通过 `spawnSync` 的 64 MiB 输出缓冲收集 | 大型项目在模型启动前因清单读取失败受阻 | stdout/stderr 写入临时文件后完整读取，清理临时资源，不再用该缓冲限额判定项目规模 | `daemon/commandOutput.ts`、`preimage.ts` |

删除了已不适用的“成员无响应后继续”设置。项目设置保留原有的单轮最长运行时间；默认关闭，用户自行设置的时限仍会生效。旧配置字段兼容读取，但不会仅凭在途耗时改变成员席位。已确认失败、用户停止、执行结果待核对及旧记录的迟到处理保持原有职责。

## 仍存在的限制及其影响

下面不是“全部限制都已删除”的声明。资源容量、用户主动设置和展示窗口需要分别评估。

| 位置或用途 | 当前值 | 是否可能阻止正常工作 | 本轮处理 |
| --- | --- | --- | --- |
| 调用预算 | 单人默认建议 6 次，自动协作建议 24 次；研讨按人数计算 | 仅预算启用时限制调用；关闭时不按这些建议值结束任务 | 保留用户选项；核对关闭路径 |
| 单轮最长运行 | 默认不限制；用户可设 10 秒至 24 小时，0 关闭 | 主动启用时会中断执行；结果不确定进入核对 | 保留；不与 20 分钟观察值混淆 |
| 自动恢复 | 最多 2 次额外尝试；格式补交 1 次 | 已发生真实失败后停止自动重试，原任务仍可明确继续 | 保留有限自动重试，避免重复副作用 |
| 非 Git 显式扫描配置 | `ZS_PREIMAGE_MAX_FILES` 可覆盖默认完整扫描 | 工程环境自行配置时仍可导致基线不完整 | 不增加普通用户设置，报告实际原因 |
| 同时执行 | 全局 4、项目 2、渠道 2；同成员及同写入目录互斥 | 超额排队，不因人数或排队直接失败 | 保留调度；同 AI 跨房间上下文独立 |
| 生成文件转为聊天附件 | 每轮 12 文件、合计 64 MiB；文本单文件 5 MiB | 超额文件不能全部登记为附件；不直接把任务变为失败/阻塞 | 保留本轮范围，列为文件交付容量问题 |
| 快照可撤销内容 | 单文件默认 8 MiB | 超限仍记录 hash 和状态，但该文件的内容撤销不可用 | 保留，不能混称启动文件数限制 |
| 上传 | 文本/代码 256 KiB、图片 8 MiB、PDF 20 MiB、Office 32 MiB、CSV 5 MiB | 超限附件拒收；不等于已运行任务强制结束 | 保留资源边界 |
| 图片尺寸 | 单边 12000 px、4000 万像素 | 超限图片拒收 | 保留 |
| 文档解析 | PDF 200 页、幻灯片 200 页、Word 10000 段 | 超限文件可解析失败，影响该附件的预览/发送 | 保留；后续可按真实大文档场景改分批读取 |
| 解析进程 | 并发 1、等待 4、30 秒；V8 768 MiB、进程 896 MiB、结果 JSON 4 MiB | 忙时拒绝新解析、超时或内存不足会失败；会影响附件输入准备 | 保留资源隔离，不能放大成整项工作的默认时限 |
| Office 解包 | 1500 条目，单条目 128 MiB、总量 160 MiB | 超限文档解析拒绝 | 保留资源边界 |
| 托管附件完整读取 | 64 MiB | 异常或历史超大附件可能在输入准备时失败；普通上传上限低于它 | 保留完整性校验，明确不是 Git 输出限制 |
| 模型附件摘录 | 常规文本 64 KiB；文档提取总计 512 KiB；表格 40 工作表、每格 4096 B；CSV 最多 2000 行 | 模型不会自动获得附件所有内容；属于上下文窗口，不能称已读全文 | 保留原件与截断事实 |
| 模型会话历史 | 房间最近 200 条、私信最近 50 条 | 影响单次输入上下文，不会删除聊天或强制终止任务 | 保留，长任务需按保存的文件/成果接续 |
| 文件发现提示 | 最多 200 个路径 | 仅提示清单，不控制真实基线扫描 | 保留 |
| 文件修改详情 | 列表 100 文件，单文件文本 256 KiB | 仅详情窗口；不控制完整改动集或任务完成 | 保留截断标记 |
| Git 状态/差异 | 状态 200 项；差异 50 文件、每文件 64 KiB、总 512 KiB | 阅读窗口；不代表其余文件不存在 | 保留展示范围 |
| Git 操作输入 | 暂存请求 100 路径、冲突文本 64 KiB、提交输入 4 MiB | 超限操作会拒绝，不是模型任务执行上限 | 保留，归入独立 Git 操作容量 |
| 本地待确认操作记录 | 成员/Git 各最多 64 条、256 KiB | 堆积到容量时阻止新的配置/Git 写入；查询原操作仍可用 | 保留原记录，不清空、不换身份重新发送 |
| PPT 静态预览 | 60 页、JSON 12 MiB | 仅该预览通道受限 | 保留，不混称解析全部幻灯片上限 |
| 远程入口 | 导出 200 资源/256 MiB，WebSocket 单消息 64 KiB/200 订阅 | 影响该次远程请求，不是本地任务步数上限 | 保留入口资源限制 |

旧 `baseline.ts` 的 20000 文件/单文件 5 MiB/总 200 MiB未发现正式调用方；不能把它列为当前现场根因。可选排队等待截止未由生产入口传入；同样不能当成默认阻塞条件。

## 界面提示

用户常规页面只显示状态、具体原因和下一步。删除规则编号、工程轮次、原型施工说明、“不伪造/不冒充”、命令与事务实现备注；协议与原始事件仍可在已有诊断详情内核对。

| 原显示 | 现在显示 |
| --- | --- |
| 全员无有效输入（§6.1 INDEPENDENT 终结规则；不合成虚构研讨报告） | 所有 AI 都未返回有效结果；启动失败时优先显示实际原因 |
| 最近运行 · AUTO / INDEPENDENT | 最近运行 · 自动协作 / 独立分析 |
| 保存成功（revision 乐观锁通过，回读一致） | 已保存 |
| 已确认：经正式执行链派发（任务+预占，author=system） | 已确认执行 |
| 原信封未能耐久保存 | 发送记录无法保存，本次尚未发送 |
| 只读聚合（board.view）等施工说明 | 点击任务查看回复、补充要求或验收成果 |

当前界面和原界面共用系统提示转换；旧记录不用改数据库即可得到新显示。转换只作用于程序生成的状态/失败说明，用户原消息、AI 正文、业务问题与修改意见、文件、工具输出及原始诊断对象保持原文。

操作手册同步更新，使用隔离“读书会筹备”示例重新采集 19 张编号截图，不含个人交付路径或实际聊天资料。

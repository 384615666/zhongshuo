# R185：众说新建 Harness 会话不进入普通历史列表

用户发现众说的内部 Harness 会话大量出现在“未分组”，并明确选择“先只处理今后新建的会话”。本轮只改变新会话的存储位置，不整理、归档、删除或搬迁现有会话。

## 实现

- 众说启动新会话时传入进程专用的 `ZHONGSHUO_DSH_PRIVATE_SESSIONS=1`。连接组件 0.1.4 使用官方 JSONL 后端，日志写入 `<DSH_HOME>/connectors/zhongshuo/sessions`，投影缓存写入同级 `storages`；Harness 普通列表仍枚举原来的目录。
- 新会话 ID 使用 `zhongshuo-session-` 前缀。同 ID 跨进程续聊仍选择专用目录；旧 ID 显式选择原目录，保留旧上下文。缺失会话直接失败，不另建会话冒充续聊。凭据、模型、供应商、MCP 和技能配置的来源不变。
- 新会话握手要求组件声明 `privateSessions`；旧组件在发送模型请求前给出升级提示。原位置的旧会话可继续使用原组件。
- 本机官方桌面 Harness 已升级为 0.2.2-rc.1，原连接组件只声明支持 0.2.1-rc.5。0.1.4 精确支持这两个版本，安装脚本拒绝其他版本。新版将工具呈现移入执行器，工具禁用阶段使用作用于单一 agent 的空工具执行器并拒绝所有调用批次；旧版继续使用原生呈现、限制与单调拒绝守卫。
- Windows 候选安装包版本为 0.1.3-beta.30；连接组件升级仍由用户运行安装目录的 `runtime-tools/deepseek-harness/setup.cmd`。不自动安装组件或更新用户已安装的众说。

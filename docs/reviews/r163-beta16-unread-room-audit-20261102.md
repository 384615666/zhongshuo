# R163：beta.16 反馈修复与 beta.15/.16 代码审计

审计范围为 beta.14 程序提交 `22cc0f9` 至 beta.16 的 `994698c`，包括设置页、私信底色、安装器和 Windows 身份处理。未修改首页、README、旧私有历史或用户运行数据。

## 用户反馈修复

- Windows 通知来源：安装器和运行期均为本应用 AUMID 注册 `DisplayName=众说`、正式图标 `IconUri`；`app.setName` 在设置 AUMID 前执行。保留原通知激活 CLSID，首次通知实际显示后再检查系统晚建的旧入口。窗口任务栏属性与通知来源注册是不同机制，删除了 beta.16 中把缺失 relaunchCommand 直接断言为 ElectronApp 来源的注释。
- 私信行及侧栏私信入口只显示未读数，不叠加蓝点。固定 22×22 圆形，超过 99 显示 99+，无障碍标签保留实际数量。
- 未读按收到的正式消息计数，排除本人消息、系统消息和未结束输出，不再用消息序号差充当未读数量。
- 已读不依赖旧列表的 unread>0：当前会话、窗口前台可见、消息已渲染且贴底才提交真实服务端序号。上翻历史、隐藏、失焦、其他会话不推进；迟到历史和列表响应不能覆盖新历史或恢复已清除的数字。未知/失败回执不冒充已读。
- 折叠条件修正为展示项目的总数：房间与私信分别计算，超过 20 后各项目普通条目默认 5，每次更多 +10；总数恰为 20 时全显。折叠项目仍计入，置顶不重复计数，隐藏项目仅计其展示的置顶项；各组独立展开。归档私信使用归档总数。
- 房间标记来自 daemon 的实际执行投影，区分排队、运行、停止、等待协作、待输入/验收、失败/未知；不把任务表 ACTIVE 直接当作运行证明。侧栏独立刷新所有展示项目，前台可见时每 5 秒及恢复焦点时刷新，不依赖当前打开的房间。只读，不改任务状态或触发模型。

## beta.15/.16 审计发现

1. **P1，beta.16 快捷方式误删风险，已修复。** 原实现解码 .lnk 字节，只要含当前 exe 文件名就删除，另一个目录里的同名程序或描述提及文件名也可能命中。改用 Electron Shell 正式解析，要求绝对完整 TargetPath 等于当前 exe；目标众说入口属于其他程序时不覆盖；写入、回读核对目标/AUMID/通知激活 CLSID 后才移除旧入口。APPDATA 缺失时直接跳过。安装器原先的完整目标比较保留。
2. **P2，通知身份修复不完整，已修复。** beta.16 仅启动时及 4 秒后清理，遗漏用户很久后首次通知由 Electron 原生层创建的入口；也未注册通知来源的 DisplayName/IconUri。本轮补注册和通知 show 后检查。不能用 setAppDetails 的窗口显示名推导原生通知来源已经正确。
3. **P2，固定任务栏重启丢失显式数据根，已修复。** beta.16 relaunchCommand 只有 exe；安装版使用 `--data-dir` 时重启可能打开默认根。本轮保留明确数据根，按 Windows 参数规则处理空格、引号及末尾反斜杠。
4. 原测试仅断言包含原始字节匹配，实际保护了不安全行为；替换为调用合同加行为反例，覆盖同名异路径、描述误命中、外来目标、写入/核对失败、通知元数据和重启参数。

beta.15 设置修改主要为布局、卡片、搜索与控件位置，通知开关/数据操作仍用原正式命令。既有设置测试 10 项、包内设置投递开关与外链需随交付验证。私信白色底保留。本轮未读、全局折叠和房间状态问题在 beta.14 已存在，不归因于 beta.15/.16。

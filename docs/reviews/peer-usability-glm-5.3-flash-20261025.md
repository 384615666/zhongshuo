# 众说全项目体验方案独立评审

日期：2026-10-25。评审对象为全项目 52 项方案，源码提交 `7520288e5d0f20c60ccaeb9d6a3f10b90a334b04`。本文只评审，不改业务、不测试、不启动程序、不访问数据库。

## 总判断

主审对真实流程的把握基本可靠，U17、U26、U31、U35、U49 等项能在当前源码直接印证，应先处理漏工作、丢输入、静默截断和错误落点。但 52 项不应都按同等深度施工：部分方案把界面入口缺口说成能力缺失，部分会鼓励程序从自然语言猜复杂意图。建议先做小闭环止血，再做跨页找回和结果表达；通用弹窗、键盘和无边界协作解析应后置。

## 最关键反驳与更正

1. **U18：不要让程序解析任意依赖。** 已有能力包括明确多成员 AUTO、独立研讨开关和成员交接机制，见 `src/ui/hifi/data/selectors.ts:303`、`src/daemon/coordinationMessages.ts:32`、`:150`。缺口是普通单人 `direct.work` 禁止追加交接，也没有让用户轻量表达“先 Claude 后 Codex”。更好做法是识别两位成员后给出“共同处理／独立研讨／按顺序”选项，第一期只支持线性顺序和后一步核对前一步结果；不应尝试理解任意依赖图。
2. **U19：完成判定必须限定在已接受步骤。** 真实缺陷是必要 Codex 核对未发生而任务完成，且 `direct.work` 没开放交接；见 `src/daemon/dispatchWorker.ts:784`、`src/daemon/coordinationMessages.ts:33`。但完成判定不应扫描 AI 回复里的所有“未验证问题”，否则历史遗留会无限扩成本次任务。应只绑定发送后被程序接受的正式步骤。
3. **U34：正式撤销链已存在，缺入口。** `changeset.undo` 是正式命令，见 `src/daemon/commands.ts:2577`；恢复检查也知道未收口撤销，见 `src/ui/hifi/components/RecoveryPanel.tsx:309`。当前缺口在 `src/ui/hifi/components/FormalChanges.tsx:29` 的正式改动详情只有阅读与任务定位。应在详情加“恢复这些文件”和影响预览，并在恢复检查提供“继续撤销”；不能描述成没有任何撤销能力。
4. **U03/U02：草稿规则要控边界。** 24 小时是既有约定，设置和手册已披露，见 `src/ui/hifi/data/store.ts:830`、`src/ui/hifi/pages/SettingsPage.tsx:975`；取消静默过期合理，但不应变成无限堆积。应把普通草稿与未确认发送账本分离，见 `src/ui/hifi/data/store.ts:1178`、`src/ui/hifi/pages/SettingsPage.tsx:923`，增加可见草稿箱和主动清理。
5. **U47：不要全局改造弹窗。** 通用 Modal 确实直接外点/Esc 关闭，见 `src/ui/hifi/components/ui.tsx:297`，但全部弹窗加守卫会增加打断。应先保护成员配置、文件评论、验收意见这类高风险表单；小确认框保持轻量。

3. 项目准备状态 U13 是重要漏项：启用、绑定、程序、认证分散，用户仍无法一眼知道“这位 AI 能不能接任务”。

## 两个端到端故事

1. 用户写“@Claude 比较，然后@Codex 验证”。发送前可见 Claude → Codex；Claude 完成后 Codex 读取本次结果；Codex 未开始或失败时，任务不显示整项完成，串内有原因和继续/取消入口。
2. 用户发送后报错并切换项目。在“待我处理 → 发送记录”按时间和摘要找到该请求；点找回进入原会话并突出那条消息；不自动重发，后续草稿保留。

## 不应做或暂缓

1. 不做从自然语言推断任意依赖、自动扩员或自动补“必要验证”。
2. 暂缓 U47/U48 的通用弹窗和全站键盘重构；先做高风险表单守卫，避免阻塞止血项。
3. 暂缓无限保留草稿、全文索引和非 Git 批量回退。全文检索要单独设计可见性；撤销先复用 `changeset.undo`，不另造危险恢复路径。

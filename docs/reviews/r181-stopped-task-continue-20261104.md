# R181：停止后在原任务继续

日期：2026-11-04。用户授权修复 beta.26「停止后不能继续」。源码工作目录 `D:/zhongshuo-public`；未操作安装版、原私有目录或用户运行数据。

## 问题与结果

`task.stop` 完成后任务成为 `CANCELLED`。原串发送由 `assertThreadTaskReady` 直接报 `TASK_STOPPED`，`task.continue` 也将其作为不可继续的终态。用户主动继续和后台自动重放未被区分。

现在原串发送「继续」或新要求可恢复已经安全收口的停止任务；详情提供绑定当前版本/停止代次的「继续任务」。按钮同样创建一条新「继续」消息并走正式串内队列，不重放旧 outbox，也不误用根任务最初的模式。原串、任务、消息、已有成果、旧运行和停止代次保留。研讨停止后不指定新成员的普通跟进沿用 DELIBERATE；显式成员/模式仍按本次要求处理。

## 实现边界

- `taskContinuation.ts`：仅在已接受的用户命令事务中重开停止任务；保留停止代次，完整核对在途根/子执行，给旧 turn 留续接隔离事件，不重写旧结果/预算。旧版「结束任务」等没有停止代次的 CANCELLED 记录仍不冒充可恢复的停止。
- `commands.ts` / `threadReplies.ts`：预检只读，恢复与新消息、队列和回执同事务提交；非法附件/成员/预算等失败会整体回滚。跨异步准备发生停止变化时拒绝旧快照。记录意图不恢复；过期按钮、归档及 STOPPING 仍拒绝。
- `dispatchWorker.ts`：被继续替代的旧 turn 后续正文/成功/失败只留审计，不能改新任务状态或新交付；历史工具/用量事实仍保留。
- `coordination.ts`：旧已取消协作的周期收尾不再把已接受新请求的父任务重新改为 CANCELLED。
- `deliberationRunner.ts`：仅在正式停止续接的代次中提供历史讨论，按本次请求序号切断；最多最近24条，每条2000字符，排除仅记录消息与本次请求之后的材料。明确其为待核实背景，不代表自动重放旧排队请求，也不混入本轮成员独立初稿。
- `executionStatus.ts` 提供正式继续动作；`docs/user-guide/index.html` 补充停止后的使用说明。不改 schema、版本、原始锚点或已有交付状态。

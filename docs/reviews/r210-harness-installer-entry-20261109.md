# R210：安装时自动识别 Harness 转发入口

## 现场原因

用户安装 1.0.1 后收到 Harness 连接组件自动配置失败提示。2026-11-09 09:32、09:33 两次 Inno 日志均记录主程序安装成功，随后 `Harness connector setup result: 1`。

PATH 首先命中 `C:\ProgramData\dsh-cli\dsh.cmd`，其中只有 `@echo off` 和 `call "实际安装目录下的 dsh.cmd" %*`。旧解析器不识别再次转发到批处理的入口，抛出 `CAPABILITY_UNSUPPORTED`；安装脚本只在 `RUNTIME_NOT_FOUND` 时查找常规安装位置，因此未回退。使用已安装代码只读复现相同报错；随包归档校验通过。

## 产品侧修改

- 共享入口解析器静态识别纯 `call "...cmd/bat" %*` 转发，支持绝对路径、`%~dp0`/`%dp0%` 相对路径和最多八个批处理文件；保留桌面 Harness 的 Electron Node 环境及 ASAR 参数。不会启动 shell 或求值批处理。
- 只接受有限前后缀（关闭回显、禁用延迟展开、原样返回退出码）；不解释环境变量赋值、额外参数、其他命令或未知变量。循环和过深转发在启动进程前拒绝。
- 转发链全部文件及最终脚本/ASAR 纳入执行身份指纹；普通 JS 入口的 package 元数据继续参与，避免新增链路削弱原授权校验。
- 自动选择入口时，PATH 缺失或无法识别均可回退到常规桌面安装位置和 npm 入口。安装器 `--installer` 与手动重试 `--install` 共用处理；显式 `--dsh`/`--dsh-js` 不会被其他安装位置替换。
- 保留归档校验、官方版本兼容检查、官方 profile 插件安装、安装后 probe 及内容一致时跳过重复安装。未安装 Harness 时只有安装器允许跳过；发现无法识别的入口但无可用回退时仍报错，不伪装成功。

已有 Inno 安装后钩子和随包 `setup.cmd` 均调用这套脚本，重新打包即可带入修复，无需改变用户安装步骤。未改首页、README、品牌、版本号或安装范围。

## 验证

- 修复前，新测试中的十个用例复现入口失败或缺少必要行为；不是将本机安装结果冒充修复验证。
- 定向九文件共 **86 项通过**，含新增 **22 项**。覆盖现场形式的 PATH 转发、桌面参数/环境、相对及多层转发、身份指纹、循环/深度限制、拒绝额外行为、打包后脚本的安装/重复安装/回退/显式入口约束/跳过条件/版本与归档校验，以及既有 Harness/Pi 适配器回归。
- 安装流程测试运行真正打包生成的 setup/解析脚本，但使用独立临时 home 与本地假 CLI，不加载用户 Harness、凭据或供应商。安装参数、仅一次插件安装和原 profile patch 字节不变均有断言。
- 使用新打包的解析模块读取本机实际 PATH，成功解析 ProgramData 转发到官方桌面程序；只在独立 home 执行官方 `--version`，返回 **0.2.2-rc.1**、退出 0、stderr 为空。随包 `--plan` 归档校验通过且 `modifiesProfile=false`。本机证据：ignored 的 `dist/r210/local-entry-verification.json`。
- 本轮五个程序/测试文件 ESLint、定向 TypeScript、`git diff --check` 通过。依赖恢复时 SheetJS CDN 下载超时；只使用已下载的定向测试依赖，未据此宣称全量依赖恢复、全仓类型检查或全量回归通过。
- 指纹仍沿用既有的 size/mtime/ctime 文件戳缓存。迭代中同大小的快速改写曾命中旧缓存；对应夹具改为不同大小，以确定性验证转发链纳入指纹，本轮不据此宣称具备同大小且文件戳未变化的篡改检测能力。

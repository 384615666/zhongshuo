# R166：历史受阻待办与纯文字同伴回复

用户反馈：待我处理残留已处理事项，四位同伴回复后协调者仍等待，并询问侧栏符号。磁盘安装元数据已是 beta.17。本轮独立本机 IPC 认证仍被拒，未定位到截图的实际执行 ID；以下根因与修复由隔离持久状态复现，不冒称已修复原库或现场串。

## 待我处理

原 mine.pending 按 tasks.status=BLOCKED 列出所有任务，已完成/取消父任务下的历史分工、被后续协作轮替代的旧失败，以及父任务和其受阻子任务都会重复进入列表。

新增只读筛选：核对同项目、同会话的祖先链及父任务最新执行所对应的协作轮；已结束或已替代的旧步骤不再进入待办。同一当前受阻父任务只列一次。存在真实活动执行、未解决 UNKNOWN、保留保护、恢复门禁或待派发请求的旧步骤仍保留入口。原因读取当前执行投影，不再把旧无原因状态事件优先展示。读取不取消旧任务、不把旧失败改成成功，不消耗模型调用。

## 四份回复后的汇总

旧协作推进条件在通常分工路径要求各 DONE 步骤都有 current_delivery_id；纯文字 conversation 回复有意没有文件交付，因此持久化的四份正式回复可能全部存在，却一直停留 running/WAITING。

现在允许当前协作轮的真实纯文字答复成为交接：只使用该子任务最新 SUCCEEDED 运行及 SUCCEEDED turn 的 final-message 绑定（或正式终稿 ID），核对消息项目、会话、任务、作者和 final 状态，并携带消息/turn/run/作者来源。刷新会话交接缓存，防止继续后误用旧答复。各步骤完成且具备有效答复/交付后，仅排入一次协调者汇总；后续新父请求不被旧会话结果重新唤醒。工作结果仍要求正式交付；缺失答复、旧轮答复、未知执行和未释放保护不按成功推进。现有预算、租约、停止和文件版本核对保留。

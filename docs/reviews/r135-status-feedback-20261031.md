# R135：恢复定位、协作方式、失败说明与侧栏长名称

处理用户五项追加反馈：查看中断任务后弹窗不关闭；退出独立研讨藏在成员菜单里；继续任务仍未完成且原因不清；同一失败叠加三个横幅；侧栏长名称遮住操作按钮。原数据库只读核对，没有重放用户业务、改写任务状态或移动运行数据。

## 现场原因与修复

截图所示最新一次继续操作，确实建立了新的独立研讨运行，但两位成员均在请求模型开始处理之前被取消，记录为confirmed-not-started并退回预占。代码中“准备新的研讨运行”没有把原父任务从BLOCKED转回ACTIVE，而会话打开后的启动检查拒绝BLOCKED任务，于是两位成员都无法开始。最后的“没有有效分析结果”只是汇总提示，不能说明为何取消；截图中的旧回复与文件并没有因此丢失。

现仅在新的研讨准备成功后转回ACTIVE，继续复用原停止代次、配置、预算和结果未知保护。正式回归先在旧实现重现3个继续失败，再验证FAILED/PARTIAL/INTERRUPTED后的新运行能让两位成员实际开始并成功，旧运行保持原状态；会话打开期间用户停止时仍不请求startTurn。不会自动重跑现场任务。

| 反馈 | 最终行为 |
| --- | --- |
| 恢复弹窗 | 四类定位入口共用成功关闭逻辑。定位失败保留弹窗和可读错误，延迟期间也不提前关闭；定位本身不派发任务。 |
| 退出独立研讨 | “回到自然协作”移到“本次运行设置”一级，与“调整独立研讨成员”并列。成员子菜单只选名单与完成；正文、草稿、权限和预算规则保留。 |
| 原因不清 | 当前运行有具体成员失败/启动取消记录时，优先采用该运行的具体原因，避免只显示“没有有效分析”。仅全部轮次都有明确未开始证据时显示“未能开始”，原运行状态不改写。 |
| 三个横幅 | 正式回复串只显示一条任务提示，原因换行可读，继续/结束/查看原因在同一条内；去掉重复的阻塞和运行失败条。没有正式状态时保留最多一条兼容提示；待答复与验收入口仍可用。长问题在最新回复完整保留，顶部只给处理说明。 |
| 长名称 | 截图中的VoiceMeeter-backup实际是项目行。项目动作列固定占位，长名在按钮前省略；hover、键盘focus和菜单打开时按钮可达，不改变名称宽度。房间名、状态和未读点仍各占独立空间。 |

## 独立复核与边界

复核发现第 12 项的一个必要补修：正式恢复链可以先保留文件保护，再接纳迟到成功；若把所有保护错误当永久无效，就会删掉笔记。现仅对“已成功、无有效用户停止、暂时 retained”的来源保留 pending，正式解除保护后再经过原 store 的所有校验合并。不放宽保护、停止、范围或来源规则，也不加 17 的 hash 校验。原红灯和复验记录见 [独立 worker 复核](r126-independent-worker-review-20261030.md)。

独立协议复核还补齐受支持协议的字符串/数字请求 ID 与不同审批 method 的合法回包值。测试核对实际 wire，不仅核对内存事件；详见 [协议分项报告](r126-protocol-20261030.md)。R82/R83 旧参数测试没有建立连接，新增连接检查正确拒绝它们；仅把夹具改为明确的无进程 live sentinel，保留原模型、effort、sandbox、权限与完整提示词断言，生产校验没有为测试放松。

保护不等于无限运行：1、6、20 中无法证明执行结果的情况会结束当前消费者，按 UNKNOWN 待核实；不以释放名额为理由伪造未启动/成功/确认退出。真实 CLI adapter 当前未提供可选 lateEvents；第 12 项的正式恢复链通过 Fake 日志和真实本地载体验证，未声称扩展了真实 CLI 回放能力。

15—18 和 19 的测试继续保留：A06（16）、C09（17）以及 R125 S1 adapter（19）仍为明确的预期反例；P04 的正式回复保护仍通过，连接流本身仍有完成后事件，独占文件仍真实记录 unknown。不能将这三项预期反例计作本轮失败或修复通过。

# R154 协作交接与恢复诊断

2026-11-01，基于公开源码 `67abbe7`，独立分支 `codex/r154-installer-recovery`。本轮只读诊断用户安装版记录，未继续、重放或修改原任务，未调用模型。首页、根 README、logo 和旧私有历史不在改动范围。

## 现场原因

- **四份成果已生成，汇总却 BLOCKED**：四个生成子任务均已完成。并行目录扫描记录了其他成员同时产生的文件，交接把这些观察也当作本成员成果，四份清单分别为 7/24/6/12 项。实际 TaskComplete 声明各自只有 6 项，汇总成员在启动前被真正冲突检查误拦。
- **Excel 修订后的后继步骤失败**：第一位成员按正式交接更新了自己的文件，后面的兄弟修订仍拿旧上游版本校验，随后父协作阻塞，其他步骤停止派发。这与外部任意修改文件需要拒绝的情况不同。
- **只显示 BLOCKED**：具体 `coordination.dispatchBlocked` 已落库，但展示没有选中它，反而把 `task.statusChanged.status` 当作原因。成员在创建执行 run 前失败，也缺少可见诊断。
- **Pi 待核对**：最后一个 Python 命令进入交互控制台并长时间未结束，随后应用正常关闭，没有收到可确认的业务终态。UNKNOWN 和保护应保留。正常关闭移除锁、旧版只留最后一份停机记录，使后来跨进程核查缺少旧持有者依据；不能把可见输出当成功或自动重发。

诊断初期发现 Codex 的 MSIX 身份读取到 AppData 虚拟副本，不能当作安装版现场。最终用 WMI 启动无 package identity 的只读 helper，数据库设置 readonly/query_only；只读取相关任务。证据保留在 ignored `dist/r154-live-evidence.json`、`r154-readonly-recheck.json`，后者 `total_changes=0`。

## 修改

1. **安装升级**：按用户最新决定，恢复原有运行中拒绝安装的行为，必须先从托盘退出再安装。本轮自动关闭实验及 helper/native 专项测试均已移除，不随包交付；手册明确 × 只是隐藏。
2. **交接成果归属**：共享扫描保留完整审计；交接只投影成功源轮次的声明与绑定工件快照，哈希仍来自不可变变更集，不采用当前磁盘哈希补造版本。旧污染缓存按原始来源只读重投影，不重写历史交付、缓存或快照；显式继续时才派发。
3. **修订版本**：仍按原依赖 DAG 拒绝独立覆盖。后继输入记录已经完成的合法因果修订及来源交付身份；共享继承文件的修订步骤顺序启动，独立初始生成仍并行。启动前再次校验磁盘及冻结输入版本，等待期间改变则拒绝，外部篡改不自动接受。
4. **原因展示**：父任务可定位本轮子步骤的具体失败，过滤旧计划迟到事件和裸状态词；新增无 run 的未启动成员失败，运行详情及参与成员页显示真实原因与任务链接，不虚构运行记录。停机中断说明绑定 exact turn 的有效 last/history，冲突保守回退。
5. **停机证据**：事务保存 completed stop 原内容与持久化时间，last 被覆盖前也保存旧 completed binding。相同记录去重、不同绑定冲突拒绝。缺归档锁时可按目标 turn 选择唯一停机记录，仍需旧 owner/root/已知后代均退出、Job kill-on-close、完整树检查和当前锁重读；只支持显式核查，不把 UNKNOWN 改成功、不重放或退款。旧 beta.2 已覆盖而没有留下的证据无法补造。

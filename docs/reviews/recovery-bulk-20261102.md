# 恢复任务按需显示与一键继续

2026-11-02。用户希望左下角“恢复任务”在没有待恢复事项时隐藏，并减少逐条恢复的操作；随后明确选择“只要一键继续，成功后自动清空”。本轮在公开源码目录实施，未改动旧目录、运行中的安装版或用户数据库。

## 行为

- 只有中断、未解除的旧占用、未结束撤销或等待确认继续的队列会显示恢复入口；正常排队和已处理的 UNKNOWN 历史不显示入口。启动不自动弹窗。
- 弹窗新增一个“一键继续”按钮，按实际父任务合并协作子任务，沿用正式 `task.continue` 的任务版本、停止代次及请求身份；不会把正常运行、完成或取消的任务重新派发。队列继续仍提交 `confirm:true`。
- 存在未完成撤销时，按钮说明会明确包含撤销；先通过现有 `changeset.undo` 续跑撤销，再继续任务和队列。文件冲突会显示具体路径，并停止这一批后续任务的提交。
- 提交成功后自动关闭弹窗，并立即重新查询恢复状态，已解决的事项移出恢复列表，入口在无事项时隐藏。任务继续在后台运行，提示不声称业务任务已经完成。
- 部分失败保留具体原因，成功项从列表移除，再次点击只处理剩余项。断线结果未知时沿用原请求身份重试，批量及逐条操作共用互斥保护，防止重复点击或交叉提交。
- 提交过程中可以关闭弹窗，后续提交继续执行；已经关闭的旧弹窗不会在完成时关闭用户新打开的恢复弹窗。
- 不新增“清空”按钮，不删除聊天、文件和任务历史。

另修复 `recovery.status.pendingRelease` 缺少任务归属的问题：补充真实 `taskId`，使只有 FAILED/retained、没有 UNKNOWN 的恢复项也能定位父任务并进入批量继续。

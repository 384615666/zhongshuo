# R169：中断检测遗漏与继续任务的内部错误提示

用户截图显示对话仍为“执行中断”，恢复列表却说没有任务；点击继续时原样显示源运行编号与恢复派发的内部拒绝说明。只读查看原应用的房间及运行详情也能看到这一状态组合，未点击继续、停止或发送。原数据根的独立只读查询未匹配界面任务，不能据此声称核验了原任务的完整数据库事实；没有修库或代重放原串。

恢复列表原来从 UNKNOWN/保护/INTERRUPTED 运行记录拼接，已解除保护或写过恢复入队事件会被排除；对话却根据当前持久执行投影继续显示 UNKNOWN。新增 interruptedTasks，以同一事实投影补查未结束根任务，并在恢复面板与侧栏同步使用。只读查询跳过动作资格，延续 R168 的性能优化；他人私信不进入新增列表。排队、运行、完成、取消不被当成新增中断。

继续动作绑定原任务版本、停止代次与当前中断源。旧恢复 outbox 已 done、但能确认没有创建 turn 或协作运行且有正式入队来源记录时，显式当前版本继续可建立新意图；旧行、历史结果均保留。真实执行、错误/缺失来源、旧版本、停止、当前在途与工作空间保护继续由正式守卫核对。普通不带版本的 redispatch 不获此例外；运行详情携带完整中断快照时支持同一行为。读取不会自动恢复。

任务按钮统一展示可读反馈；过时状态重新读取，重复请求说明正在处理中，未知回执保留原 commandId 重试语义。内部编号、队列键与派发术语留在后台诊断中。旧运行详情和私信控件同样转换该两类旧内部说明。没有资格的 UNKNOWN 项只提供查看入口，不猜测继续操作。

本轮定向与界面验证、完整回归、包身份及交付结论在完成后回填。仅交付安装包，沿用用户暂不安装的选择；不创建 GitHub Release，不运行真实模型。

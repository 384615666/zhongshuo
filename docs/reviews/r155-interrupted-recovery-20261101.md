# R155 中断任务检查与恢复闭环

2026-11-01，基于公开源码 `10d71d1`，独立工作树 `codex/r155-recovery-actions`。安装器保留用户决定的“先从托盘退出再安装”；不恢复自动关进程实验，不迁移旧私有目录数据，不推送或发布。

## 原因与结果

用户截图对应 Pi 旧执行：UNKNOWN、预算 settled、保护 retained，父任务的新消息因此被正式守卫拒绝。它没有完整答复或文件快照，最后动作是一个进入交互状态的 Python 命令。旧 beta2 的 completed stop 后被一次空 stop 覆盖，当前库既无这次旧 stop 历史，也无旧锁归档；仅“重新打开众说”不能补造旧持有者退出的证据。

此前“核对执行结果”只有笼统入口，没有显示具体阻塞成员、没有完整结果时仍让用户核对，父任务 reason 的 taskId 也可能指回父任务。如今改为 **检查中断**，传递 exact turn/child/run，直接显示真实对象、已有答复/文件、最后动作和程序退出检查结论。没有完整结果时明确说明。

## 最终行为

- 新增本机只读 `recovery.inspect{turnId}`。它不写回执、预算、保护或派发，不调用模型，也不凭 PID 不存在认定完整退出。远程调用拒绝；返回源轮次真实任务归属及退出准备状态。
- 检查通过才显示 **解除占用**。明确点击后重查、必要时仅处置尚未结算的 UNKNOWN，再走既有正式保护释放；检查最终回执。已 settled/refunded 不重复结算，失败保留保护，不自动放行 dispatch 或重放旧请求。释放后的原 UNKNOWN 仍是 UNKNOWN，保留历史但不再作为阻塞提醒。
- 旧版 stop/锁证据都丢失时，增加经系统确认的 Windows 新启动代次作为退出依据。读取 OS LastBootUpTime 和 GetTickCount64 并核时钟一致、晚于旧登记/历史存活观测与时间容差、当前排他锁合法，再核根/历史进程及树，重读启动/锁/stop 事实。真实新 PID 代次可以复用旧数字，不杀它、不把新树冒认成旧后代。睡眠/休眠/重开众说不构成重启证明。用户这条当前同次 Windows 启动仍阻止释放，并明确要求安装新版后重启一次 Windows、再检查和解除占用。
- 旧 UNKNOWN 即使没有 retained 标志和租约，缺正式释放事件时也不能当 no-op；仍走真实退出检查并落正式事件，避免“检查 ready，点击后仍卡住”。矛盾的 none/非空 PID 或 pre-launch 登记不冒充无子进程事实。

legacy 时间依据没有旧 boot ID，使用旧 wall-clock 时间与系统启动时刻，要求正常稳定本机时钟；不能证明历史时钟被人为回拨的情况。时间/系统 API/进程身份有疑问时保留保护并显示原因，不承诺任何环境下强制解锁。

## 验证与边界

原安装库通过 WMI 外部只读 helper 核实，规避 Codex MSIX 的 AppData 虚拟副本；`query_only=ON`，`total_changes=0`。没有修改用户任务、结算、保护、队列或项目文件。只读投影确实找到 Pi 子任务，无答复/文件，最后命令失败；helper 自己不持有原 daemon 锁，因此不冒充服务端拥有者作退出核查。

集成回归覆盖无最终结果、真实父→子恢复绑定、只读零写、真实退出证据释放后父守卫通过、预算/UNKNOWN/旧 outbox 不变、缺 retained 标记旧数据收口、矛盾无进程登记拒绝。另用真实 Windows boot API 配合明确标记的合成“旧启动前登记”，经正式 `recovery.releaseProtection` 收口，未实际重启电脑。boot 正负例覆盖同启动、时间容差、查询失败、PID 重用、历史后代、锁/stop 竞态等。

Electron 实际组件 23 项检查通过，含父按钮→正确子任务、打开检查只读、重启提示、显式解除、失败保留、已释放历史不再作为待处理以及宽屏。独立审查发现“无 retained/no lease UNKNOWN 释放 no-op”并已复现修复，7 个独立场景最终通过；不把 mocked 新启动当作用户机器已重启的证明。

完整回归、类型/lint、最终安装产物及验收结果在收口时追加。用户当前原执行仍 UNKNOWN，最终恢复步骤需要用户重启 Windows 后在新程序中明确操作；本轮不会代用户重启或自动重跑旧业务。

# R144：Windows 可安装 EXE 与实际安装验证

用户反馈 V78 沿用数据入口仍报错，要求制作可发行的安装 EXE 并安装测试。本次最新日志确认已有 daemon 正在运行，重复启动被单实例锁拒绝；R143 的原库测试只证明启动及命令可用，截图仍有项目路径导致的启动失败状态，不能据此宣称完整用户入口已验收。

## 交付行为

安装版 `0.1.0-beta.1` 使用固定 AppId 和当前用户安装方式，提供中文安装向导、开始菜单、可选桌面快捷方式和系统卸载登记。程序目录 `%LOCALAPPDATA%/Programs/Zhongshuo`，数据目录 `%LOCALAPPDATA%/Zhongshuo/data`，无需系统 Node.js。不会自动使用或复制旧便携版数据；原数据与正在运行的旧版进程保持原状。用户可在设置的数据与存储中主动导入已有数据。

原生 EXE 识别随包安装标记，清理继承的运行覆盖、固定正常渠道默认值、按数据根区分管道。稳定基础目录先取得 Electron 单实例锁，再读取数据位置或对账数据操作；重复打开唤起原窗口。发生失败时显示具体原因与本地日志位置。错误清理只停止确认属于本次派生进程的 daemon，不向另一实例发停机命令。无效目录参数不会读取继承的旧数据根。数据操作后台使用新 EXE 名称，并显式保持同一基础数据目录重开。

安装器在修改之前独占探测主 EXE 和后台 Node；程序运行时拒绝升级和卸载，不强杀任务。卸载只移除登记的程序文件，数据和未登记文件保留。安装器副本禁用 Electron RunAsNode fuse，继承 `ELECTRON_RUN_AS_NODE=1` 仍打开桌面程序，其余 fuse 保持不变。打包保留运行库/第三方许可和离线操作手册，新增两张实际安装截图。

当前为未签名的测试发行包，元数据 `signed:false`；没有加入自动更新或远端发布。AI CLI、供应商配置与 Harness profile 连接组件仍按现有手册自行配置，不随安装器导入个人网关、密钥或技能。

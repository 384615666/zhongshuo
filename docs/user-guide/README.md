# 众说操作手册

适用版本：V53 / R110 · 更新日期：2026-10-26

众说把同一项目里的房间、AI成员、任务、私信和文件放在一起。你可以像聊天一样交代工作，在原对话里追问、看结果和要求修改。

**随时查手册：点左侧设置入口，再点“帮助与关于”，即可在设置中阅读本手册。** 也可以在设置搜索中输入“手册”直接找到。手册随程序版本一起更新，无需联网。

## 1. 打开与退出

### 继续你原来的项目和聊天

1. 打开本次交付文件夹 **desktop-daily-win-v53-r110-settings-guide-20261026**。
2. 双击 **start-existing-data.vbs**。
3. 在左侧点项目下的房间；一对一会话从 **私信** 进入。

这次沿用原来的数据位置，不需要搬文件。你原来的数据仍在旧V44包的 **server-data** 目录；日常启动入口继续引用它，请保留该目录。

### 全新开始

1. 没有旧数据时，双击 **start-desktop.vbs**。
2. 点 **打开/切换项目**，选择要工作的本地文件夹。
3. 到 **成员管理** 配置需要使用的AI，再进入默认房间发消息。

这两个启动入口使用的数据位置不同。已有历史的用户继续用 **start-existing-data.vbs**，就能进入同一份历史。

### 最小化和退出有什么区别

- **最小化**：收起窗口，正在执行的工作继续。
- **点标题栏X**：出现退出确认；点 **取消** 留在程序里，点 **退出** 正常关闭。退出后当前执行会停止。

收起右侧对话串、切换页面、切换房间都不是停止任务。要停止一项具体工作，使用它自己的 **停止任务**。

## 2. 项目与房间

### 打开和切换项目

1. 点顶部当前项目名，或左侧 **打开/切换项目**。
2. 选择已有项目，或选择本地文件夹打开项目。
3. 顶部项目菜单中，项目名下方会显示对应目录，便于分清同名项目。
4. 左侧展开项目，点具体房间进入。

已有项目重复打开会继续使用原项目，不会另建一套同名历史。

### 新建房间

1. 在左侧项目行点 **+**，或在项目主页点 **新建房间**。
2. 填房间名称，点 **创建**。
3. 创建后会进入新房间。

新房间默认加入项目现有成员，协调者沿用原设置，不用逐个重新添加AI。需要改变这个房间的成员时，再进入房间设置调整。

### 房间和对话串分别装什么

- **房间**放多件事的总览，每次另起话题会形成一张卡片。
- **对话串**放其中一件事的原始要求、追问、AI回复和成果。
- 房间卡片的长内容会缩略，点卡片或回复数看完整对话。
- 要继续同一件事，在右侧 **跟进当前任务** 输入；要另起一件事，用房间底部输入框。

## 3. 成员与AI设置

### 添加或配置AI

1. 左侧点 **成员管理**。
2. 新增成员时使用页面的添加入口，填写显示名称。
3. 在成员卡片或详情中点 **AI设置**。
4. 选择当前电脑上使用的渠道、模型及需要的执行权限，然后保存。
5. 回房间发一条简单消息，确认该成员能正常回复。

模型和可执行程序的选项以设置中实际读到的列表为准。修改绑定后，新请求使用新配置；已有执行仍按它开始时的配置继续。

### 选什么权限

- 只需要解释、核对或读资料时，使用你希望的读取范围。
- 要AI实际改代码或文件时，需要给这次工作相应的项目文件权限。
- 改了权限后，回原任务点已有的继续入口，或在原串明确说明接下来要做什么。

设置权限不会自动启动工作。保存AI配置后也不必重新创建项目或房间。

### 启用、停用和房间成员

成员停用后不再接新请求。想停止已经开始的一项任务，到那项任务里点 **停止任务**。

房间设置中的成员选择影响这个房间里能使用哪些AI。默认成员已经合适时，可以直接开始聊天。

## 4. 房间聊天与协作

### 发一条消息

1. 进入房间，在底部输入要求。
2. 要指定成员时，可以使用现有 **@** 选择成员，也可以在文字里自然说明谁来做。
3. 点 **发送**。
4. 点新卡片或回复数，在右侧看回复。

例如：

> @Claude 帮我比较这两种方案，然后@Codex 核对这次比较结果。

输入界面没有增加顺序设置、收件预览或发送前的安排表。接单模型根据你的文字决定如何使用现有协作能力。

### 让另一位接着做

直接写清楚希望怎样配合：

> 先让Claude改这段说明，再让Codex读取改后的版本核对。

> 这次只需要Claude解释原因，不要修改文件。

> 你们分别给意见，最后把分歧整理给我。

程序沿用已有分工与交接。后一步需要前一步结果时，会使用这一次的成果；尚有已安排的必要步骤没做完，整项任务仍未完成。

如果你只需要普通答复，直接提问即可，不必为了发消息选择协作模式。

### 继续、补充或修改要求

在原对话串的输入框接着说，例如：

> 把第二点讲得更具体。

> 按上面结论修改文件，并核对改动。

> 保留第一版的结构，只调整错误处理。

追问会留在同一件事里。模型能看到本串的已有内容，不需要把之前的回答整段复制一遍。

### 仅记录和独立研讨

输入区原有菜单中还保留 **仅记录** 和 **独立研讨** 等已有选项。只在确实需要时使用：

- **仅记录**用来留下信息，不派发AI。
- **独立研讨**用于需要多位AI先独立思考、再比较意见的场景。
- 普通“谁先做、谁再核对”的要求直接写在消息里即可。

<a id="dm"></a>

## 5. 私信

1. 左侧点 **私信**。
2. 要继续旧话题，打开已有会话。
3. 要开始独立的一件事，用现有新建入口选择成员。
4. 在私信输入框提问、加附件或继续追问。

**新建私信有自己独立的上下文。** 同一位AI的其他私信不会自动并进来。要继续原来的事情，就回到原会话，不必新建。

私信和房间消息是不同的会话。需要某位房间成员处理的要求，直接在相应房间或任务串里交代。

## 6. 任务进展、停止与继续

### 从哪里看进展

- 房间卡片看简要状态。
- 点进对话串，看当前状态和回复。
- 需要查具体执行过程时，切到 **详情**，看 **活动与进展** 或 **运行详情**。
- 私信中的任务在对应私信内查看。

| 状态 | 你可以怎样处理 |
| --- | --- |
| 正在执行、排队中、等同伴 | 继续等待；需要时到详情看当前进展。 |
| 等待另一任务 | 当前成员或文件位置被其他工作占用，等其结束。 |
| 等你处理 | 阅读任务中提出的具体问题，补充信息。 |
| 待你验收 | 查看当前交付，再决定确认还是要求修改。 |
| 已完成 | 看本次答复和成果；要修改就在原串继续说。 |
| 未能开始、未完成 | 看现有错误原因，处理后再继续。 |
| 待核对 | 先用现有恢复检查核对上次执行，不必反复发送同一要求。 |
| 正在停止、已停止 | 等停止结果，已有回复和成果仍可查看。 |

### 停止与继续

- 点 **停止任务**：停止这项任务的执行。
- 点 **按原请求继续**：仍按原来的工作要求继续，不会把修改文件的要求悄悄换成仅分析。
- 原本就是只读或仅分析的请求，继续时仍保持原范围。

继续后若仍显示原来的问题，先处理错误中指出的配置或条件。点击继续不是重新建一件相同任务。

<a id="find"></a>

## 7. 搜索、待我处理与任务看板

### 搜索和收藏

1. 点 **搜索与收藏**。
2. 输入关键词，使用原有范围和类型选择查找。
3. 点消息、任务或文件结果打开它。
4. 常用内容可以在原消息的操作中收藏。

搜索查到哪一类内容，就打开对应内容。没有找到时，可以换关键词或使用现有范围选择。

### 快捷查找

按 **Ctrl+K** 打开快捷面板，输入页面名、成员名、任务名或消息关键词。

- 点成员结果会进入该成员详情。
- 点任务或消息结果会定位对应内容。
- 用上下方向键选择，回车打开，Esc关闭。

### 待我处理

左侧 **待我处理** 集中放需要你回应、验收或继续处理的事情。点条目进入对应任务，根据现有提示处理即可。

### 任务看板

点 **任务看板** 看现有任务状态，点卡片回任务。看板用于总览，具体追问和修改仍在原对话串里做。

## 8. 成果、修改与验收

### 看本次结果

1. 在原对话串先读AI的答复。
2. 有文件或交付时，切到 **成果**。
3. 点文件打开预览，需要时用预览中的保存入口。

旧任务的成果会按该任务读取，不会因为项目里又完成了很多任务就显示成空。

### 要求修改

直接在原串说明要改哪里，例如：

> 第二段说得太笼统，补上失败后的处理步骤，其他地方保留。

不需要学习新的返工按钮或先选一种修改模式。原有人工验收入口仍按它自己的流程使用。

### 人工验收

任务要求人工验收时：

1. 打开 **交付与验收**。
2. 查看这次提交的版本、文件和核对结果。
3. 按现有按钮确认，或填写需要修改的意见。

验收针对当前这一版交付。后面产生新版时，先看新版内容再决定。

### 旧回答和补交版本

如果同一回合出现“原答已补交”，默认阅读有效的补交结果。旧原文可以展开核对，不需要把两份都当成不同任务重新处理。

<a id="files"></a>

## 9. 附件、预览与引用

### 把文件交给AI

1. 在当前房间、对话串或私信输入框点附件图标，或把文件拖进输入区。
2. 等附件准备完成。
3. 在正文里写清楚要怎样处理，再点 **发送**。

附件跟随当前会话和这次要求。只添加附件、还没发送时，AI不会自动开始处理。

### 预览和保存

点消息中的文件卡片或成果中的文件打开预览。不同格式使用页面提供的阅读和保存功能；切换预览不等于让AI执行文件里的内容。

### 引用一段文字

1. 打开文件预览，选中要讨论的文字。
2. 使用原有 **引用** 操作，把它带入当前输入框。
3. 补上问题，再发送。

选中的文字会完整带入，不再默默只保留前400字。引用本身不是发送，插入后仍可以编辑。

### 评论

预览里的评论用于记录意见。要让AI处理，仍在当前任务或私信中说明要求并发送；留下评论不会自动启动AI。

<a id="git"></a>

## 10. 文件与Git

左侧 **文件与Git** 用于查看项目文件、原有Git信息和任务改动。

- 浏览文件后可以打开预览。
- 读代码改动时，先确认当前项目和文件，再看具体差异。
- 提交、切换分支、合并或推送，使用页面已经提供且当前可用的操作。
- 需要AI修改代码时，在房间或原任务串中说明要求。

**文件已修改、Git已提交、GitHub已推送是不同结果。** 需要推送时，把这个要求写清楚；任务结束后核对回复中的提交和推送结果。

没有使用Git的项目，仍可用众说聊天、读文件和处理任务。

## 11. 通知、外观与其他设置

### 在设置中查看操作手册

1. 点左侧 **设置** 入口。
2. 点 **帮助与关于**，页面上方就是完整操作手册。
3. 点手册中的章节目录，跳到要查的操作；向下滚动继续阅读。

也可以在设置搜索中输入“手册”或“教程”，点 **操作手册**。版本和诊断信息仍在手册下方。

手册跟随当前程序一起提供；升级新版后，这里会显示随新版更新的内容。需要在程序外查看时，双击交付文件夹中的 **众说操作手册.html**，同样可以离线阅读。

### 完成通知和静音

任务完成或需要你处理时，原有桌面通知会提醒你。

- 点完成提醒回到答复。
- 点待验收提醒进入交付与验收。
- 点执行异常提醒进入运行详情。
- 私信提醒回到相应私信。

只想关闭某串的提醒时，在该串的现有订阅或通知入口静音；静音不会停止任务。设置里的 **通知** 可以查看已有静音项和投递记录。

### 外观与头像

到 **设置与帮助 → 外观** 改主题或头像显示。也可以在设置搜索中输入“主题”或“头像”，点结果到对应控件。

### 模型调用次数预算

原有预算功能按模型调用次数工作。需要限制一项任务的调用次数时，在现有运行设置中调整；达到上限后按任务当前状态处理。日常不需要限制时，可以沿用原有选择。

设置开关与表单按各自原有方式保存。需要点保存的地方，完成修改后点原按钮即可。

## 12. 按需使用的其他已有工具

### 归档和恢复

不常看的项目或房间可以用原有归档入口收起。归档后到现有归档管理查看历史或恢复。

归档、从应用里移除项目和删除磁盘文件不是同一个操作。只想收起项目时，使用归档或移除入口，不用删除项目文件。

### 备份和已有数据恢复

这是已有工具，日常聊天不要求先做备份。

需要时到 **设置与帮助 → 数据与存储**，按现有 **备份全部数据** 或 **使用已有数据或从备份恢复** 操作。选择保存位置，等待复制和核对完成，再按结果继续。原数据目录请按实际结果保留。

### 其他设备

已有远程使用需求时，到 **设置与帮助 → 连接与设备**。按页面现有地址、配对和授权操作连接。只在本机使用时，无需设置这一项。

<a id="send"></a>

## 13. 发送后不知道有没有收到

### 正常收到

看到自己的消息已经出现在房间、对话串或私信里，就继续等回复。成功发送不再常驻 **查询刚才的发送**。

### 结果不确定

1. 留在出现异常的原输入区。
2. 点现有 **查询刚才的发送**。
3. 找到时会直接定位原消息，并收起这次查询块。
4. 没找到或暂时查不到时，按原有结果提示处理。

查询不会把同样内容再发一次。只有你明确选择现有的重发操作时，才会重新提交原请求。

### 草稿还在但消息也找到了

查询旧发送时，后来新写的内容仍保留在自己的输入区。可以继续编辑，不必为了核对旧消息删掉新内容。

## 14. 常见问题

### AI没有回复，但界面显示在执行

先看当前成员活动，必要时打开运行详情。有时正在读文件、执行命令或等另一个成员，不一定立即出现文字回复。

### Claude答完了，Codex还没核对

如果原要求有核对，仍应等待核对结果。可以在原串继续问“Codex这一步现在怎么样”，不用另开重复任务。

### 报错说成员或模型不能用

到 **成员管理 → AI设置** 检查渠道、模型和程序配置。改好后回原任务，使用它的继续入口。不要通过重建项目来解决AI配置问题。

### 点“继续”后没有改文件

先检查原要求是否就是仅分析，以及任务是否仍有错误。如果你希望实际修改，在原串明确说明修改目标，并配置相应的文件权限。

### 为什么找不到刚才的查询块

成功发送后会收起。只有发送结果尚需核对或出现异常时，才需要它。普通历史从房间、私信或搜索查找。

### 旧任务看不到成果

先确认打开的是那项任务的 **成果**，而不是另一件同名任务。读取报错时先重试读取，不必要求AI重做文件。

### 更新后看到空项目

先退出，确认用了本次包中的 **start-existing-data.vbs**。**start-desktop.vbs** 用的是另一份数据位置。请保留原V44包的数据目录。

### 需要反馈问题时给什么

说明你在哪个项目、哪一串、点了什么，以及希望发生什么；附上当前错误或截图即可。任务名、时间和版本号能帮助定位，不必重复执行原任务来复现。

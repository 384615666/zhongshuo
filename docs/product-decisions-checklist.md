## 一、已经明确的核心需求，不需要重新确认

1. 本地文件夹是一等项目，能分析其中的代码和文件。
2. 有 Raft 式群聊多 agent 协作，调用 CLI runtime。
3. 不指定成员时，一个成员先分析，再组织多个成员工作并整合。
4. `@全体` 时，各自报告、相互比较、多轮交流，争取形成统一结果。
5. `@某个成员` 时，由指定成员处理，其他群成员静默。
6. 在主对话池发任务，回复归入原消息的独立线程；可以点开单独看。
7. 不同任务的对话上下文默认不混在一起。

以下待确认的是这些需求的具体行为、边界，以及从 Raft 文档补充的功能。它们不会被当作重新否定上述目标。

## 二、怎么回答

- 功能项可以写“首版要”“以后做”“不需要”，也可以直接说希望如何使用。
- 行为项可以写“按建议”或给出自己的规则。
- 可只回答一部分。例如：`01 按建议；06 不要固定三轮；13 以后做；37 先接 Claude、Codex、DSH。`
- “按建议”只确认你明确列出的编号。若想整批接受，可以明确写“01—10 按建议，06 例外……”。
- 前面的编号不是优先级。先讨论会影响协作体验的 01—12，再挑选阅读辅助功能，通常最省力。

### 13. 人的线程关注与 Agent 的线程跟进（实机查看后修正）

2026-09-13 通过用户已登录的 Chrome 查看指定 Raft 回复串，发现这里需要区分两项。之前只按人的通知偏好解释“关注”，不够完整；以下修正说明不表示用户已经选择保留哪一种实现。

**13A：你是否关注这个任务的动态。** 这是下面通知开关例子所描述的功能。

例子：你同时开着“登录功能”“数据库方案”“整理资料”三个任务。“整理资料”还在运行，但你暂时不想持续关注它的回复。

关注表示把该任务的新动态纳入你的关注列表或通知规则；取消关注表示不再主动提醒这个任务的普通后续动态。你仍然可以点进去看，也可以继续回复。**它不等于停止 AI，不等于退出群聊，不等于清除历史，也不改变 AI 的任务上下文。**

它与静音可以分开：关注决定哪些任务进入“我关注的动态”；静音决定这些动态是否弹出提醒。首版也可以简化，只提供“这个任务的通知：开/关”，不同时引入两个术语。

建议：首版先做简单的任务通知开关；你发起的任务默认开启。任务是否需要你授权、是否失败等关键事项始终保留在“待我处理”中，弹不弹窗由通知偏好控制。若你只用一个项目、很少同时运行很多任务，完整关注列表可以后置。

**13B：哪些 Agent 持续跟进这个任务。** 实际页面右上角显示“3 个 Agent 正在关注”，列表包含 XP-codex-ds、XP-claude-ds、XP-claude-glm53f，并分别提供“移出关注者”按钮。这与人的桌面通知设置不是同一项。

本地产品可设计为：线程顶部列出参与/跟进成员，用户能增加成员或让某个成员退出后续跟进。退出后是否仍可手动 @回来、已有运行是否继续、历史是否保留，需要独立定义。建议保留历史、停止后续自动跟进；当前运行的停止提供单独动作。以上是建议，未通过点击移除测试 Raft 的真实执行行为。

`@某一个成员` 仍要符合其他群成员静默的已确认要求：历史上关注过这个串，不应成为无视当前指定模式的理由。人的未读、agent 的订阅、当前参与名单和正在运行的工作需要分别记录。

**待确认：13A 决定人的动态提醒；13B 决定是否需要 Agent 跟进名单，以及退出跟进的行为。此前关于第 13 项的通知开关选择只适用于 13A，不能代替 13B 的选择。**

|---|---|---|---|

## 五、实际修改项目与文件工作：25—34

“在本地项目工作”不自动决定怎样修改、审批和交付。下面的取舍影响开发范围和日常操作。

| 编号 | 待确认内容 | 实际场景与影响 | 建议起点 |
|---|---|---|---|
| 25 | 分析与修改如何切换 | 你说“看看这个模块”，应仅分析；说“修复它”，是否直接改？还是每次都选权限模式？ | 明确修改请求在项目已设范围内直接执行；含糊分析请求先分析。提供清楚的模式显示，减少重复确认 |
| 26 | 多个成员怎样同时改代码 | 第一版同一目录每次一个写者，其他人可并行分析；也可以让每人改独立副本后整合，但后者需合并界面与冲突处理 | 先单写者，把多任务协作跑顺；如果“并行编码”是你的核心需求，应直接前移隔离工作目录 |

| 29 | 命令、安装和外部操作的范围 | 测试、启动服务、安装依赖、提交 Git、推送或部署是否需要不同控制？会影响 AI 被打断的频率 | 项目中配置常用允许操作；正常测试按已设范围执行。提交/推送/部署等单独设置，不能从“读代码”推导授权 |

| 31 | 附件类型 | 你会给 AI 拖图片、PDF、Word、Excel 或 CSV 吗？保存附件和 AI 能读懂它是不同能力 | 先列你常用类型；基础文件和图片优先，其余按实际需求验证 |
| 32 | Files 成果集合 | 每个任务的报告散在聊天里时，希望有一处集中查看全部报告、附件和版本；它不同于项目代码目录 | 首版做一个按任务筛选的成果列表 |
| 33 | 文件选区评论 | 高亮报告的一段或代码某几行，留言“这里不合理”，让 AI 对着准确位置修改 | 首版可后置；如果报告评审是主要用途，可提前支持 Markdown/代码行 |
| 34 | 报告导出格式 | 最终报告仅在应用里阅读/导出 Markdown，还是要交付 Word、PDF、分享图片？多格式会增加渲染和验收工作 | Markdown 为基础；你经常对外交付的格式优先增加 |

## 九、你不需要代替开发者做的决定

数据库用什么事务结构、如何防止重复派发、JSON 事件怎样解析、线程 ID 怎样分配、Windows 怎样管理进程树，都由开发者按已确认的产品行为实现并测试。

同理，具体重试秒数、列表分页数、缓存大小、事件批处理频率可以先作为工程配置，不需要逐一请你选择。只有当它们体现为你能感知的行为，例如“任务多久自动停止”“关闭窗口会不会继续花费”，才纳入本清单。

保护用户既有文件、不伪造共识、不把失败标成成功、不泄露凭据、消息不串线程等属于基本正确性，不作为“可不可以做坏”的选择题。

## 2. 第一批：现有设置页的版式与交互整理

**这一批不新增面向用户的配置能力，不改分类，只让现有五个分区好读、好用。** 五个分区指：通用、执行工具、设备与局域网、归档管理、诊断与帮助。已列明的功能例外只有三处：「日志保留」补真实可选值或降级只读（§2.4）、「打开目录/复制路径」可操作项（§2.5）、「原型工具」折叠组（§2.6）；除此之外不添新控件。

### 2.1 宽度与居中

- 应用设置容器应在**主内容区域内居中**，常规设置正文有**自己的最大宽度**。
- 参照物已存在：项目设置页用 `.pset { max-width: 920px }`（[components.css:620](../../hifi-prototype/src/styles/components.css:620)）。应用设置当前只有 `.settings-layout { grid-template-columns: 200px minmax(0, 1fr) }`（[components.css:843](../../hifi-prototype/src/styles/components.css:843)），`.settings-body` 无任何宽度约束（[components.css:937](../../hifi-prototype/src/styles/components.css:937)）。
- **具体数值实测后定**，施工时在以下窗口宽度各截一次图并记录实际正文宽度：1920 / 1600 / 1440 / 1280 / 1100 / 900。
- 窗口变窄时：控件能换行，**不挤压标签**；标签与控件不得重叠或截断到不可读。
- **表格与日志允许独立处理宽度**，不强迫目录树、运行记录表、验证矩阵与普通设置行共用同一种排版。宽表可保留自身横向滚动，不必为了对齐而压缩正文。

### 2.2 设置行版式

当前每一组设置是独立白卡，卡内再套说明块、等宽目录树、警示块，读起来是文档而非设置。需要引入稳定的**设置行**基元：

```text
开机自动启动                          [ ●   ]
登录系统后自动运行

关闭窗口时继续在托盘运行               [     ]
关掉窗口不结束任务，可从托盘重新打开

重启后自动继续未完成的任务             [ ●   ]
关闭时，重启后先列出可继续的任务让你确认
```

- **标签在左、控件在右**，控件右对齐形成可扫视的一列。
- 说明位于标签下方，**默认一到两行，允许自然换行**（见 §0 第 3 条）；更长的原理说明折进「了解更多」或详情层。
- 字号与灰度按实际阅读舒适度决定，**不为了区分层级一律缩小**。
- **固定控件列宽只适用于普通开关与短选项**。路径输入、认证配置、授权范围表单必须允许例外，按内容需要占宽。
- 一组设置**一张卡**，卡内多行用发丝分隔线（`--border-subtle` 类）分隔，替代「一行一卡 / 一组多卡」的现状。
- 当前值不再塞进 label 括号（如「深色外观（当前：浅色）」），改为独立值列。

### 2.3 归档管理双标题与筛选行

- **双标题（必修）**：`SettingsPage` 在 `section === 'archive'` 时渲染 `SectionHead title="归档管理"`（[SettingsPage.tsx:562](../../hifi-prototype/src/pages/SettingsPage.tsx:562)），紧随其后的 `ArchiveManager` 又渲染一个 `.page-head` 大标题（[ArchivePage.tsx:89](../../hifi-prototype/src/pages/ArchivePage.tsx:89)）。同一屏两个标题、两段副说明。
  - 修法：`ArchiveManager` 增加「嵌入模式」参数，嵌入时不渲染自己的 `.page-head`，由外层设置分区标题承担；独立 `/archive` 路由仍保留完整页头。**不得复制出第二套归档组件或第二份状态。**
  - **嵌入模式下筛选动作不得跳出设置路由**：「清除项目筛选」（[ArchivePage.tsx:102](../../hifi-prototype/src/pages/ArchivePage.tsx:102)）与项目下拉（[ArchivePage.tsx:124](../../hifi-prototype/src/pages/ArchivePage.tsx:124)）现在直接 `navigate('/archive…')`，嵌入时点这两个控件会把用户拽出设置页。嵌入模式下搜索、项目筛选、清除筛选一律组件内状态驱动、只更新局部渲染；只有「跳去项目/房间」这类明确钻取才允许导航。
- **筛选行布局**：当前搜索框很窄、项目下拉拉满全宽，同一行控件宽度不统一（截图 4 可见）。按 §2.2 的控件列规则统一，窄窗下允许换行。

### 2.4 区分「可操作」与「仅模拟」

同一个页面上，点了就弹 toast 的按钮和真正改状态的开关长得一模一样，这是设置页最不该有的问题。逐项处理：

| 位置 | 现状 | 处理 |
|---|---|---|
| 诊断 → 「日志保留：14 天」 | 点击 toast 说「可在此调整」，但**没有任何调整入口**（[SettingsPage.tsx:412](../../hifi-prototype/src/pages/SettingsPage.tsx:412)） | 二选一：① 就地给出真实可选值（如 7/14/30 天）并写入 mock 状态；② 若本批次不做，降级为**只读展示**，去掉按钮外观与「可在此调整」的措辞 |
| 执行工具 → 「重新检测」「连接测试」「认证方式」 | 仅 toast | 保留按钮外观，但**必须带「原型模拟」标记**，或在无真实能力时明确禁用并说明原因。不得给假成功 |
| 通用 → 三个系统开关 | 仅改内存值 | 已有「原型模拟」Tag，保留；说明文字同步（见 §2.5） |

要求：**每个控件都能回答「能不能改、改了影响什么」**。原型无法模拟的能力明确禁用或标注，不用 toast 冒充已生效。

### 2.6 危险操作按风险分级

不规定警示色「只能出现在确认弹窗」（见 §0 第 4 条）。规则：

- **普通说明**用中性色，去掉大面积常驻橙色块。
- **删除、撤销、重置**等操作使用明确的按钮语义（danger 变体）。
- **真实影响权限、数据或执行行为的风险，在操作旁就地提示**——例如「配对的设备拥有和本机一样的权限，能发任务、停止任务、改设置」（[SettingsPage.tsx:251](../../hifi-prototype/src/pages/SettingsPage.tsx:251)）保留，但改为**简短、就地、中性容器**，不必占整块橙色面板。
- **「重置原型数据」移进「原型工具」折叠组**（目的地定案：放「诊断与帮助」分区底部，第二批重排后随迁「帮助与关于」底部；默认折叠，不用隐藏 URL 参数，也不设不存在的「开发入口」）。理由：它是截图、演示、复现问题的常规动作（`resetStore()` 连导航偏好一起清，见 `navPrefs.ts` 的注释），既要和日常设置分开，也必须一眼能找到。组内至少含「重置原型数据」，可顺带收纳其他原型专用动作。
- 通用分区现有的「高级操作」橙色分隔带改为中性容器 + danger 按钮；「退出」的说明文案保留（窗口关闭 vs 真正退出是有效信息）。

## 3. 第二批：重排为七类，补上通知与外部 AI 连接

### 3.1 七个一级分类

| 一级分类 | 放什么 |
|---|---|
| **通用** | 【迁】开机启动、窗口关闭行为、启动恢复；【新·批三 §4.3】应用级运行并发；【暂缺】基础输入偏好（发送快捷键） |
| **外观** | 【迁】主题；【暂缺】跟随系统、字号或界面缩放、消息显示密度 |
| **通知** | 【新·批二 §3.2】通知事件、通知渠道、声音、免打扰 |
| **AI 工具** | 【迁】工具安装与检测、认证与登录、连接配置；【暂缺】运行资源；【迁】版本/协议/验证记录折叠进技术详情 |
| **连接与设备** | 两个**独立分组**：【迁】访问众说的设备 / 【新·批二 §3.3】外部 AI 连接（MCP） |
| **数据与存储** | 【迁】数据位置与占用、归档管理、已移除的项目；【新·批三 §4.2】备份与恢复 |
| **帮助与关于** | 【迁】故障诊断、日志导出与保留、错误码速查（折叠）、原型工具折叠组（§2.6）；【新·批三 §4.4】版本与更新、使用帮助、反馈 |

**图例**：【迁】现有项原样搬家，不改行为；【新】新增项，标注规格出处与批次；【暂缺】无状态、无规格，**本批不显示**。

**施工铁律**：【暂缺】项不得做成占位控件、空表单或「敬请期待」空页——`appSettings` 现在只有三个布尔（`types.ts:1212` 附近：`launchAtLogin` / `keepInTray` / `autoResumeTasks`），全库没有发送快捷键、消息密度、界面缩放的任何状态。第二批只搭分类骨架；要做，先按 §4 的「用户操作/保存结果/生效时机/失败处理」四件事补规格。第二批落地的【新】项只有通知（§3.2）与 MCP（§3.3）。

**两个具体取舍**：

- 归档管理**保留现有页面与快捷入口**，但归入「数据与存储」，不再独占一级分类。三个入口（`/archive`、应用设置、项目 ⋯）继续共用同一个 `ArchiveManager`。
- 设备访问与外部 AI 连接共用「连接与设备」入口，但**必须分别展示权限说明**。当前设备配对（§8.3）与 MCP 的范围授权（§31.5）是两套权限模型，**不得混成一张模糊的「已连接客户端」列表**。

> 这两条是 2026-09-26 设置页评审留下的待拍板项（归档降级、设备与 MCP 合并一级入口），本任务书按上面的缓冲条件定案，施工照此执行，不再等确认。

### 3.2 通知（设计已要求，原型缺失）

依据 §27.11 ATTN-05：主设计已收录「Settings → 通知」。当前原型零实现。

- **至少做到**：能展示并**模拟修改**偏好——不是只有一个「暂无内容」的空页。
- 优先覆盖四类事件：需要审批、任务失败、任务完成、被提及。
- 渠道、声音、免打扰时段作为体验补充。
- **不得宣称已接入真实推送**。ATTN-06 明确「通知、人的 Activity、Agent inbox delivery 是不同机制」，界面不得把通知开关等同于执行授权。
- **单一真相源（必守）**：通知偏好与房间静音、线程关注读写**同一份订阅状态**（`Room.tsx:1250` 的注释已写明「关注/静音读的是同一份订阅状态……不会各存一份」），不得另建第二份「通知订阅」状态。覆盖关系按「应用级全静音/免打扰 > 房间静音 > 线程关注」，并在界面文案里写清；「服务器级全静音」是 ATTN-05 明文要求，须做成全局开关。
- **事件分类的完整口径**：ATTN-05 的完整清单是私信、已加入频道消息、关注线程回复、未加入频道提及；上面的四类是原型优先子集，界面文案不得暗示这就是全部。

- **至少做到**：能演示**创建 → 查看范围 → 撤销**的完整流程。

## 4. 第三批：补齐配置能力

每一项都分别定义**用户操作 / 保存结果 / 生效时机 / 失败处理**四件事，不写「支持配置」这类空话。

### 4.1 AI 工具接入与认证

从「检测报告」改为「配置流程」。正文只回答四个问题：**我怎么接入一个工具？现在登录的是谁？用订阅还是 API 配置？为什么不能用？**

- 工具列表：名称、安装状态、认证状态、当前是否可用。
- 工具配置：可执行文件位置、认证入口、支持的连接配置。
- 故障处理：缺安装 / 未登录 / 认证过期 / 连接失败，各自给对应动作。
- 影响范围：哪些成员使用这份配置，修改后何时生效。
- 技术详情：版本、协议能力、验证记录（含 C0—C4），**折叠查看**。

**保留边界**：应用设置管理「可供成员使用的工具与连接配置」；**具体成员用哪个模型、承担什么职责，仍由成员管理负责**。不得出现第二处模型设置。

### 4.2 数据管理

依据 §12.5。当前只有一段目录文字。

- 实际数据位置、打开目录、占用情况（**原型阶段标注为模拟值**）。
- 配套的备份与恢复入口；沿用 §12.5「使用 SQLite 备份接口或等价一致性备份方案，不能只复制活跃 WAL 主文件」的口径，界面不得承诺「复制文件即可备份」。
- 清理前说明**对象与影响**：清理应用成果 ≠ 删除用户源目录，两个动作不得混成一个（§12.5）。
- 归档管理与已移除的项目在此分区内保持可达。

### 4.3 运行与资源限制（**已有设计依据**）

依据 §10.3，原文：「**建议起始值**：全应用最多 3 个活跃模型 turn；单成员 1 个；单 provider 可单独限额。上限均可在设置中配置（2026-09-17 确认默认值，决策 12）」。

**这是已定案的配置项，本文明确修正前一轮「等定案」的说法。** 可配置性已定案（决策 12），但 **3 / 1 是确认的默认起始值，不是硬上限**：界面文案不得写成「全应用最多 3 个」这类不可改口径，默认值填 3/1、标明可改即可。排到第三批是**交付顺序**问题。落点：归「通用」分区（回答的是「整个软件同时跑多少模型调用」，与工具接入无关；§3.1 表中「AI 工具」的【暂缺】运行资源指工具进程资源，两者别混）。

界面必须让用户分清三者回答的是不同问题，不得因为都涉及「限制」就认定重复：

| 配置 | 归属 | 回答的问题 |
|---|---|---|
| 应用级运行并发 | **应用设置** | 整个软件同时执行多少个模型调用？ |
| 项目写入并发（`writeConcurrencyPolicy`） | 项目设置 | 这个项目同时允许多少个受管理任务修改文件？ |
| 任务预算 | 任务详情 / 输入区 | 这个任务累计最多使用多少调用额度？ |

界面文案需按上表口径写清，并在应用设置项旁**注明与项目级设置的分工**，避免用户误以为两处重复。

### 4.4 帮助与关于

应用版本、更新状态、版本说明、反馈入口、使用帮助。与诊断导出、日志保留、错误码速查合并为一个分区。分区底部保留「原型工具」折叠组（§2.6：第一批先进「诊断与帮助」底部，重排后随迁此处，不再另行搬动）。

## 5. 与项目设置、成员管理等入口的归属（不推翻既有决定）

[设置分离方案](./prototype-settings-separation.md) §3 的边界继续有效，**缺口不得靠把所有配置搬回应用设置解决**：

- **应用设置**：本机的软件行为、工具接入、通知、数据、外部连接。
- **项目设置**：这个项目的交付要求、协作限制、文件修改规则。
- **成员管理**：成员身份、职责、提示词、模型选择、工作空间和生命周期。
- **房间设置**：参与成员、房间规则、协调者、该房间的通知偏好。
- **任务详情**：这一次任务的预算、授权、运行状态和临时调整。

例如「某成员用哪个模型」不得变成应用级「默认模型」去掩盖；「我不想收到这个房间的消息」不应要求用户进入全局大表单里找房间。

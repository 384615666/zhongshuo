## 2. 交付目标

同一套共享预览组件覆盖以下场景，最多同时显示两个内容区（应用导航不计）：

| 布局 | 左侧 | 右侧 |
|---|---|---|
| L1 | 房间对话池/看板/文件 | 无 |
| L2 | 房间主池 | 回复串 |
| L3 | 房间上下文 | 文件 |
| L4 | 任务回复串/私信 | 文件 |
| L5 | 项目文件/Git 列表 | 文件/diff |

主池普通附件无 taskId 也能预览；从线程打开文件保持线程；文件可在同一合法可见范围内保留，左侧可切任务。私信与群聊 audience 不自动共享。

顶部目标：房间栏管房间，线程栏只有**一条紧凑导航**（收起/返回 + 回复/成果(讨论串为附件)/详情 + ⋯，2026-09-24 界面信息减负后不再有任务号/状态/图标组与顶部原消息两行；任务身份由输入区目标摘要承担、完整身份在「详情」分组内），文件栏有标签/版本/来源/引用目标/收起（视图切换走「阅读 ▾」菜单）。原有项目菜单继续在导航，项目全停继续在项目设置。不要引入重复设置入口或新的 AI 输入框。

## 3. 允许修改与边界

允许修改：原型 `src/`、必要的模拟数据与资源 fixture、相关脚本/测试、原型 README 及本次验证记录。必要依赖应最小化并更新锁文件，不能顺手升级整个项目。

不做：正式 daemon/SQLite/runtime 集成、真实模型调用、项目迁移、批量重排设计资料、Git 初始化/提交/推送/部署、重置用户工作区、修改其他 AI 的设计稿实现。无需新增 Electron 高权限读取接口来完成 mock 交互。

可用真实静态文本/图片 fixture 验证读取和显示；正式磁盘授权、Office 转换、视频解码等尚未接通的部分，显示明确能力状态，不能用假正文假装真实解析。数据模拟与 UI 真可操作是两回事：按钮、标签、导航、引用草稿必须真能操作。

## 5. 分阶段施工（通过后继续）

### A. 资源契约和最小状态实验

1. 增加明确的 mock Attachment/ResourceRef、Message 与资源的关联、origin/openedFrom、固定版本和 audience。无任务主池附件合法，不能伪造 taskId。
2. 新建结构化 DraftReference；旧附件仅有 name/size 且无内容时保留提示“需重新附加”，不猜路径生成资源。
3. 用同一份 Markdown fixture 贯通主池、线程两个文件入口。实际点击打开预览，左侧目标正确。
4. 贯通 L2→L3/L4→收起/关闭恢复，主池和线程各有未发送草稿。L3 有“继续 #14”直接入口。
5. 实现容器空间测量和候选 L4 分配。保留 L2 MAIN_MIN=420、THREAD_MIN=380；不要全局改成 360/440。
6. 验证 1280/1372/1100/900px、长标题、两行摘要、多行草稿、长代码及表格。失败时先修复，不绕过最小宽度或缩小文字。

A 阶段先沿用旧顶部，避免一次改布局、模型、路由和全部按钮。通过这道检查后继续 B，不只交实验截图结束任务。

### B. 完整原型交互与顶部

1. 工作区状态与业务实体分开：上下文、预览、发送目标、布局偏好、请求代次分别管理。
2. 完成 L1—L5、DM、成果/房间文件、项目目录/Git、搜索/收藏来源及返回。用同一 PreviewPane，不保留重复独立预览壳。
3. 文件多标签、同版本去重、不同版本并存、准确来源、当前文件变化提示、固定版本引用。
4. 区分收起区域/关闭标签/关闭所有/放大/回来源；实现有条件恢复快照，主动切过上下文不能跳回旧任务。
5. 同步完整顶部：线程一条紧凑导航（收起/返回 + 回复/成果/详情 + ⋯）、待验收不被隐藏（详情分组内 + 回复视图的可见处理卡）、文件标签和阅读方式菜单。不重写已有验收或运行控制流程。该条的"线程标题与返回"以 2026-09-24 界面信息减负施工为准（`./prototype-ui-declutter.md`）：标题不再常驻顶部，改由输入区目标摘要与「详情 → 任务概况」承担。
6. 文件引用加入明确目标草稿；异步读取完成后仍插入点击时捕获的目标。源文件评论与当前对话引用分开，二者均固定版本。
7. DM 使用独立 conversationId/audience；切到群聊暂藏受限标签及名字，无授权不能复制私信正文。
8. 资源加载、失败、缺失、更新、不可解析和过大状态可操作；迟到响应不覆盖当前标签，关闭标签不被回包重新打开。
9. 单区域切换、导航临时隐藏、焦点返回、独立滚动和草稿恢复实现完整；隐藏消息不自动全读。

### C. 路由兼容、格式展示和回归

1. 修复 query 解析，使用 URLSearchParams 等完整解析方式；明确编码路径、资源和版本，URL 不携带执行命令。
2. 兼容 `/artifact/:id`、串内 artifacts 查询、`/project/:id/changes`、现有 DM 路由，保留来源搜索参数和返回锚点。
3. 后退/前进、刷新、项目切换恢复活动上下文与预览。URL 优先于旧偏好，不能猜同名目标。
4. 当前原型可真实渲染的 Markdown/文本/代码/图片/CSV/diff 优先实现；PDF/Office/HTML/视频按实际能力接入或给出可验证的“不支持/仅模拟”状态。保留七类附件和五类评论锚点模型，不因后端未接删掉发布需求。
5. 原型引用/评论可以写入 mock store，但必须真实反映在对应会话/版本上并标模拟，不能只 toast“成功”而对象没有变化。
6. 增加一份干净启动可重复的 fixture 场景：两个任务、主池无任务附件、DM 受限附件、两个文件版本、变化/失败/迟到响应。

## 6. 建议修改点

| 模块 | 职责 |

| `App.tsx`、`TitleBar.tsx` | 工作区宿主与导航开关；不在每页各建资源状态 |

| `data/types.ts`、store/actions、草稿模块 | 资源关联、版本、audience、引用持久化；模拟权限不冒充生产权限 |
| `lib/threadNav.ts`、`router.ts` | 规范路由和历史兼容，资源归属校验 |

新增模块名自行选择；不要为匹配本说明命名而做无必要的全项目重构。现有任务、权限、设置和 Git 功能不是本次替换对象。

## 7. 必须保护的不变量

- 主池仅原消息及聚合，任务全文只属于对应线程；未读和后台进度不串线。
- 切面板不是停止任务，打开文件不是执行、验收、提交或模型上下文授权。
- 主池、线程、DM 的正文、mention、附件、引用与意图草稿各自保存。
- 当前项目、可见项目与资源实际归属不能混用；来源和引用目标可以不同但必须明确且有权限。
- 历史版本、行/段落/CSV/HTML/时间锚点不自动漂移；读取当前文件不能覆盖已引用快照。
- Git 应用状态、任务交付验收、文件预览是独立维度；不添加一键危险回滚。
- 打开外部内容不执行脚本、不取得 Node/IPC 能力，不拼 shell 命令打开任意路径。

## 2. M0 最小真实闭环

M0 的目标是“文件夹 → 指定成员 → 真实工作 → 正确位置的结果”，不是一次完成所有界面入口。

| 顺序 | 对应包 | 必须真正接通 | 暂不能冒充的部分 |
|---|---|---|---|
| 1 | DEV-01 | 共用命令/结果/事件、conversation/MessageTarget、三模式路由、发送意图、权限状态与来源范围 | 不声称已启动 AI 或已写数据库 |
| 2 | DEV-02/03 | SQLite 迁移/事务/回执/outbox；可脚本化 fake adapter | fake adapter 是故障夹具，不能标真实 runtime supported |
| 3 | DEV-04/05、DEV-17 最小隔离、DEV-21-M0 最小合同 | 真实目录身份、同物理目录锁域、daemon 单实例、目标绑定、上下文范围、输出归属、停止代次及 DIRECT 输入输出合同 | 不能仅以路径字符串或前端过滤证明隔离 |
| 4 | DEV-06 与 DEV-17/21-M0 联合完善 | 在专用 fixture/独立测试会话接通固定版本的真实 runtime、实际权限和输入/输出；联合完成隔离及注入/续接验证 | 最小隔离先于真实调用；未验证档位禁用，失败不降级完全访问 |
| 5 | DEV-07 | 从 UI 打开目录、指定成员发送、流式回复、停止与重启看历史 | 内存种子不替代真实数据库；UI 文案不代替进程证据 |

以上是能力依赖，不要求每包所有工作完全串行。DEV-06 可先做受限的适配认证，但不能无隔离地发起真实调用；DEV-17 完整隔离和 DEV-21-M0 正式合同须在面向用户的 DEV-07/G3 开放前验证。

M0 首先开放 DIRECT；AUTO/DELIBERATE 的类型和路由预留在 DEV-01，但未实施时明确不可用。私信底层目标在 DEV-01 定义，完整对话执行在 DEV-22/M3；不能为了给 M0 加“所有入口可点”而用另一套临时私信模型。

## 3. 页面与真实能力的接入合同

| 原型入口 | 正式命令/数据 | 用户应观察到的真实行为 |
|---|---|---|
| 打开文件夹 | project.open；目录身份、项目/默认房间事务 | 重开同一物理目录定位已有项目；不擅自初始化 Git、不改项目文件 |
| 主池发送 | message.submit(room_root) | 保存根消息并建立准确线程；commandId 重试不重复发任务 |
| 回复串发送 | message.submit(thread) / 明确 task.steer | 目标来自提交时实体；切换界面不改变输出去向 |
| 一次性仅记录 | intent=record_only | 保存后意图复位；无任务/运行/预算占用，无 mention 派发 |
| 普通私信 | conversation.* + message.submit(dm) | 项目内一对一；同对话记住上文，新对话独立；无房间任务号；后台串行、可停、可恢复 |
| 停止 | task.stop(taskId,targetRunId,expectedStopGeneration) | 先 STOPPING，确认退出才停止；旧停止不伤新运行，停止不等于撤销文件 |
| 权限确认 | 经验证的 adapter 请求/答复 | 确认前无对应变更，拒绝不继续，过期按钮不能批准新请求 |
| 项目与应用设置 | 对应作用域命令 + expectedRevision | 保存绑定原目标；切项目不会把未完成保存写到另一个项目 |
| 文件/附件/共享预览 | ResourceRef、版本/hash、来源和 audience | 每个标签保留来源；跨会话私信资源暂藏；引用进入正确草稿而非直接发送 |
| 状态与未读 | domain_events + 读取投影 | 只有真实执行中才旋转；WAITING_USER/BLOCKED/REVIEW 静态；未读独立，不用任务状态推断 |
| 应用重启 | SQLite 历史 + 进程/会话恢复 | 历史存在；非终态运行显示中断与待继续，不自动继续花调用 |

正式 UI 不直接执行 SQL、拼 shell 或调用模型。Electron main/preload 只开放窄接口转发 daemon；`zs` 和以后 MCP 进入同一业务命令面，不能复制一套绕过规则的实现。

## 4. 后续施工的验收场景（本轮不执行）

每个场景应区分 UI 显示、持久化结果、真实 runtime 事件和项目文件变化，缺任一证据就如实标未验证。

1. 真实目录中放置已知 fixture，指定成员返回可核对的文件事实；显示明确来源，不能拿种子回答。
2. 在 A 任务等待时切到 B，A 的流式消息仍只落 A；两个任务的 ContextBundle/session 不能串线。
3. 连续双击/网络重试/提交后响应丢失，仍只有一份任务与派发；同键异参明确冲突。
4. 运行中停止，显示 STOPPING；进程仍存活时不能显示已停止或放掉写锁；旧结果不能使任务复活。
5. 关闭并重启应用，历史与运行状态从 SQLite 恢复；非终态待用户继续，队列不自动补跑。
6. 原生权限档位按 B6/RT-23 在真实适配路径认证，未通过保持禁用；mock 的确认卡不算通过。
7. M3 私信补验：同一成员两个独立对话、当前对话连续发送、停止后队列暂停、归档只读、附件/搜索/导出和通知一致限域。

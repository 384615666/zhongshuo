## 1. 先定性：这不是本次界面减负引入的回归

| 核对项 | 结论 |
|---|---|
| 私信输入区是不是减负时被删掉组件的？ | **不是**。私信页 `src/pages/Dm.tsx` 自己手写了一整套 `.composer` 标记（文本域 + 一枚「独立可见范围」chip + 发送），**从来没有复用共享 `Composer`**；该文件与减负开工前快照 `archive/ui-declutter-pre-20260924/src/pages/Dm.tsx` **逐字节相同**（`diff -q` 无输出）。也就是说"缺控件"是长期状态，不是这一轮改坏的。 |
| 设计要求私信有什么？ | §4.6：「私信沿用 §4.2 三模式，以该私信的参与者作为成员边界……无 @ 的任务进入 AUTO，由私信协调者接单；单个结构化 @ 进入 DIRECT；@全体或多个明确 @ 进入 DELIBERATE」「讨论消息只保存、不调用模型」。DM-02：「持久历史、线程、任务顶层消息、**附件及相同工具能力**，结果仅 audience 可见」。**（注：这两条已于 2026-09-25 按用户决定回写 —— 私信收敛为 1 对 1、不做 @ 路由，见设计报告 §0.21 与本报告 §6；此处保留的是当日核对时引用的原文。）** |

## 2. 改法

### 2.1 输入区改为与房间/线程同一个组件

`Dm.tsx` 不再手写输入条，改为渲染共享 `Composer`。私信特有的三件事由 props 承载、语义不变：

| 私信特有 | 承载方式 |
|---|---|
| 「独立可见范围」声明 chip | 新增 `scopeChip`（房间不传） |
| 「只唤醒 X；其他成员零调用」/「已归档：只读」说明行 | 新增 `statusNote`（房间那行已在减负中删除，私信保留的是**私信特有语义**，不是重复身份） |
| 归档态的「取消归档」 | 新增 `extraAction`（放进操作簇，与只读说明同处一地） |

成员边界（§4.6）在 `Composer` 内解析：`kind:'dm'` 时取该会话的 `memberIds`，@ 候选、方式推导、冻结名单都只在这条边界内计算；「@全体」的提示语也随之为"冻结该私信全部启用成员"（房间仍是"当前房间启用名单"）。

于是私信输入区获得了与房间同源的一套控件：**任务/讨论、方式芯片、附件、@提及、预算 chip（DELIBERATE）、权限档位（四档，含未验证档位不可选）、本次运行设置（方式/预算推导/权限三节）、发送/写入**，以及草稿按会话持久化（`draftKey = dm:<id>`）。

### 2.2 附件真的落地（房间/线程/私信统一）

新增 `src/data/attachments.ts`：

- `mockAttachmentDescriptor(index)`：输入区那枚芯片的体积**取自将要落地的同一份内容**（不再出现"芯片说 128 KB、点开说 11 KB"的自相矛盾）；
- `materializeAttachments(attachments, target, messageId)`：发送时生成 `PreviewResource`（`kind:'attachment'`，`origin`/`audience` 按真实归属写入：房间附件 ↘ `audience:{kind:'room'}`；私信附件 ↘ `audience:{kind:'dm', conversationId, memberIds}`）＋ `MessageAttachment` 链接；内容按扩展名映射到原型**真能渲染**的 fixture（png/md/csv/txt），其余落 `unsupported(not_connected)`，不拿假正文冒充解析。hash 由内容推导、体积按内容真实字节数计算。
- 接线点：`submitMessage`（线程跟进、主池讨论、主池任务三条路径）与新增的 `submitDmMessage`。

发送后消息上出现真实附件条目，点开进共享预览（标签 `附件-1.png v1`、来源标注「私信 · 会话名 · 模拟资源」）；**切到群聊该标签暂藏且不泄露文件名**（§17.9 第 7 条，由 `verify-dm-composer` 断言）。

### 2.3 私信发送语义（新增 `submitDmMessage`）

- 讨论意图：只保存消息（不唤醒成员、不调用模型），附件一并落地；
- 任务意图：按 §4.6 规则推导方式（无 @ → AUTO 由协调者接单；单 @ → DIRECT；@全体/多 @ → DELIBERATE 并冻结该会话名单），把方式、名单、权限档位、方式开关、audience 与 commandId 写进 `LOCAL_ONLY:` 诊断，并**明确提示"私信任务提交接口未接通（清单 R4），未创建任务号"**；界面不出现任务卡与任务号徽标；
- 归档私信：直接拒发并提示只读；同一 `commandId` 不重复发送（RT-01）。

### 2.4 回归抓到的真实退化（已修正）

第一轮跑 `verify-round14` 时 **16/17**：`② 已归档会话为只读（输入框禁用）` 失败 —— 我第一版只做了"能写但发不出去"，把原来的**输入框 disabled** 弱化了。归档是只读（房间里归档后整个输入条会被只读面板取代），因此：

- 新增 `inputDisabledReason`：私信归档时 textarea 直接禁用 + 占位写明原因；
- 并且发现只读态**在视觉上与可写态一模一样**（截图佐证：只能靠 placeholder 文字判断），补了 `.composer-input:disabled` 的字色与 `not-allowed` 光标；
- 用例侧：**恢复**原断言（不禁用② 的标准），并在新套件里补"只读色 ≠ 可写色、光标 not-allowed"一条。

### 2.5 顺带修掉的两个真实缺口

1. **「引用到私信」此前是空操作**：预览的「引用到 …」派发 `zs:focus-composer`，而全仓只有共享 `Composer` 消费它（`takePendingQuotes`）——私信没有共享输入区，所以从文件引用到私信的片段**静默丢弃**。现在私信渲染共享输入区，引用会真正进草稿。
2. **私信草稿不再随会话丢失**：原来是页面内 `useState`（切走/刷新即丢），现在按 `dm:<id>` 持久化，并与房间同一套"成功不占位、失败必须提示"的策略。

## 5. 未验证 / 不适用 / 诚实边界

1. **没有真实文件选择器与摄取**：附件仍是"模拟副本"（内嵌 fixture 内容 + 模拟体积/hash），预览照常打「模拟资源」标签；真实拖入/选择/粘贴图片未接通，输入区 tooltip 已按此改写，不再宣称"摄取为本机不可变副本并记录 hash"。

3. **`#N` 是消息序号**：不是任务号（房间/私信同款），验收时不要把它读成任务编号。
4. **未跑**：真实系统级 150% 缩放与触屏宿主（与上一轮相同，仍属未验证）；`verify-visual.mjs` 的 1 项仍是脚本自身条件跳过。

## 6. 2026-09-25 收敛：私聊做减法（取代 §2.1 的私信 props 与 §2.3 的私信发送语义）

用户原话：**「我感觉现在的私聊太重了，去掉小群功能吧，也不需要区分什么任务/讨论，@也去掉，像『只唤醒 Claude；其他成员零调用』、『独立可见范围』这种描述也去掉」**。

### 6.1 改法

| 去掉的 | 怎么去 | 留下的边界 |
|---|---|---|
| **小群** | 新建私聊弹窗从"多选（多个成员即小群）"改为**单选 radio**；`defaultTitle` 不再生成"… · 小群"；种子 `dm_4` 从 `[Codex, Codex#2] · 小群：周报分工` 收敛为 1 对 1「Codex · 周报分工」，其消息里两位发言人也合成为 Codex 一人（避免"参与者之外的成员在会话里说话"） | 同一个成员仍可有多条私聊；消息/附件的 audience 归属逻辑不变（§17.9 第 7 条照旧） |
| **任务/讨论** | 私信不再渲染意图切换（`Composer` 新增 `showIntentToggle`，私信传 `false`）；`submitDmMessage` 去掉 `intent` 参数与"只保存不调用模型"分支，发送即"把消息发给该成员" | 房间/线程的任务/讨论语义**完全不变**（同一组件的另一个分支） |
| **@ 提及** | 私信不再渲染 @ 按钮与提及弹层（新增 `showMentions`，私信传 `false`）；输入 `@` 不再弹候选 | 私信发送不再带 mentionIds；房间/线程的 @ 与方式推导不变 |
| **说明性文字** | 输入区不再有「独立可见范围」chip 与「只唤醒 X；其他成员零调用」状态行（相应 props 直接从 `Composer` 删除，不做保留）；**会话头部的「独立可见范围：… 只有这些参与者能看到这个会话」面板一并删除**；空态文案改为一句"直接发消息给 X 即可" | 私密性**没有变成假的**：消息与附件仍按该会话 audience 隔离，只是不再用一行说明文字去讲它 |

保留：**附件、权限档位、本次运行设置、发送**，以及归档态的「取消归档」与只读视觉。

### 6.2 顺带把"说实话"的位置挪对

私信不分任务/讨论了，但"任务号不伪造"这条没有变：原来写在发送 toast 里（含"清单 R4"字样），现在收进**「本次运行设置`」**，并且**去掉了内部条目引用** —— 产品界面不写「R4」「§x.y」（这是减负那轮已经立下的规矩，我第一版又犯了一次，视觉核对抓出来）。现在是：

> 私信暂不创建任务：这条消息只发给该成员，不占用任务预算。

（原来那节会显示 AUTO 的"最多 20 次"，那是房间任务的预算公式，私信里既没有任务也用不上它。）「本次方式」一节也换成私信口径："私信只有一种方式：把这条消息发给这个会话的成员，不涉及房间里的其他人。" 发送后的提示简化为「已发给该成员（含 N 个附件）」。

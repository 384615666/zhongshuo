# 原型修改方案：项目设置与应用设置分离

2026-09-21，第十六批。依据：[主设计 v1.14](../zhongshuo-development-design-v1.md) §17.8、RT-27。用户要求“项目的设置合并一个页面，每个项目单独入口，不与整个软件设置混在一起”。本说明可直接交给原型实施 AI；本轮只交付文档，未修改原型。

保留已实现的导航、多项目、可选任务验收、Git 和 Runtime 能力。修改范围为 `hifi-prototype/` 的入口、设置页布局、mock 保存、路由与相关回归，不接真实系统配置、文件修改或模型调用。

## 1. 最终入口

```text
主侧栏
搜索与收藏
文件与 Git
任务看板
成员管理

项目
  众说          当前  ⋯  → 项目设置
    # 开发大厅
  docs                ⋯  → 项目设置
    # 文档整理

────────────────
待我处理
设置                     → 仅应用设置
```

- “⋯”是独立按钮，打开菜单不触发项目切换、房间跳转或折叠。选择其中“项目设置”才聚焦该项目并打开设置页。
- hover/focus-within、菜单打开及当前项目设置页时显示按钮；键盘能访问，触屏下常驻可见，不只依赖鼠标悬停。
- 项目设置所在项目标记“当前”，菜单项显示当前位置；底部“设置”此时不高亮。应用设置页才高亮底部“设置”。不要让两个入口同时看起来是当前页。
- 不新增第五个顶部功能入口，不再在应用设置里保留一份项目设置入口或切换标签。

## 2. 项目设置：一个项目、一张页面

路由：`#/project/:projectId/settings`。标题使用项目名，附真实项目路径；不要放项目选择下拉，也不要再放一个页内左侧分类栏。全局主侧栏保留，可从那里或顶栏切项目。

```text
众说 · 项目设置
D:\zhongshuo

任务交付
任务验收                              [开启]
任务交付后需要你确认，仅影响新任务。
1 个已有任务等待验收 → 查看

协作限制
成员无响应后继续                       [20] 分钟
单次分析最长运行                       [20] 分钟
单次修改最长运行                       [60] 分钟

文件修改
同时修改文件的任务
● 一个任务（推荐）
○ 多个任务
  选中多个时再显示：最多 [2] 个
  同文件并发可能需要手动处理冲突。

当前有 1 个任务正在修改文件 → 查看运行详情
                                      已保存
```

此处数值为现有默认值示例，实际读取对应项目状态。缺席等待与运行时限仍是不同设置，不能合并成一个“超时”；只说明用户可见作用，内部字段名不常驻。

### 内容归属

| 项目设置保留 | 处理方式 |
|---|---|
| 任务验收开关 | 沿用 v1.12 的可选验收规则与旧任务策略；只影响新用户任务 |
| 缺席等待与单轮运行时限 | 同一“协作限制”分节，保留各自现有字段及生效规则，不把全局并发槽放进项目页 |
| 单写者/并行写入及上限 | 同一“文件修改”分节；互斥单选同屏，选择并行时展开上限及简短影响说明 |
| 已存在的项目默认项 | 放入其所属分节，保留已有行为；不要顺手新增默认模型/默认权限等尚未定案的配置 |
| 当前写入情况 | 简短状态 + 运行详情链接，不展示大张只读表或内部锁域 ID |
| 成员设置 | 保留成员管理入口，需要时链接过去，不复制一套成员列表 |

单写者说明建议：“减少任务之间的并发冲突；其他写入任务排队。撤销前仍会检查文件变化。”禁止出现“撤销一定可靠”。同目录外部编辑、原有修改保护、并行归因及撤销降级的程序边界保持不变。

## 3. 应用设置：只管整个软件

底部“设置”打开 `#/settings?section=general`，标题为“应用设置”。可保留现有左侧分类与右侧内容，但只放以下应用级分区：

```text
应用设置

通用              启动、托盘、外观、数据位置等已有选项
执行工具          Codex / Claude 的检测、登录、能力与诊断
设备与局域网      配对与已连接设备
诊断与帮助        日志、诊断导出、可展开的错误码速查
```

- 删除“当前项目”导航组、项目选择器、“任务与协作”“文件写入安全”项目分区及所有相关开关。
- Runtime 原组件继续复用，只在应用设置中呈现；登录/认证状态不因切换当前项目复制或重置。
- 将现有“错误码速查”并入“诊断与帮助”，旧链接可直接展开并定位到速查区域。
- 无项目时应用设置照常可用。应用页不显示“正在修改众说设置”等项目文案。
- 提醒继续放在待我处理，不搬回设置；成员配置仍归成员管理。

## 4. 表单样式与保存方式

1. 项目页内容宽度控制在约 800—960px；窄屏自适应。名称与一句说明在左，开关/输入在右，小屏可自然换行。不要用一行小开关配一整屏宽的大卡片。
2. 任务验收常驻说明只讲作用及“仅影响新任务”。旧待办用一条可点击提示；迁移说明是可关闭的中性提示，不作为永久橙色警告。详细规则放“了解更多”，不把设计文档全文贴进页面。
3. 不在普通设置正文显示 `turnDeadline`、`writeConcurrencyPolicy`、`attribution=ambiguous`、§/RT-/DEV-/M3 等内部字段与编号。追溯放在代码注释、交接文档和诊断中。
4. 沿用即时保存，不新增整页“提交设置”的流程。开关/单选有效操作后更新对应 store，并反馈保存状态；不能固定 checked、点击只 toast 而实际不改变。
5. 数字输入保留编辑态，允许清空或逐位输入；失焦/Enter 后再校验范围并保存。无效值不提交，显示行内错误，Escape 恢复已保存值；禁止每输入一位就强制变默认值或重新挂载导致失焦。
6. 离开时无效草稿不写入、不带到别的项目，返回显示已保存值。有效提交绑定原页面 projectId；保存失败不报成功，错误属于原项目，不污染当前新页面。
7. 原型修改 mock 状态并明确原型边界；没有真实桥接的系统开关不能声称实际改变了开机启动/系统服务。若能力尚不可模拟，明确禁用而非给假成功。

本包不新增审批。原有权限与有效策略继续执行；设置位置变化不替代任务验收、Git 授权或原生审批。

## 5. 路由与项目切换

先解析和规范化 URL，再决定是否同步当前项目。当前 App.tsx 中“任意 query.projectId 都当成焦点”的逻辑须调整，不能继续作用于应用设置链接。

| 路径 | 行为 |
|---|---|
| `/project/A/settings` | 校验 A 后只加载 A；同步焦点，必要时将 A 加入可见集合 |
| 项目设置页从顶栏/侧栏项目名切到 B | 进入 `/project/B/settings`，保持设置功能；点击 B 的房间则进入房间 |
| 应用设置中切换当前项目 | 应用页内容及配置不变，只允许全局焦点变化 |
| `/settings?section=project或collab或budget&projectId=A` | replace 至 `/project/A/settings?anchor=collab`，同页定位到任务/协作分节 |
| `/settings?section=write&projectId=A` | replace 至 `/project/A/settings?anchor=write` |
| 项目旧链接未带 projectId，或仅 `scope=project` | 有有效当前项目才填入并规范化；无当前项目提示从项目菜单进入，不选择 projects[0] |
| 项目旧链接显式传入不存在/无权访问的 ID | 报错且没有写入控件，不当作参数缺失，不回退其他项目 |
| `/settings`、`section=app或general` | 规范为 `section=general`，删除多余 projectId，不据此切项目 |
| `section=runtime或lan或diagnostics` | 保留应用分区，删除多余 projectId；`/runtimes` 继续跳 runtime |
| `section=errors` | 跳 `section=diagnostics&anchor=errors` |
| `section=reminders` | 维持现有跳待我处理行为 |

表中的“或”为枚举候选，不是 URL 内容。已识别的 section 优先决定范围，只有缺少 section 才使用旧 scope=project；未知 section 给出说明，不据此修改项目。anchor 只滚动/展开分节，不产生第二张项目设置页。旧链接跳转使用 replace，前进/后退不应循环。

设置写入必须以经校验的路由项目为目标。删除现有 `find(...) ?? projects[0]` 式项目回退；只认 A 时不能误改第一个项目。目录失效但项目记录仍存在可显示历史配置及重定位提示，与“项目不存在”分开处理。A 请求返回时只更新 A 的 store/cache，不刷新成 B 的成功提示或覆盖 B 的字段。

## 6. 建议修改位置

- `src/pages/SettingsPage.tsx`：提取项目表单与应用分类，保留应用入口兼容；不要在同一页面用 query 切项目/应用两个大范围。
- 可新增 `src/pages/ProjectSettingsPage.tsx`：接收明确 projectId，渲染一个分节表单。子分节组件保持稳定定义，避免输入时卸载重建。
- `src/App.tsx` / router / navigation actions：项目行菜单、新项目设置路由、设置高亮与旧链接规范化；只在项目设置路由同步项目焦点。
- 现有 project/store actions：复用 setTaskReviewEnabled、setWriteConcurrencyPolicy、updateLoopSettings；检查绑定的 projectId。应用配置继续使用应用状态，勿创建新的重复配置来源。
- 现有 `shot-settings.mjs`、设置/导航验证脚本：更新路由与断言，不继续要求应用设置包含项目选择器。

修改前核对其他会话的新代码，不按旧行号覆盖文件。不重做侧栏四入口顺序，不拆散文件与 Git，不恢复独立 Runtime 或 commit 验收。

## 7. 原型验收（RT-27）

1. A/B 各自有“⋯ → 项目设置”；展开菜单不切换，点设置才正确进入目标。
2. 项目页标题/路径准确，一张页面包含三组设置，无页内项目下拉和第二级分类导航。
3. 改 A 的验收/时限/写入策略不影响 B；A→B 快速切换、迟到返回和数字草稿不会串项目。
4. 项目页不高亮底部设置；应用设置高亮底部入口，不显示任何项目选择器/项目表单。
5. 无项目可用时仍能进应用设置与 Runtime；不存在/无权限的项目设置不回退第一个项目。
6. 原 collab/write/project/budget/app/general/runtime/lan/diagnostics/errors/reminders 链接按表兼容；带无关 projectId 的应用链接不改变焦点。
7. 开关可真实改变 mock 值，数字输入不中途钳制、不丢焦点，无效值不写入；反馈准确，无仅 toast 假成功。
8. 旧项目迁移提示不常驻警告，旧待验收仍保留；新项目默认及只影响新任务规则保持 RT-25。
9. 单写者不承诺可靠撤销；并行互斥选项同屏，上限/影响只在需要时展开；运行详情仍可达。
10. Runtime、配对、错误码、诊断等能力仍可访问；纯入口变更不冒称真实认证通过。
11. hover/键盘/触屏能访问项目菜单，短窗表单可用；旧导航 RT-26 与 Git/验收 RT-24/25 不回归。
12. 跑 build 与相关 UI 回归，提供项目 A/B、应用通用/Runtime、无效项目空态截图；只报告实际执行结果。

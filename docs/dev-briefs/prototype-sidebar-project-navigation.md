# 原型修改说明：侧栏、多项目导航与文件/Git 合页

决定：2026-09-20，第十五批；文档整理：2026-09-21。依据：[主设计 v1.13](../zhongshuo-development-design-v1.md) §17.1、§17.7、RT-26。用户已确认本次顺序与方向。本说明中的“看板分组”指**按项目分组展示任务**，不取消任务原有的状态分组。

交付范围：修改 `hifi-prototype/` 的导航、页面壳、mock 状态、路由与相关验证；不接真实文件系统扫描、Git 或模型执行，不改用户项目内容。保留已实现的[可选任务验收](./prototype-optional-task-review.md)。本文件是交接要求，不是原型已完成的报告。

第十六批覆盖（2026-09-21）：项目设置已从底部设置中拆出，采用“项目行 ⋯ → 独立项目设置单页”，底部只应用设置；具体布局、collab/write 等旧链接迁移以[设置分离方案](./prototype-settings-separation.md)及主设计 v1.14 §17.8 为准。其他多项目导航规则保留。

## 1. 最终导航

```text
顶栏：[ 众说 ▾ ]  D:\zhongshuo  main    当前项目活动 / 项目全停

侧栏（从上到下）
搜索与收藏
文件与 Git
任务看板
成员管理
────────────────
项目                      ← 仅此区域滚动
  ▾ 众说             当前
    # 开发大厅
    # 方案讨论
    私信
  ▾ docs
    # 文档整理
    私信
────────────────
待我处理                3  ← 固定底部
设置                      ← 固定底部
```

- 上部四入口顺序不可调换；不要再加“工作/功能”标题占高度。
- 项目只显示顶栏菜单中勾选的项目，按保存的顺序排列；切换焦点不自动重新排序。
- 房间/私信缩进在项目下。成员列表不再放侧栏；“成员管理”是唯一主入口。
- 不再出现独立的 Git、文件与改动、Runtime、全局私信主入口。
- 顶栏去掉重复的设置/待我处理主按钮；搜索快捷键可继续使用，跳转同一套搜索逻辑。
- 当前项目标记与当前位置高亮分开：在文件页，高亮“文件与 Git”，项目仍有“当前”标记，但房间不能也显示为当前页面。
- 上下固定区保持可达，项目多时只滚动中间；窄窗口折叠侧栏，不能把底部按钮挤出视口。

## 2. 顶栏项目菜单：显示多选，焦点单选

收起时仍显示一个当前项目名，可加小字“显示 N 个项目”，不横排所有项目名字。

```text
[搜索项目…]
显示在侧栏     项目
☑              众说     当前
☑              docs
☐              data-backfill
＋ 打开本地文件夹
```

1. 勾选框只控制侧栏显示；点击项目名称才切换焦点。使用分离的点击区域，checkbox 操作不能冒泡触发切换；键盘标签说明其作用。
2. activeProjectId 始终单值，visibleProjectIds 为有序去重数组。当前项目必须在可见集合中，不能直接取消，提示“切换到其他项目后可隐藏”。
3. 点击未勾选项目名或打开一个新项目：聚焦并自动加入可见集合，不清空其他选择。点击某项目的房间同样聚焦所属项目。
4. 首次使用只默认显示当前项目，之后恢复本人偏好；无项目时显示打开文件夹，不创建假 projectId。
5. 隐藏/收起项目不停止任务、不删除记录、不清草稿、不自动已读、不清待办，也不改 Agent 的参与名单或上下文。

只保留这一个可见项目选择器，侧栏顶部不要再增加“显示 N/M 个项目”的第二套控件。

## 3. 功能页范围

| 入口 | 默认展示 | 切换/定位规则 |
|---|---|---|
| 搜索与收藏 | 当前项目；页面内“搜索/收藏”标签 | 可显式切可见项目/全部项目；页头显示范围，结果带来源项目 |
| 文件与 Git | 当前项目；页面内“文件/Git”标签 | 首次文件，之后按项目记忆标签；页面项目切换与顶栏同步 |
| 任务看板 | 侧栏可见项目，按项目分组 | 可切单项目，再筛该范围内房间；单项目选择同步当前项目 |
| 成员管理 | 当前项目成员 | 页面项目选择同步顶栏与路由；不展示混合项目成员名单 |
| 待我处理 | 全部可访问项目 | 隐藏的项目也包含；卡片标来源，支持显式单项目过滤 |
| 项目设置 | 项目行 ⋯ 进入该项目的独立单页 | 不放页内项目下拉，路由绑定项目；项目切换遵循新设置方案 |
| 应用设置 | 底部设置进入，仅含应用/执行工具等全局配置 | 无项目选择器或项目表单；Runtime 不因项目切换复制配置 |

“当前项目”和“聚合范围”必须分别呈现：看板选择多个可见项目时，顶栏仍显示一个当前项目。阅读聚合列表不改变焦点；点击具体任务才切到其来源项目。

## 4. 文件与 Git 合为一个页面

采用同一个页面壳与项目选择器，上方两个标签：**文件 / Git**。

- **文件**：可展开的项目目录树、选中文件预览、已有任务改动集与 diff、来源任务/交付链接。补齐可交互的目录树，不能只把当前改动集列表换个标题。原型可使用清楚标注的 mock 树，包括未修改文件、嵌套目录及空目录；非文本/大文件显示适当说明，不假装读取真实磁盘。
- **Git**：保留工作区改动、暂存/取消暂存、提交、历史、分支与远端、冲突等已有视图；“历史”属于 Git 内部导航，不另加第三个顶层标签。
- 共用 DiffView、ChangeSet/交付对象，不复制两份数据。按任务/改动集暂存仍保留，默认跳过用户原有改动；普通文件/代码块 Git 操作不要求先验收。
- 非 Git 项目的文件标签照常可用；Git 标签显示“尚未初始化 Git”及“返回文件”，不自动 git init，不把空态显示为已连接仓库。
- 标签记忆按 projectId 保存。第一次进入默认文件；显式 `tab=git` 深链优先，不被上次记忆覆盖。切项目后读取目标项目自己的记忆。
- 主入口已合并，不保留另一条“文件与改动”或“Git”侧栏入口。页面里的文件和 Git 数据仍分别表达，不能混淆应用、验收和版本历史。

## 5. 任务看板按项目分组

原型现有列表按状态分组但会混入不同项目；改成**外层项目、内层任务状态**，使用现有状态分组和卡片，不必重新设计全套看板。

```text
任务看板      范围：[侧栏可见项目 ▾]   房间：[当前范围全部 ▾]

众说（4 项）
  执行中 …
  待验收 …
  已完成 …

docs（2 项）
  执行中 …
  已完成 …
```

- 范围切换为“单个项目”时，显示项目选择；也能回“侧栏可见项目”。聚合状态不把 activeProjectId 改成数组。
- 默认列用户根任务；子任务在父卡展开/详情里看，不当作额外根任务重复计数。项目无任务时保留项目名与空态。
- 卡片显示项目名、房间或私信来源、编号、状态和负责人。两项目同名房间、同号 #1 也能区分。
- 房间下拉只取当前 scope 的房间；换 scope 后旧 roomId 不合法就清空并提示，不继续展示旧房间数据。
- 点击卡片用 task.projectId/roomId/conversationThreadId 导航，不能拿全局 activeProjectId 拼来源链接。后退恢复看板原 scope/筛选。
- 顶栏“当前项目后台任务”是单项目快捷入口，需显式带 scope=project 和对应 ID；侧栏主入口才默认 visible。
- 切到/收起某项目分组只是查看行为，不派工、不重建 WorkflowRun。

## 6. 成员、私信和设置

**成员管理**：页头增加项目选择，和顶栏同源。切换后仅显示目标 ProjectMember；同一个 profile/runtime 被多个项目使用时，成员身份和会话不能合并。无成员项目显示添加入口；关闭页面不停止成员任务。

**私信**：每个项目节点下各有入口，带 projectId；从成员详情发私信必须用该成员真实项目。不要继续依赖全局 /dm 隐含当前项目造成同名成员串线。私信仍沿用已有三模式与 audience 隔离。

**项目设置**：第十六批改为每个项目行的“⋯ → 项目设置”，独立单页，不放底部设置内。任务验收、协作限制与文件修改归该项目。

**应用设置**：底部一个“设置”入口，只含通用、执行工具、设备与局域网、诊断与帮助。执行工具（Runtime）保留安装检测、版本、连接/登录、能力认证等已有组件，异常通知直接打开对应区域；不展示当前项目分组或项目选择器。

当前任务验收规则保持上一份交接：可选、每份任务交付一条待办；合页/导航变化不恢复 commit 专属验收、不增加审批按钮。

## 7. 路由、个人偏好与异步边界

| 入口 | 目标路由示例 | 旧入口兼容 |
|---|---|---|
| 搜索与收藏 | `#/library?tab=search&scope=project&projectId=proj_A` | `/saved` → saved 标签；支持 scope=visible/all |
| 文件与 Git | `#/project/proj_A/files?tab=files` 或 `tab=git` | `/project/:id/changes` → files；`/project/:id/git` → git |
| 看板 | `#/tasks?scope=visible`；`#/tasks?scope=project&projectId=proj_A` | 裸 /tasks 默认 visible，房间过滤保留 roomId |
| 成员 | `#/project/proj_A/members` | /members 按当前项目规范化；/member/:id 按实体归属 |
| 私信 | `#/project/proj_A/dm?conversationId=…` 或 `memberId=…` | /dm/:memberId 先解析成员项目；/dm 按当前项目 |
| 项目设置 | `#/project/proj_A/settings?anchor=collab`，anchor 可省略 | 原 section=project/collab/budget/write 等按第十六批方案迁移；显式无效项目禁止回退 |
| 应用设置 | `#/settings?section=general`、`section=runtime` 等 | /runtimes → runtime，app → general；应用链接的多余 projectId 清除且不改变焦点 |

旧文件/提交/任务链接中的 path、changeSetId、taskId、commit 等有效定位参数必须保留，不能只打开页头丢失对象。URL 优先于 tab 记忆和旧 activeProjectId；兼容跳转使用 replace，避免后退循环。

打开隐藏项目的合法深链：先核对实体归属和访问 → 加入可见集合 → 聚焦项目 → 定位内容，并轻提示“已在侧栏显示项目…”。其他可见项目不清空。无权限/不存在的链接显示错误，不回退到当前项目的同号对象。

原型增加一个版本化的导航偏好对象，例如：

```ts
type NavigationPreferences = {
  version: 1;
  activeProjectId?: string;
  visibleProjectIds: string[]; // 有序且去重
  expandedProjectIds: string[];
  fileGitTabs: Record<string, 'files' | 'git'>;
};
```

可存独立 localStorage key；校验 ID、去重、补入当前项目、清掉已删除偏好，不重置其他原型数据。正式版由 navigation_preferences 保存 viewer/client 偏好，本包不实现数据库。换设备可以有不同侧栏，分享 URL 不携带可见项目列表。

单项目页统一走同一个项目切换动作；异步读取缓存按 projectId 标识。A 页面发出的请求在切到 B 后返回，只更新 A 缓存，不能盖住 B。房间/线程草稿按项目和目标保存，发送命令绑定输入框原目标；导航不能将 A 草稿发进 B。“项目全停”仍只停明确显示的当前项目。

## 8. 建议修改位置

- `src/App.tsx`：侧栏三段布局、顶栏项目菜单、高亮、旧路由兼容。
- `src/data/types.ts` / store / selectors：导航偏好、单项目聚焦动作、看板/成员/待办范围；只读聚合不得修改底层任务归属。
- `src/pages/pages-task.tsx`：TasksBoardPage 项目分组、范围过滤、来源正确的深链。
- `src/pages/pages-misc.tsx`：文件页壳/目录树、成员项目切换、设置嵌入 Runtime；已有交付与权限状态保留。
- `src/pages/GitPage.tsx` 与 `components/DiffView.tsx`：作为 Git 标签内容复用，避免复制 diff 或再次实现验收。
- 搜索/收藏/私信所在组件、导航测试和截图脚本：核对实际位置后更新；不要让测试继续断言旧侧栏入口必须存在。

当前原型已有其他会话修改，实施前以实际文件为准，保留已经完成的任务验收、Git 与线程改动。只列预计文件，不要求按旧行号覆盖。

## 9. 验收用例（对应 RT-26）

1. 上四入口顺序、下两入口固定；多个项目滚动/短窗口时均可达，无独立 Runtime/Git 重复项。
2. 勾选 docs 只增加侧栏项目，不切当前众说；点击 docs 名称/房间才切；当前项目不可隐藏。
3. 文件/Git 共用项目，tab 记忆按项目；旧 Git/ChangeSet 链接精确打开对应标签与对象。
4. 非 Git 文件树和预览可用，Git 标签给说明且无自动初始化。
5. 两个项目同名房间、同任务号仍分组清楚；卡片打开真实来源；筛选切换不保留无效 roomId。
6. 成员页面选 docs 后顶栏同步，成员只属于 docs；私信目标不串项目。
7. 隐藏项目仍有审批/阻塞/待验收时，待我处理计数不丢失；点卡自动补选正确项目。
8. 刷新恢复显示偏好；后退/前进遵循 URL；不存在项目/无项目/目录失效均有明确状态。
9. 快速 A→B 切换下 A 的迟到请求不污染 B；草稿、Git 按钮目标和项目全停仍准确。
10. Runtime 在应用设置内可正常使用，原 /runtimes 链接与异常入口有效；项目设置按第十六批 RT-27 独立入口，应用页不再混有项目配置。
11. 原可选验收 RT-25、Git 能力 RT-24 不回归；目录树/diff/看板不会生成重复验收。
12. 跑 build 与对应导航/交互检查，更新截图；只报告实际执行的结果，mock 不能作为真实文件/Git/runtime 认证。

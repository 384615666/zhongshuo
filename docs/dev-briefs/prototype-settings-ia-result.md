| 视口 | 正文宽 | 水平溢出 | 标签/控件重叠 |

| 1600 | 880 | 0 | 0 |
| 1440 | 880 | 0 | 0 |
| 1280 | 754 | 0 | 0 |
| 1100 | 574 | 0 | 0 |
| 900 | 596（单列） | 0 | 0 |

- 窄窗断点从 860 上调到 **980**：主内容区还要减去主侧栏约 250px，900 档若维持两列，正文只剩 374px，中文长句被挤成多行；改单列后正文 596px。
- 宽表例外：运行记录表、错误码速查表标 `.settings-wide`（`overflow-x: auto`），1100 档展开 20 条速查后仍 **0 溢出**。

### 2.2 设置行
- 引入共享 `.pset-row` 基元（§7 要求"扩这一个共享基元"）：标签在左、控件右对齐成一列、**同一张卡内多行用发丝线分隔**（一组设置一张卡）。
- 当前值改**独立值列**：`深色外观（当前：浅色）` 这类括号写法已消失（专项脚本断言正文不含 `（当前：`）。
- 长值（成员名单、路径）走 `.pset-value-wrap` 换行，不截断 —— 这条是被截图抓到后补的：初版 `Codex 实现者、Claude 审查者…` 在值列里被省略号截断。
- 控件列宽可变：数据目录、备份、清理、连接范围等行 `wide`；开关与短选项仍固定列宽。

### 2.3 归档管理
- `embedded` 模式下去掉自己的 `.page-head`：数据分区里**只有一个「归档管理」标题**（专项断言 `.settings-body` 内 `.page-title` 数量为 0）。
- 嵌入模式下搜索 / 项目筛选 / 清除筛选全部组件内状态：点「清除项目筛选」后 `location.hash` **不变**，卡片列表恢复全部；独立 `/archive?project=x` 保持 URL 语义与「返回全部归档」按钮（回归断言仍在）。
- 筛选行：搜索框 260px、项目下拉 180px 同高同量级，窄窗各占一整行。

### 2.4 可操作 vs 仅模拟
- **「日志保留」选①**：就地给出 7/14/30 天真实可选值并写入 `appSettings.logRetentionDays`，正文当前值同步；"可在此调整"这类无入口文案已删。
- 执行工具的「重新检测 / 连接测试 / 认证方式」保留按钮外观，**每个按钮旁一个「原型模拟」标记**（专项断言标记数 = 按钮数）。
- 通用三个系统开关保留卡片级「原型模拟」标记；只改内存模拟值的运行并发项同样标注。

### 2.5 开发材料降级
- C0—C4 验证等级表 + 「不要调用模型 API 自建执行循环」+ 版本/适配器/能力协商 → 折进执行工具的「技术详情」（默认关；展开后可达，专项两条断言分别验"正文看不到实测记录"与"展开后能看到"）。

## 3. 第二批：七类重排 + 通知 + MCP（§3.1—§3.4）

- **七类**：通用 / 外观 / 通知 / AI 工具 / 连接与设备 / 数据与存储 / 帮助与关于。归档管理不再独占一级分类；【暂缺】项（发送快捷键、消息密度、界面缩放）**没有**做成占位控件、空表单或"敬请期待"页。

- **通知**（§27.11 ATTN-05）：
  - 应用级偏好（全静音、免打扰时段、渠道、提示音、四类事件）存 `appSettings.notifications`；**房间静音与线程关注仍读 `s.subscriptions`**，界面就地列出并提供「取消静音 / 取消关注」——专项用"在房间卡片 ⋯ 里静音 → 应用设置列表立刻出现该线程"证明是同一份状态。
  - 覆盖关系（应用级全静音/免打扰 ＞ 房间静音 ＞ 线程关注）写在可见文案里；应用级静音生效时列表上方给出显式提示。
  - 「原型没有接入真实推送」与"通知 ≠ 执行授权"（ATTN-06）写在**可见文案**（初版只写进 tooltip，被专项脚本抓出后改成可见）；ATTN-05 完整清单（私信、已加入频道消息、关注线程回复、未加入频道提及）也改成可见说明，四类明确标注为优先子集。
- **外部 AI 连接（MCP，§31.5）**：
  - 完整走通创建 → 查看/改范围 → 轮换 → 吊销 → 删除记录；令牌创建时显示一次（可复制）、之后只留前缀。
  - 范围按四维配置（项目/房间 × 操作集 × 可调度成员 × 预算上限），操作集按**四类动作**分组（读 / 创建与补充要求 / 停止 / 代发消息），具体工具名在折叠里逐条列出；「首批不开放的命令」默认折起、展开后逐条可达，审批与验收标注**永远只属于用户**。
  - 连接列表含**最后活跃时间、累计调用数、当前范围**三项（§31.5 原文三项），并显示预算已用/上限。
  - 明确标注「原型没有 MCP 服务端：后台尚未接入」，未只补按钮冒充已完成。
  - 设备与 MCP **两个分组、两套数据、两份权限说明**，没有合并成一张"已连接客户端"列表。
- **设置搜索**（§3.4 可选加分项，已做）：索引 30+ 真实项，输入「登录/备份/通知」等可定位；命中后切分区 + 滚动 + 1.8s 高亮；搜不到时明确说"没找到"，不摆"即将支持"。

**验证系统对话框时踩到的两个坑（值得记下来）**：
1. **"没有对话框"无法用程序化探针证明**。原来的 `verify-desktop.ps1` 在找不到 electron 窗口时会兜底匹配**任意进程**的 `#32770`，于是"这一步不该有对话框"的反向断言被一个残留窗口误判成失败。新写的 `dialog-probe.ps1` 默认只认 electron 归属，并且**关闭后用重新枚举确认**（`IsWindow` 在本机的目录选择器上会给出"已消失"的假结论 —— 早期出现"打印已关闭、窗口还在屏幕上、每跑一次多一个对话框"）。
2. **该对话框不一定关得掉**。本机（Windows 11 + Electron 33）的目录选择器对 `WM_CLOSE` 无反应，只有 `SetForegroundWindow` + ESC 生效且**看焦点**。因此 `verify-open-folder.mjs` 全程**只调起一次**系统对话框（那一次就是用户要的行为证据），其余用 DOM 断言代替；脚本结束时会打印"对话框若仍在请按 Esc 或重启宿主"。

另外：`dialog-probe.ps1` 必须存为 **UTF-8 with BOM** —— PowerShell 5.1 没有 BOM 时按系统 ANSI（本机 GBK）读脚本，中文注释被读成乱码后整份脚本报"字符串缺少终止符"（实测踩到）。

## 5.6 用户第二轮反馈：菜单偏移 + 去掉页面头部（同日）

### 5.6.1 设置菜单"点外观时偏右几像素"

**原因**：滚动容器是 `.page`（内部滚动）。短内容的分区（「外观」只有一张卡）不出现滚动条，长内容的分区（通用 / 通知 / 帮助）出现滚动条——
`.page` 的可视宽度因此差一个滚动条宽度，而设置布局是 `margin-inline: auto` 居中的，于是整块内容左右各漂约 5px。
实测：外观档导航左缘 `312`，通用/通知/帮助档 `307`。

**修法**：`.page { scrollbar-gutter: stable }` —— 槽位常驻，有没有滚动条都不再改变宽度。
修后四档实测导航左缘**全部 307**（无漂移）。

### 5.6.2 去掉页面顶部头部

用户要求删掉页面顶部的「标题 + 一段说明」块（点名了「应用设置」与「搜索与收藏」两处，并说"等"）。执行口径：

| 处理 | 页面 |
|---|---|
| **整块删除**（只有标题 + 说明） | 应用设置、搜索与收藏、成员管理、任务看板、归档管理（含独立 `/archive`）、Runtime 兼容页 |
| **瘦身**：删标题与说明段，保留控件/坐标 | 待我处理（保留"范围"标签 + 筛选分段）、项目主页（保留概览标签 + 操作）、文件与 Git（保留路径 + 项目选择）、Git（保留路径 + 拉取/推送/新建分支）、文件与改动（保留路径 + 锁域/分支标签） |
| **不动**（实体页头，标题是实体名而不是页面标签） | 任务详情 / 研讨详情 / 运行详情（任务标题 + 状态 + 操作）、成员详情、成果详情、项目设置（§17.8 要求标题含项目名与路径）、项目缺失页 |

**信息没有丢**：归属边界由各分区副标题各说一次（应用级 vs 项目级）；待我处理的范围与筛选、文件页的路径、项目主页的概览标签都保留；归档语义由行内「恢复」动作与卡片标签承担。

**踩到的坑（值得记下来）**：把页头删成空壳时写出了 `{!embedded ? ( {/** 注释 */} ) : null}` ——
三元分支里只放注释会被编译成"渲染一个空对象"，React 抛 #31 并**让整棵树白屏**（不只是那一页）。
已删除该空壳并在代码里留了警示注释。教训：JSX 注释写成 `{/** */}` 本身没问题（esbuild 编译成无子节点），
但**不能让它成为三元/表达式容器里唯一的内容**。

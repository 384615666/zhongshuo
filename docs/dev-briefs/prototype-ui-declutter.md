## 2. 回复串：删除两行，只保留一条导航

删除当前 `thread-head` 中的顶部任务号/状态/操作行，以及常驻 `thread-anchor` 原消息摘要横条。不要重新添加同等高度的标题栏、编号条、状态条或原消息引用条作为替代。

新结构：

```text
[收起/返回]   回复   成果   详情                       ⋯
──────────────────────────────────────────────────────
当前视图内容
──────────────────────────────────────────────────────
跟进 #12 · 分析模块依赖…                 ← 输入区目标摘要
多行输入
输入区操作
```

- 常驻内容页签仅“回复、成果、详情”。更多菜单位于同一行最右侧。
- 普通讨论串使用“回复、附件、详情”；无附件时可隐藏“附件”，但有附件或附件深链时必须可达，不伪造任务成果。不要据 Artifact 需要 taskId 就判断讨论串无附件：当前列表还独立聚合消息附件。
- 导航组选中态唯一，保持当前浅渐变。键盘可达，无 hover 才能发现的唯一关键入口。
- 删除“另起任务”按钮，新任务统一从主池输入框创建；不改变创建新任务的业务语义。

### 2.1 收起/返回与任务身份

| 场景 | 左侧按钮行为 |
|---|---|
| L2 主池＋线程 | 收起回复串，主池保留 |
| 单区域线程 | 返回所属房间主池 |
| L4 线程＋文件 | 返回主池上下文，文件按现有共享预览的上下文/可见范围规则保留或暂藏 |

按钮名称、tooltip 与行为相符。以上操作不停止任务、不清草稿、不删除成果/文件标签。预览自己的“收起预览”是独立操作，不与关闭线程混淆。恢复布局遵守 §17.9：主动切过上下文则保留最新选择，不跳回旧任务。

不增加导航行内的任务号或状态 chip。L2 可通过主池选中卡识别任务；所有任务串输入区以非 placeholder 的目标摘要显示 `跟进 #N · 简短标题`，长标题省略但可完整查看，点击可进入详情。窄窗/L4 同样可辨认当前目标。只读/不可发送场景也保留目标信息，不因输入框隐藏而失去身份。普通讨论串显示讨论摘要，不伪造编号。子任务目标覆盖为明确的 `→ 子任务 #n`，取消定向恢复整串。

线程切换暂通过返回主池完成，不新增常驻线程切换器；同步旧规格标题菜单切线程的要求。保留项目/房间来源与正确返回路径。

### 2.2 详情内分组

| 分组 | 内容 |
|---|---|
| 任务概况/讨论信息 | 完整标题、任务号（若有）、完整原始要求/根消息、真实状态、方式、阶段及必要来源 |
| 参与成员 | 当前线程成员与跟进名单；复用既有增删/唤醒规则 |
| 活动与进展 | 事件记录、普通系统过程说明 |
| 运行详情 | 工具活动、用量、错误、诊断，按运行选择 |
| 交付与验收 | 完成摘要、版本、验证、残余问题和验收决定；复用原 DeliveryPanel |
| 研讨详情 | 仅适用任务：初稿、互评、争议、确认矩阵 |

默认展示概况，其余以紧凑分组导航或展开区访问，不把原来 8 个 tab 重新铺成一条拥挤常驻栏。完整原始要求在此可查；不删历史消息、原消息身份或定位能力。

交付有内容时提供分组；pending 验收、授权请求、阻塞或失败需要处理时，在回复视图提供明确处理卡/提示，可直达对应组。仍由原验收组件承担决定，不增加第二套验收状态，不跨任务批量验收。

### 2.3 更多菜单与停止

线程“⋯”包含关注/取消关注、静音/取消静音、复制链接等已有次级操作；存在未读时才提供“跳转首条未读”。菜单反映当前状态，操作复用原有逻辑。关注不等于参与/跟进成员，不能将二者合并成同一个状态。

当前停止按钮主要在任务详情中，本次要补“详情之外可发现”的入口：在允许停止的任务状态下，于输入区操作区域提供明确的“停止任务”动作，复用既有 stopTask 和状态判定；有活动任务但输入因权限/归档等不可用时，停止是否可用仍按真实任务权限判断，不由输入 disabled 推断。保留任务允许的跟进发送能力，不以停止按钮替代唯一发送入口。进入停止中后防重复点击并显示真实状态。

不要为此新增长期占空间的运行卡/顶部状态条；停止仅在适用时出现。详情中的停止动作复用同一执行路径。关闭/返回绝不触发停止。

## 3. 主池卡片与房间头部

- “任务详情”按钮已删，不恢复。去掉重复的常驻“打开回复串”；回复数量提供显式打开入口，任务标题亦可打开。
- 卡片默认保留标题、一个主要状态、简短进展/必要原文摘要、回复数、必要时间。标题优先完整识别，最多两行并提供全文途径；编号为次级文字。
- 关注状态不常驻，新建卡片“⋯”菜单承载关注/取消关注等适用操作，和线程菜单读同一订阅状态。禁止因点击菜单、附件或文本选择误触卡片导航。
- 同一卡片未读只留一种：优先保留可读的 `N 条未读`，移除额外未读圆点/专用强调；当前选中状态仍保留，它与未读不同。房间头部及侧栏的房间级汇总保留，不混成卡片冗余。
- 协调者与成员数合并成轻量房间信息入口；房间设置统一进入“房间信息 ⋯”，避免两个竞争入口。房间成员与线程参与者不混淆。
- 正常写入占用缩成一行；阻塞当前工作、并发冲突或需要处理时显示原因和动作，不能因精简隐瞒。

## 4. 系统说明与异常

正常的 AUTO 路由解释、程序校验成功、派发规则不长期占回复区域，移到详情对应组。任务概况显示本任务的派发摘要，不把房间路由规则冒充某任务运行事实。

校验失败、失败、阻塞、权限请求、待验收、需处理分歧继续可见。仅改正常信息的呈现，不删除事件记录。普通流程移除 task.steer、内部路由协议等实现术语；诊断仍可查。

## 5. 文件预览：去重复，保留来源与版本

- 文件名默认以标签显示一次；同名补最短父路径，完整路径进文件信息。
- 保留一个清楚的版本标识，区分固定交付/附件版本、工作区读取快照和 Git 比较双方。
- 来源为可点击短摘要；无 taskId 的附件按实际来源展示，不能造任务。
- Markdown 默认阅读。将“源码、自动换行”等放入 `阅读 ▾` 菜单；代码默认代码视图；格式不支持的操作隐藏或解释禁用。
- 这项覆盖旧视觉规范“预览/源码必须常驻分段控件”，同步文档和测试。菜单明确当前模式，切换保留既有滚动/定位能力。
- 对话并排时保留 `引用到 X`；选择文字可提供“引用选区”。引用锁定点击时目标与固定版本，加入草稿，用户发送后才进入上下文。
- 下载、导出、复制路径、文件信息等进文件“⋯”；能力缺失或无权限时不伪造可用动作。
- 文件列表入口按标签溢出/暂藏资源提示等需要显示；保留可访问的已开文件管理。不得泄露暂藏受限标签的名称。
- 放大收菜单；放大后明确显示还原/返回。收起预览常驻，保留标签和阅读位置。
- 当前标签关闭常显，其他标签可 hover/focus 显示，并有键盘/菜单访问途径。
- 文件更新、版本失效、无权限、加载失败按现有规则提示，不用同名文件替代，不执行原始 HTML/脚本。

## 6. 输入区与本次运行设置

保留真实多行输入、目标摘要、附件、@、上下文允许的任务/讨论切换、当前权限有效状态和发送。讨论不调用模型，不显示不适用的运行/权限配置；不把已存在的讨论串改造成任务。

低频选项进入从输入区“⋯”打开的“本次运行设置”菜单/弹层（当前若无则新增轻量组件，不建设新全局设置系统）。方式说明和预算推导公式在其中查看。非默认方式启用时以紧凑状态表达。

### 6.1 预算决议

- DELIBERATE 多成员研讨：保留发送前推导预算数值（如“最多 N 次”），人数/方式变化时更新；保留 §10.4 E12 的推导与约束。
- 普通默认任务：预算明细可在本次运行设置查看；非默认预算、超限/不足、调整请求或影响本次执行时显式提示。
- 不删除硬上限、调度预留或原有预算保护；纯讨论不显示模型预算。
- 使用当前预算计算逻辑，不自行复制公式造成两套值。既有设置仍沿用作用域。

### 6.2 状态与草稿

收纳只隐藏操作入口，不隐藏发送目标、当前执行方式及权限有效值；不可用档位保持禁用并说明原因，不静默改值。普通保存成功不常驻提示，失败必须显示。目标身份不要仅写 placeholder，输入文字后仍可见。

主池/线程/子目标的草稿和附件按现有规则隔离，中文 IME、重复发送保护、路由与 mention 保持原有行为。新增运行设置菜单必须键盘可达，打开不触发发送。

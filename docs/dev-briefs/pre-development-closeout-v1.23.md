## 2. 私信设计结论

采用“正常项目文件夹里的普通对话”：选项目和一位 Agent，直接发送；没有群聊模式、协调者、@ 路由和房间任务号。同一条对话沿用上文，另建对话有独立 conversationId/session。

所属项目提供工作目录、权限和预算；聊天历史与附件存应用数据区。后台复用执行任务/运行体系，保证停止、确认、预算与恢复；输入继续使用普通聊天体验。运行中发送按对话串行排队，停止暂停后续队列，归档不自动续跑；只记录不产生执行。附件、搜索、导出、未读和通知都采用同一 conversation audience。

正文与字段：[开工契约 §2](../development-baseline-v1.23.md)。主设计 §4.6/§12/§15 与 DEV-01 已同步。

## 3. MCP 补充结论

补充的不是 MCP 服务实现，而是第一包必须遵循的业务接口约定：

- 当前真实主体与代用户身份分开；本地 UI/任务 CLI/外部连接凭据各有边界。
- 可读范围、操作、可调度成员及预算分别校验；外部发起链转换到本地调用也不能丢失来源限制。
- 同 scope/key/hash 返回原回执，异参冲突；提交事务与回执原子，响应丢失可恢复。
- stop 绑定 run/停止代次，不影响后续新运行。
- 四项查询 room.list/member.list/task.get/events.list 的字段、分页、空结果、撤权与过期游标已定。
- 第一批 MCP 限房间/线程，不从任务、成果或事件查询旁路读取 DM；未来 DM 必须显式会话授权。

详见 [开工契约 §3](../development-baseline-v1.23.md)。MCP 本体仍为 FULL-11，不进 v0.1；已有 §31 的协议兼容方案不在本轮扩写或声称通过。

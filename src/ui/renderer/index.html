项目设置
任务验收（§10.5，项目级开关）：开启后，任务交付需要你确认；关闭后，满足交付要求即完成。不会自动提交或推送 Git。
成员 runtime 绑定（成员级设置）：为各 agent 成员选择 runtime 与模型（claude/codex 必须显式模型）；作用范围=该成员之后派发的任务（在途不变）；绑定持久化，重开生效。配置成功≠已认证——支持能力与认证状态分列显示，保存不触发探活、不读写凭据。
协作限制（§17.8：缺席等待与单轮运行时限，项目级）：NULL/清空=回落 daemon 全局默认；新派发任务起生效（在途任务保持派发时的时限）。数字单位=分钟。
文件修改（只读呈现）：当前有效策略=单写者（同一物理目录同时只安排一个受管理写入任务——只减少并发冲突，不宣称撤销一定可靠）；并行写入/工作树增强按 §14.7 延期未开放，不是可切换开关——保存任何设置都不会改变该边界，未认证权限档也不因配置开放实际写入。
写入并发：单写者（同一物理目录同时只安排一个受管理写入任务；并行写入增强已延期，§14.7——未开放，不是可点开关）。
帮助与故障引导（START-07/09 首版）
发送与路由：主池留空 @＝自动路由；@成员＝DIRECT 指派；「仅记录」＝一次性只保存不派发；线程内跟进不新建根任务。
研讨（@全体）：成员独立分析→互评→（争议则讨论）→整合→逐结论确认；缺席成员如实标注，不用一句总结覆盖分歧。
验收：策略为「人工验收」的任务完成后进入待验收；按钮绑定展示时的交付版本（防错稿）；「要求修改」的说明会注入返工输入；Git 提交不等同验收。
恢复与保护：崩溃/截止后的「状态未知」不自动重跑；对账前先「服务端取证」；人工声明保留写入保护；周期快照只证明「未观察到存活后代」，不构成完整退出证明——有子进程 runtime 的自动解除路径已关闭。
迟到成果：截止后到达的输出经服务端事件通道接收（幂等、不复活已停止任务、不覆盖新交付）；回执与业务效果同事务。
仓库与变更：主池顶部为仓库状态只读视图（暂存/未暂存/未跟踪区分，不改动你的工作区）；Git 操作区支持暂存/取消暂存/按任务批量暂存（自动跳过任务开始前的用户原有改动，混合文件列为冲突不自动分离）与提交（预览绑定 HEAD 与暂存区，变化即拒绝）；提交不等同任务验收，也不会自动提交或推送；任务串变更记录含撤销进度与冲突原因；撤销续跑走恢复中心。
未开放能力（如实）：AUTO 自动分工未过价值闸门暂不开放；真实 CLI 迟到回放待补证（显示 unsupported）；并行写档增强延期中；恢复解除对有子进程 runtime 暂时只保留保护。
恢复与保护帮助（START-07 首版）
·「状态未知」＝上次执行截止/崩溃时没等到终态回执，结果不确定——不自动重跑、不伪造成功/失败。
· 对账前请先「服务端取证」：由 daemon 按登记的进程身份做 OS 核对（父进程＋其派生进程树＋活跃期快照的孙进程归属核对）。
· 「人工声明未启动」会退款但保留写入保护：程序未确认执行结束前，保护不解除。
· 周期快照只能「未观察到存活后代」，不构成完整退出证明（快照间隔内派生且父链已断的执行载体不可排除）：有子进程 runtime 的服务端自动解除路径已关闭，保护保留并说明原因；仅无子进程模型（程序事实）可解除。
· 截止后到达的迟到成果经「服务端事件通道」接收（recovery.pumpLateEvents）：合同校验通过才交付；任务已停止/已有更新交付时不复活、不覆盖；回执与业务效果同事务、按事件源+turn 幂等。
· 运行能力只显示实测结论：未验证项如实标注「unverified/待补证」，不用成功回复推断整体能力。

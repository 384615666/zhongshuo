### 诊断（依据截图 screenshots-desktop/16-18、33-34 与源码）

- 必须遵守的既有约束：视觉规范 §4「应用导航之外最多并排两个内容区」（所以不做三栏）；§17.7「文件与 Git 合页」与页内项目选择器均保留；顶层页签按 §5.5 内容页签规格；主按钮按 §5.8。

## 多 agent 并发写入：文件级占用锁方案评估（讨论结论，未实施）

用户转来一份与 GPT 的讨论：用 MCP 三个接口（上传/查询/解除"某文件别改"的公告）做多 agent 文件级互斥。已对照 v1.21 设计文档给出评估。

### 结论（按优先级）
- **P0 静态分区**：模块归属写死在任务拆分里，零运行时协调，覆盖多数场景。
- **P1 worktree/快照 + 统一整合**：真正要并行时用（§14.4 已预留）。
- **P2 目录级锁 + 冲突记账 + 响亮降级**：即现有 §14.1 `parallel_writers`。
- **P3 文件级公告锁**：仅在"必须同目录 + 必须高并行 + 写入入口完全可控"时才做。

### 可复用的判断依据
1. **死锁不需要检测，靠构造消除**：整组原子申请（all-or-nothing）+ 禁止持锁等待扩展。满足则死锁数学上不可能，只剩活锁，用随机退避 + 等待时间加权解决。§10.3 已有"禁止父 turn 持锁等待子任务"= 第二条。
2. **锁只挡写不挡读**：agent 的读取经任意工具发生、无入口可拦截，共享目录意味着半成品对其他 agent 可见。这是文件锁方案的原理性缺口，worktree/快照天然没有。
3. **前提不可靠**：方案依赖"AI 提前准确列出涉及文件"，LLM 对此召回率低。众说 §14.2 选的是**事后记账**（前后快照比对 ChangeSet）而非事前声明——AI 说不准要改什么就别指望它声明。
4. **选型看失败模式**：静态分区→边界小冲突（可预测）；文件锁→内容交错静默损坏（不可恢复）；worktree→合并冲突（git 报错，三方对比可解）。原则：**能响亮失败的方案永远优于会静默失败的方案**。
5. **众说刻意不用租约自动过期**（§10.3"锁保留至确认相关工具停止或完成"），正是为了避开"旧 writer 还在写、新 writer 已接手"的静默损坏。GPT 推荐的 etcd lease 是众说明确避开的路径。
6. **不要另建 MCP 服务**：daemon 已负责目录身份/锁/快照/diff/worktree（设计文档 daemon 章节）。独立 MCP 会导致两套目录身份判定，违反 §3.3 / RT-09（junction、符号链接、父子项目重叠）。

### 若要落地的最小接口集
`acquire`（原子整组，返回单调递增 fencing token）/ `status` / `renew`（宿主自动，非大模型自调）/ `release`（校验持有者与代次）/ `wait-notify`（调度器通知，替代一分钟轮询唤醒大模型）。占用记录须含：canonical path identity、taskId+runId、token+generation、baseCommitSha、lease expiry、idempotency key。

## 针对众说的替代提案：规划期分区（意图契约 + 屏障整合）

读了 §3.1/§3.3/§5.2/§5.3/§6.2/§8.1 后提出。**核心：众说有协调者与结构化分工计划（§5.2 delegate JSON 含 dependsOn 依赖图），"整组原子申请"可以从运行时问题前移为规划时问题**——冲突在派发前就被拒绝，运行时根本不需要锁。

### 关键既有资产（可复用，不必新建）
- §5.2 分工计划契约：协调者**一次性**产出全部子任务（含 `access`、dependsOn），天然具备全局视图。
- §6.2 阶段屏障：已实现"首轮报告存工作目录之外 + 房间工具按阶段过滤读不到他人草稿"。这是**上下文级隔离**，比 worktree 的文件系统级隔离更彻底（拦得住 grep，因为 API 根本不返回）。目前只用于场景二分析，可推广到场景一并行修改。
- §3.2 Artifact/ChangeSet 版本化成果、§14.2 前后快照记账、§8.1 daemon 独占写入 + SQLite 事务、§3.3 目录锁域与 canonical path。

### 提案要点
1. **给 §5.2 子任务契约加 `writeScope`（glob 数组）与 `intent`（语义变更声明 + 影响面）**。范围由**协调者**划，不由执行 agent 申报——规划者在全局视图下划范围比执行者猜准得多，解决"AI 说不准要改什么"。
2. **派发前程序化校验**（零模型成本、失败响亮）：glob 两两求交判重叠 → 拒绝派发；越出授权目录 → 拒绝；依赖成环 → 拒绝（§5.2 已有）。路径比对复用 §3.3 canonical path，不另写一套。
3. **执行期无锁**：基线快照（§14.2 已有）+ 结束出 ChangeSet。越界写入靠事后检测标 `out_of_scope`，走 attribution=ambiguous + 三方查看，符合 §14.2/§14.5 口径。
4. **整合期**：收集各子任务 `intent`，算出语义依赖边（A 改 login() 返回结构 / B 读 login()），拓扑排序定整合顺序；验证只认整合后版本（§14.3、§5.4 已有"模型说测试通过不算"）。

### 落地阶段
- A：加契约字段 + 派发前 glob 重叠校验器（不动 workspace，仍按 §5.3 串行改）。改动最小、价值最大。
- B：**writeScope 不重叠的 modify 子任务允许并行**——直接替代用户整套 MCP 锁方案，把 §5.3"同一原目录修改串行"的并行度从 1 提到 N 且零运行时协调。
- C：按 writeScope 决定 workspace 形态（小且无重叠 → 原目录；重叠或跨模块 → 快照/worktree §14.4）。
- D：整合期意图依赖边 + 拓扑排序 + 整体验证。

### 风险与边界
- 协调者 writeScope 可能划错（太小做不完 / 太大损并行度）→ 越界检测兜底 + 扩范围须走协调者，不能自己拿锁。

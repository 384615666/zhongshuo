01怎么工作

像交代同事一样，
把事说清楚。

不用学编排语法，也不用在几个窗口之间来回复制。分工和研讨，都是一句话发起。

  1. 01

    打开文件夹

    选一个本机目录，它就是项目。AI 读写的是真实文件，Git 状态和改动也按磁盘上的内容显示。

  2. 02

    添加 AI 成员

    使用本机已登录的 Claude、Codex 或兼容渠道。每个成员可以单独设置模型与权限。

  3. 03

    在房间里交代

    用一句话说明目标：要分工就写清谁先做、谁核对；要讨论就点名几位 AI，开启独立研讨。

02协作方式

不止一种一起。
按你要做的事选。

不用先记模式：你 @ 谁、怎么问，决定 AI 怎么配合。

A · 让它做事

要交付文件、改代码、整理资料

  • 自动协作

    不 @

    交给协调者，按需拆解、分工、交接和整合；授予写权限后可改文件。

  • 指定成员

    @ 一位

    由指定 AI 直接处理；适合任务明确，或你清楚该找谁。

  • 多人分工

    @ 多位

    把指定成员放进同一件事，由协调者统筹分工与交接。

想先看方案：选「计划模式」，本次只出方案或分析，不改文件；需要落文件时在权限里允许编辑。

B · 让它一起想

没思路、要评审、要挑漏洞

  • 共同研讨

    开启「独立研讨」

    选两位以上成员或 @全体：每位先独立出稿，再交叉互评、整理相同点与分歧；只读，不直接改文件。

  • 简短交流

    共同研讨里问一句

    简单问题不必展开完整互评：成员分别回复后直接结束，适合先听一圈意见。

默认先独立出稿，也可以跳过独立首稿直接讨论；结果只读，需要执行时回到自动协作或指定成员。

C · 单独与记录

先想清楚，或只留一条记录

  • 私信

    单聊一位 AI

    一对一、独立上下文；适合先把思路聊清楚，再回房间安排。

  • 文件评论

    不触发 AI

    在文件上留评论、锚定当前版本；只保存记录，不发起模型派发。

私信内容不会带进房间；每次新建私信都是独立话题。

D · 继续这件事

已经有任务或结论，往下推进

  • 原串继续

    引用 / 补充

    在同一回复串里追问、补充要求；不用重新讲背景。

  • 停止、验收与返工

    任务详情 / 成果

    停止或继续任务，按版本验收，或让 AI 按意见返工。

历史版本、原始要求和旧交付都保留，返工不会覆盖旧记录。

一句话记住： 不 @ 自动协作 · @ 一位 指定成员 · 开「独立研讨」 让多位 AI 一起想

03跨 harness 协作

不是子代理，
是各跑各的 harness。

子代理通常继承父 agent 的模型、工具和上下文；众说让 Claude、Codex 等成员各自运行在原生环境里，在同一个项目里交接、评审和验收。

01

强项不被拉平

Claude 的视觉与交互判断，在 Claude Code 里最完整；GPT 的工程与后端能力，在 Codex 里最顺手。硬塞进别人的 harness，工具链和上下文往往都要打折。

02

工具各自原生

每个成员继续使用自己 harness 的 MCP 服务、记忆和 skill，不需要为了统一编排，把它们压平成一套通用接口。

03

协作在项目层

不是把一个模型的请求转发给另一个模型执行，而是每个成员在自己的环境里接自己那一棒。房间、任务、回复串和验收把结果串起来。

工作原理

共享项目，分开执行，显式交接。

众说只统一任务、权限、状态和结果的记录方式；模型怎么想、用什么工具，由各自的 harness 决定。

跨 harness 不是零成本：任务边界、上下文和文件改动都要显式交接。房间、任务、回复串和验收把这些放在明面上；子代理适合同一个环境里的同构拆解，跨 harness 适合前端 / 后端这类异构分工。

04示例

同一套协作，
放到真实工作里。

三个来自真实界面的例子：头脑风暴、方案评审，以及多名专家代码审计。

示例 01 · 头脑风暴

还没想清楚？
先让几位 AI 各出几招。

把模糊的问题交给几位 AI，分别从用户价值、增长和实现成本提方向；再归类、对比，收敛成一份优先尝试的短名单。全程只读。

  • 用户价值
  • 增长
  • 实现成本

示例 02 · 方案评审

一份方案，先让几位 AI 各挑毛病。

Claude、Codex 和评审专家分别从产品、架构与风险角度独立评审，再互评、整理相同点与分歧；全程只读，结论还在你确认之后。

  • 产品视角
  • 架构视角
  • 风险视角

示例 03 · 多名专家代码审计

同一份代码，
几位专家分头找问题。

安全、并发与测试覆盖各自审计，逐条指出文件位置、影响与修复优先级；全程只读，交叉复核后把报告留在同一条串里。

  • 安全
  • 并发
  • 测试覆盖

05能做什么

不是一个聊天框，
是一间能交付的工作室。

从提出要求到拿到文件，中间的过程都在同一个工作区里。

文件夹即项目

项目直接对应本机目录；AI 在授权范围内处理真实文件，文件页与 Git 改动都来自磁盘本身。

一句话决定怎么配合

不 @ 自动分工，@ 一位指定成员；开启独立研讨，多位成员一起出意见、互相评审。

一条回复串推进

进展、问题、成果与返工都留在同一条串里；引用某条回复继续追问，上下文不会断。

私信单独讨论

和某一位 AI 单独聊，先把思路理清楚，再回到房间安排工作；每次新建私信都是独立话题。

任务与成果

每个任务都有状态和交付物：停止、继续、验收、预览、下载或另存为，都能在应用里完成。

数据留在本机

聊天、附件和任务记录保存在本机数据库；可随时备份、恢复，或迁移到新电脑。

06界面

该看的东西，
都在同一屏。

没有隐藏的工单系统，也没有另一套结果仓库。

回复串

在原串里补充要求，不丢上下文。

打开一条回复串，能看到你的要求、AI 的回答、任务状态与文件成果。引用其中一条，追问或要求修改时，背景都还在。

  • 引用回复
  • 任务状态
  • 成果文件

文件与成果

成果直接打开看，不用先下载。

文本、代码、图片、PDF、Word、Excel、PPT 都能在应用内预览，Markdown 也可以直接阅读；确认后另存为，或回到房间里继续修改。

  • 七类预览
  • 原文件另存为
  • 按任务追溯

本地优先

工作文件在你的磁盘上，
对话记录在你的电脑里。

众说是一个本地程序，不是又一个云端工作区。你的项目仍然是一个普通文件夹，可以继续用编辑器、终端和 Git 操作它。

数据放在哪里，怎么备份
  • 本地SQLite 数据库

07细节

为日常使用
准备的细节。

不追求功能列表的长度，尽量让每一步都做得可恢复、可核对。

  • 七类附件与成果预览：文本、代码、图片、PDF、Word、Excel（含 CSV）与 PPT；Markdown 也可直接阅读。
  • Git：查看改动、提交记录和分支；不是 Git 仓库会如实说明，不会自动初始化。
  • 搜索、收藏与 Ctrl+K：找回消息、任务或文件；Ctrl+K 直接跳到成员、任务或页面。
  • 任务看板与「待我处理」：按状态查看任务，集中处理需要你回答或验收的事。
  • 成员管理：每个 AI 可单独配置模型与权限，也可以设置头像。
  • 计划模式：本次只出方案或分析，不自动改文件；确认后再继续执行。
  • 备份与恢复：整份备份本机数据，或从备份恢复、使用已有数据；换电脑时手动迁移。
  • 14 章、19 张编号截图的中文操作手册，应用内可读，仓库内也有离线 HTML。
